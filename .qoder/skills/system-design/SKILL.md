# System Design Skill (v4 — 概要设计版)

## 核心原则

本 Skill 专注于**概要设计**，不定义具体类和接口的参数，仅关注：

1. **实体和实体关系**（ER 模型）
2. **模块划分**（边界和职责）
3. **架构分层**（层次结构）
4. **关键业务流程**（概要流程）
5. **数据流向**（模块间数据流）

### 设计原则

| 原则 | 说明 |
|------|------|
| **分层清晰** | 展示系统的层次结构，不涉及具体实现 |
| **模块独立** | 明确模块边界和职责，不暴露内部细节 |
| **关系明确** | 清晰表达实体间关系，不定义字段细节 |
| **流程概要** | 描述关键业务流程，不定义详细时序 |
| **流向清晰** | 描述数据在模块间的流向，不定义数据格式 |
| **受控抽象** | 每层只展示该关注的架构信息 |

**关注者**：开发人员、架构师

**目的**：展示关键业务流程和数据流向的概要描述

#### 5.1 关键业务流程

```markdown
## C5: 关键业务流程

### 业务流程列表

| 流程 ID | 流程名称 | 涉及模块 | 说明 |
|---------|---------|---------|------|
| BP-001 | 用户注册流程 | 用户模块 | 新用户注册并认证 |
| BP-002 | 下单支付流程 | 订单模块、商品模块、支付模块 | 用户下单并完成支付 |
| BP-003 | 订单履约流程 | 订单模块 | 订单状态流转和履约 |

### 业务流程 1: 下单支付流程 (概要)

**流程描述**：
1. 用户选择商品 → 提交订单
2. 订单模块校验库存 → 创建订单
3. 用户发起支付 → 支付模块处理
4. 支付成功 → 更新订单状态

**流程图**：

```

              ┌─────▼─────┐
              │  创建订单  │
              └───────────┘
                    │
              ┌─────▼─────┐
              │  支付模块  │
              │  (跳转)    │

                    │
              ┌─────▼─────┐

                    │
              ┌─────▼─────┐
              │  订单完成  │

**说明**：仅描述流程步骤和模块间交互，不定义接口参数和返回值。

## C4 一致性规则

1. **上下对齐**：C1 的人物/外部系统必须与 C2 的接入层对应
2. **层次归属**：C2 的层次必须完整，分层依赖合理
3. **模块归属**：C3 的模块必须属于 C2 的某个层次
4. **实体归属**：C4 的实体必须支持 C3 的模块业务
5. **流程归属**：C5 的流程必须涉及 C3 的模块，模块间数据流必须符合模块依赖

## 常见陷阱

1. **过度设计**：在架构层面定义具体字段、方法参数、接口签名
2. **流程过细**：在概要设计中绘制详细的时序图或流程图
3. **层次混乱**：分层职责不清晰，依赖关系混乱
4. **模块耦合**：模块边界不清晰，循环依赖
5. **流程缺失**：关键业务流程不完整或数据流与模块依赖矛盾

## 边界约束

| 设计内容 | 定义 | 不定义 |
|----------|------|--------|
| 架构分层 | 层次名称、职责、依赖 | 具体类、方法、参数 |
| 模块划分 | 模块边界、接口、依赖 | 实现类、方法签名 |
| 实体关系 | 实体名称、关系类型、基数 | 具体字段、索引、约束 |
| 业务流程 | 流程步骤、涉及模块、交互顺序 | 接口参数、返回值、异常处理 |
| 数据流向 | 源模块、目标模块、数据内容、流向类型 | 数据格式、编码方式 |
