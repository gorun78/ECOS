# 前端开发规范

> 版本: 1.1 | 2026-09-28
> 适用: ecos_frontend React 19 + Vite 6 + TypeScript + Tailwind 4 + Express BFF
> 上游依据: .trae/rules/架构铁律.md §4（前端铁律 4.1~4.8） + .trae/rules/后端开发规范.md §十（配置/字典分组契约）、§十一（版本与 Git 归档契约）
> v1.1 变更: 新增第六~十节（国际化 / 主题与显示模板 / 移动端兼容 / 配置与字典消费 / 组件路由与 API 收口）、第十一节（版本与归档界面）；删除第四节 Vue3 过时条款；自检清单同步

## 一、 核心红线（最高优先级）
低冗余与一致性：拒绝无效变量、空逻辑与过度注释；严格跟随项目现有代码风格、目录与技术栈，禁止私自魔改公共配置与全局样式。
安全与健壮：强制参数校验、异常捕获（try/catch）与边界处理；禁止裸写接口与无判断逻辑。
精准与可维护：拒绝模糊的万能代码与无效兜底；代码逻辑分层清晰、功能单一，方便二次迭代。
扩展性： 拒绝类似逻辑的代码块，尽量抽象公共方法；禁止实现重复的组件。
所有方法、变量需要有必要的注释。
样式风格需要统一。
尽量使用公共样式。

二、 基础语法与命名
格式：统一 2 空格缩进，语句必加分号，代码块必加 {}；全程 ES6+，禁用 var 及废弃 API。
命名：语义化英文命名，禁拼音/简写。变量/函数小驼峰，常量全大写+下划线，组件/类大驼峰，CSS/文件夹短横线，Hooks 以 use 开头。

三、 HTML & CSS/SCSS
HTML：语义化标签，按钮用 <button>，图片必带 alt；禁冗余空标签、行内样式（动态除外）及交叉嵌套。
CSS：单行单属性，SCSS 嵌套最大 3 层；优先复用全局变量，禁硬编码色值/尺寸及滥用 !important；优先 Flex/Grid 布局，禁老旧浮动。

四、 JS/TS & 框架规范
JS/TS：常量 const，变量 let，禁全局污染；函数单一职责，复杂逻辑拆分；TS 禁滥用 any，复用已有类型，做好空值处理；多层判断用卫语句/短路运算。
React：仅函数组件 + Hooks；Hooks 顶层调用；Props 必 TS 约束；合理使用 useMemo/useCallback。（本项目为纯 React 技术栈，不引入 Vue/Pinia/Vuex 相关写法）

五、 结构、接口与性能
目录：严守 src 标准目录（views/components/api/utils 等），公共逻辑必须抽离，禁页面堆砌通用代码。
接口：禁硬编码地址/密钥；统一使用项目封装的 request；列表/分页逻辑统一封装；敏感数据禁明文存储。
性能：组件销毁时清除定时器/监听器；高频事件加防抖/节流；路由/组件懒加载；图片懒加载。

六、 国际化 i18n（🔴绝对禁止硬编码中文，对齐架构铁律 §4.3）
1. 文案一律 `useLanguage()` → `t("namespace.key")`；禁止 JSX/常量/数组里出现中文字符串字面量（含 placeholder、title、aria-label、toast 文案、表格列名、图表 legend）。
   ```tsx
   import { useLanguage } from "../components/LanguageContext";
   const { t, locale } = useLanguage();
   // ✅ <span>{t("databench.datasource.add")}</span>   ❌ <span>添加数据源</span>
   ```
2. 语言实现落 `src/components/LanguageContext.tsx`；语料按域分目录 `src/locales/{domain}/{zh-CN.json, en.json}`（现有域：common / dw / ontology / knowledge / cognition / aiworkbench / copilot / dashboard / scenario / sec）。
3. 新增 namespace 三步：① 同域 `zh-CN.json` 与 `en.json` **成对**加 key（禁止只加单语）；② `LanguageContext.tsx` 注册 namespace；③ 端到端切换中英文验证该 Tab 无残留字面量。key 命名 `{domain}.{module}.{name}`，全小写点分。
4. 中英切换不得引发重排错误：长英文串必须可换行/可截断（`truncate` + `title`，或弹性布局），禁止固定宽度容器写死中文长度。
5. 枚举/标签类文案优先走数据字典（见第九节 `dictLabel` / `dictLabelEn`），不在 locales 里重复维护一份业务枚举翻译。

七、 主题与显示模板（4 主题，对齐架构铁律 §4.1 / §4.4 / §4.5）
1. 样式来源：`useTheme()`（`src/components/ThemeContext.tsx`）返回语义 token，组件只用 token 类名；结构性组件禁止硬编码 Tailwind 颜色（`bg-white` / `bg-slate-900` / `text-gray-500` 等一律视为违规）。
   ```tsx
   const { styles } = useTheme();
   // ✅ <div className={`border ${styles.cardBorder} ${styles.cardBg}`}>   ❌ <div className="border bg-white">
   ```
2. 4 主题基线：`slate-light` / `deep-space` / `cyber-terminal` / `royal-purple`。新增组件必须在 4 主题下逐一肉眼验证可读性，单一主题通过不算过。
3. 语义色（Success/Warning/Danger/Info）同样主题感知：light 用 `bg-xx-50`，dark 用 `bg-xx-500/10`；禁止直接用 `bg-green-500` 表达状态而不区分明暗。
4. 排版表（铁律 §4.4）：页面大标题 `font-bold text-xl tracking-tight`；卡片/组标题 `font-semibold text-sm`；正文 `text-xs leading-normal`；注释/时间戳 `font-mono text-[10px] tracking-wider uppercase`。
5. 布局范式（铁律 §4.5）：外层 `flex-grow overflow-y-auto p-6 font-sans` → 内层 `max-w-7xl mx-auto space-y-6` → 标题区 / KPI 网格 / 详情区；间距：主区间 `space-y-6`、卡片内 `space-y-4`、网格 `gap-4`。
6. 禁止为某主题单独写一套组件或加 `if (theme === ...)` 分支渲染；主题差异只允许体现在 token 层。

八、 移动端兼容（🔴新页面默认要求响应式）
1. 断点体系两套且边界对齐：CSS 侧用 Tailwind 默认前缀（sm 640 / md 768 / lg 1024 / xl 1280），JS 侧判定移动端统一 `(max-width: 767px)`，即 md 下界。禁止自造第三套断点数值。
2. 视口判定只允许复用 `src/hooks/useMediaQuery.ts`（SSR 安全 + unmount 自动解绑监听）；禁止在组件内裸写 `window.innerWidth` / `matchMedia` 判断布局（`window.innerWidth` 仅允许用于浮层位置钳制）。
3. 移动抽屉只允许复用 `src/hooks/useMobileSidebar.ts`（返回 `isMobile` / `sidebarOpen` / `toggleSidebar` / `closeSidebar`，移动→桌面自动关闭）；不得各页面重复实现 drawer 状态。
4. 表格移动端方案：宽表用 `src/components/common/MobileDataTable.tsx`（内部已按 `(max-width: 767px)` 切换卡片式呈现，可传 `mobileQuery` 覆写）；禁止在移动视口下横向滚动整页。
5. 交互约束：触摸目标 ≥ 44×44px；hover-only 功能（悬浮工具条、hover 展开）必须在移动端提供等价的点击/长按入口；右键上下文菜单（`CatalogContextMenu` / `CanvasContextMenu`）在移动端必须有替代入口；图形编辑器（pipeline-editor / ontology canvas）在 `isMobile` 下须降级为只读或简化面板，不得出现不可用的隐藏手势。
6. 禁用桌面-only 依赖：拖拽（HTML5 drag / 画布连线）在移动端必须声明降级策略并写入 PRD 验收；不允许"移动端暂时不支持"作为默认交付结论。
7. 视口变化时清理与重算：ResizeObserver / 定时器 / 监听器随组件销毁清除（承接第五节性能条款）。

九、 系统配置与数据字典消费（对齐后端开发规范 §十）
1. 作用域模型与后端同构：配置 = `config_group`（`general` 平台全局 / `{engine}` 工作台独立）；字典 = `subsystem`（与所属工作台 `config_group` 同名）。前端不得另立一套分组名。
2. 设置页组织：每个工作台/引擎的设置与独立字典**并列放在同一 Settings 区域**，按分组各占独立 Tab（每 Tab 独立文件，见第十节）；全局配置只在系统管理域展示，不得复制到各工作台页面。
3. 配置读写：统一调 `/api/v1/system/config`（全局）与 `/api/v1/engine/{module}/settings`（引擎分组）；禁止前端硬编码配置默认值来"兜底"——默认值事实源是后端 `default_value`，reset 类操作必须调 reset 端点（`PUT /api/v1/sysconfig/{key}/reset`）后回读。
4. 字典消费：只允许 `useDict(dictType, locale)` / `fetchDictItems(dictType)`（`src/hooks/useDict.ts`，已实现全局缓存 + 并发请求去重）；禁止各页面自行 `fetch('/api/v1/system/dict/...')`，禁止在 locales 里重复维护业务枚举翻译。
5. 字典标签按 locale 取 `dictLabel`（zh）/ `dictLabelEn`（en）；空字典必须有可见的空态/错误态（复用 `EmptyState` / `Toast`），禁止静默渲染空下拉。
6. 配置生效性以 `is_consumed` 语义为准：后端标记未消费的配置项不得在前端展示为"已生效"。

十、 组件、路由与 API 收口（对齐架构铁律 §4.2 / §4.6 / §4.7 / ADR-10）
1. 图标：仅 `lucide-react`，禁止自定义 SVG / 图片图标；尺寸约定 表格按钮 `w-3.5 h-3.5`、卡片 `w-4 h-4`、Hero `w-5 h-5`；Icon map 用 `Record<string, ComponentType>`，不用 switch-case。
2. 体量：单文件 ≤800 行；超限拆子组件。每个 Tab 独立文件，主 Layout 仅做组合 + 状态管理，目标 <300 行。
3. 路由：HashRouter（`#/` 路由）；懒加载按路由/组件切分。
4. API：函数统一收敛 `src/api.ts` 或模块内 `services/*Api.ts`，禁止组件内裸写 fetch；SSE 流式用 `EventSource` / fetch readable stream。
5. 代理双轨（务必遵守）：生产/preview 走 Express BFF（`server.ts`）且默认**全部** `/api/*` → `GATEWAY_URL`(:8080)；vite dev 的 18 条引擎前缀直连（18081~18090）仅对 dev 生效。前端代码不得写死后端端口或假设"所有请求都过 gateway"，也不得依赖直连前缀在生产可用（`ECOS_LOCAL_DIRECT_SERVICE_PROXY` 默认 false）。
6. 前后端契约（铁律 §4.8）：列表 API 只回摘要时，详情/编辑器必须调详情接口取全量；节点类型等枚举与后端同源，禁止前端自造枚举别名；写操作成功后必须重拉列表；DELETE 是逻辑删除（status→ARCHIVED，详情仍可查），断言与展示按此语义。

十一、 版本与归档界面（统一组件 + 单一通道，对齐后端开发规范 §十一）
1. 单一通道：git / 版本相关请求只允许走 `src/services/gitService.ts`；禁止页面或面板内自行 `apiFetchData('/api/v1/ecos/git/...')` 拼路径调用。
2. 强类型契约：`gitService.ts` 禁止 `<T = any>` 与 `data?: any`；必须定义 `RepositoryId` / `CommitVO` / `BranchVO` / `TagVO` / `DiffVO` / `AssetVersionVO`，字段名与后端 VO 同源。
3. 寻址与凭据：前端只传语义化 `repositoryId`（如 `dw-pipeline` / `ontology-model` / `kb-asset-tree` / `cognitive-model` / `agent-collab` / `scenario-def`），**禁止传 `localPath` 或任何服务器路径**；请求类型中不得出现 `username` / `password` / `token` 字段（凭据由服务端注入）。
4. 公共组件收敛：版本时间线、提交历史、差异对比、发布/提交对话框、分支切换为公共组件（收敛至 `src/components/common/version/`）；各工作台仅传资产特定的列名、文案与 `repositoryId` 配置，禁止复制粘贴 panel 实现（现 7 处各自实现须逐步合并）。
5. 未接入资产的展示：后端返回 `not_available` 时必须渲染明确空态（复用 `EmptyState`）+ i18n 说明文案；禁止展示假成功 toast、假 commitId 或空时间线冒充"无历史"。
6. 发布/回滚反馈：长耗时归档按后端 `runtime-task` 返回的 `taskId` 反查进度（复用任务中心轮询/SSE），结果走 `Toast`；操作完成后重拉版本列表（承接铁律 §4.8 写后刷新）。
7. 主题与移动端：版本面板一律走 `useTheme()` token；版本时间线在移动端（`(max-width: 767px)`）降级为折叠列表 + 抽屉，差异对比在移动端降级为逐行文本对比，禁止桌面端双栏布局直接缩到移动端。

十二、 注释与输出自检
注释：仅注复杂逻辑、公共函数（JSDoc）与核心文件；禁无意义注释与调试残留。
输出：代码可直接运行，无报错/警告/console/debugger；结构清晰，区分新增/修改代码；复杂功能附简短说明。
自检：输出前必须校验格式、命名、冗余、TS 类型、样式层级、异常捕获、内存泄漏及目录规范，违规项立即自动整改。
主题与文案：无硬编码中文（`t()` 全覆盖，zh-CN/en 成对）；无硬编码 Tailwind 颜色（结构性组件全走 `useTheme()` token）；4 主题逐一验证通过（第六、七节）。
移动端：视口判定走 `useMediaQuery` / `useMobileSidebar`，无裸 `window.innerWidth` 布局分支；宽表走 `MobileDataTable`；hover-only 与右键菜单在移动端有等价入口；触摸目标 ≥44px（第八节）。
配置与字典：配置读写限定自身 `config_group`，默认值不前端硬编码；字典只走 `useDict`，标签按 locale 取 `dictLabel` / `dictLabelEn`（第九节）。
收口：图标仅 lucide-react；单文件 ≤800 行、每 Tab 独立文件；API 收敛 `api.ts` / `services/*Api.ts`；不依赖 vite dev 直连前缀（第十节）。
版本归档：git 请求只走 `services/gitService.ts` 且无 `any`；只传 `repositoryId` 不传 `localPath`、无凭据字段；未接入资产显示空态而非假成功；版本 UI 复用公共组件（第十一节）。
