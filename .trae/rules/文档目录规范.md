## 一、核心原则

| 规范项 | 核心要求 |
|:--|:--|
| **生命周期分类** | 一级目录按软件生命周期五类划分：架构 → 需求 → 设计 → 实现 → 测试；文档按**主要意图**归入唯一一类 |
| **单一分类** | 一份文档只归一个目录；跨类文档按"读者第一动作"归类（如 PRD 虽提及架构，主意图是需求 → `20-需求/`） |
| **可追溯** | 每份文档头部有 `> 来源 / 日期 / 责任人` 三行（`文档编写规范.md` R1）；新旧路径对照在 `迁移映射-2026-09-28.md` |
| **批准方可删** | 现行有效文档只加不删（R9）；过期归档/目录壳经用户或 PMO 批准 + 映射表留痕后可物理删除（v3.1 起，git 历史兜底） |
| **目录扁平** | 新写入文档相对 `docs/` 深度 ≤ 2 层（`五类/文件.md` 或 `五类/子目录/文件.md`，R6 上限 3 层不变） |
| **模块入名字** | 模块信息不再靠目录承载，改写进文件名（如 `PRD-02-data-engine需求规格-2026-09-28.md`） |

## 四、文件类型白名单（R4）

`docs/` 下只允许：
- `.md`（主文档语言）
- `.json`（审查证据：审批记录 / 调度计划 / 验收 verdict，归 `50-测试/reviews/`）
- `.mjs`（联调冒烟脚本，归 `50-测试/`）
- `.html`（参考资料中的可交互架构图，归 `40-实现/refs/`）
- `.txt`（审计原始数据，例外仅旧存留）
- `.sh`（审查证据中的构建脚本，归 `50-测试/reviews/`）

**禁止**：`.png`/`.jpg`/`.gif`（R5 不合规，图片走外部 CDN）、`.pdf`（不入库）、`.exe`/`.zip`/二进制文件

## 五、目录变更流程（R11~R13）

| 触发事件 | 动作 |
|:--|:--|
| 新模块出现（新 service / engine） | **不再开一级目录**；模块名进文件名，落对应生命周期类目录 |
| 目录改名/废弃 | 物理移动 + 映射表登记；旧目录壳在映射表留痕且用户/PMO 批准后可直接删除（v3.1），不再要求保留指针壳 |
| 批量迁移 | 必须同步产出/追加**迁移映射表**（旧路径 ↔ 新路径全量对照），并更新 `docs/README.md`、`.trae/rules/` 引用与根 `agents.md`（R13） |
| 零散迁移 | **禁止**——必须批量执行 + 映射表留痕（R13） |
| 过期归档清理 | 逐份校验 git HEAD 内容留底（hash 匹配）→ 用户/PMO 批准 → 批量删除 + 映射表加注删除记录；无留底的一律保留（v3.1 实践基准） |
