## 一、核心原则

| 规范项 | 核心要求 |
|:--|:--|
| **目录镜像代码** | 一级目录与 `ecos_backend/services/` + `engine/` + `runtime/` + `workspace/` + `gateway/` 1:1 对应 |

## 四、文件类型白名单（R4）

`docs/` 下只允许：
- `.md`（主文档语言）
- `.json`（审查证据：审批记录 / 调度计划 / 验收 verdict）
- `.mjs`（联调冒烟脚本，归 `22-integration/`）
- `.html`（参考资料中的可交互架构图，归 `30-cross-cutting-docs/refs/`）
- `.txt`（审计原始数据，例外仅 2 个旧存留）
- `.sh`（审查证据中的构建脚本，归 `30-cross-cutting-docs/reviews/`）

**禁止**：`.png`/`.jpg`/`.gif`（R5 不合规，图片走外部 CDN）、`.pdf`（不入库）、`.exe`/`.zip`/二进制文件

## 五、文档归类决策树（按重要意图唯一目录）

```
新文档要放哪？
├─ 架构宪法 / ADR？ → 00-架构/adr/
├─ 网关层（gateway/）？ → 10-gateway/
├─ service 层（5 个 service）？ → 20-services/{sysman|datanet|buszhi|dccheng|aiming}/
├─ 横切底座（runtime/*）？ → 21-runtime/
├─ 跨模块联调 / Wave 收口？ → 22-integration/
├─ 交付质量 / 产品化？ → 23-quality/
├─ 引擎层（6 engine，护/土/金/水/木/火）？ → engine-{security|data|ontology|kb|cognitive|ai}/
├─ workspace 场景应用？ → workspace/
├─ 审查 / 验证证据（含 JSON / curl）？ → 30-cross-cutting-docs/reviews/<对象>/<task_id>/
├─ 跨模块 / 验收 / 验收门禁 PMO？ → 30-cross-cutting-docs/pmo/
├─ 行业 / 竞品 / 参考？ → 30-cross-cutting-docs/refs/
├─ 部署 / 回滚 / 清理清单 / 运行手册？ → 30-cross-cutting-docs/ops/
└─ 已完成不再引用？ → 30-cross-cutting-docs/99-archive/
```

## 六、目录变更流程（R11~R13）

| 触发事件 | 动作 |
|:--|:--|
| 新模块出现（新 service / engine） | 任务表必须含「建一级目录 + README」（R12） |
| 目录改名/废弃 | `git mv` 物理移动，旧名落 `*-legacy/` 子路径（R9） |
| 零散迁移 | **禁止**——必须走 `_win_tasks/docs-migration.ps1` 批量（R13） |
| 跨目录变更 | 必须更新 `文档编写规范.md` §0.1 一级目录表 + 跨引用 |
| 历史遗留 `*-legacy/` | 不删除（git 留痕），每季度盘点一次可归档到 `30-cross-cutting-docs/99-archive/` |
