## 一、红线 R1~R13（违反 = Reviewer 判 FAIL）

| # | 红线 | 处置 |
|:--:|:--|:--|
| **R1** | 头部必带 `> 来源 / 日期 / 责任人` 3 行元信息 | 缺 → Reviewer 打回 |
| **R2** | 显式标注版本（v0.x 草稿 / v1.0 正式 / v2.0 修订） | 缺 → 不可进入评审 |
| **R3** | 文件名小写+短横线+日期 `YYYY-MM-DD`，数字前缀 2 位 | 违规 → 重命名 |
| **R4** | 文件类型白名单：`.md`/`.json`/`.mjs`/`.html`/`.sh`/`.txt`（限 2 个旧存留）| 其他后缀 → 移至 CDN 或仓库外 |
| **R5** | 禁图片（`.png`/`.jpg`）入 `docs/`（图片走外部 CDN，PDF 不入库） | 删除并通知起草人 |
| **R6** | 子目录深度 ≤ 3 层（不含文件本身） | 超 → 扁平化 + 通知 |
| **R7** | 文档内禁明文密钥/Token/密码，走引用 | 命中 → 立即恢复 git 历史 + 告警 P0 |
| **R8** | 删除文档需 PMO 指令 + commit hash 留痕 | 违反 → 回滚 + 报告 |
| **R9** | 只加不删：旧目录改名 `*-legacy/` 落新目录 | 直接删 → 违规 |
| **R10** | 引用其他文档用相对路径（`../NN-模块/xxx.md`），禁绝对路径或 `<TODO>` 占位 | 占位符 → 打回 |
| **R11** | 新文档必须落入 §〇 目标态目录（拒写到 14 个过渡期目录） | 拒收 |
| **R12** | 新建 PMO 命令/新模块时，任务表必须含「建 `engine-{name}/` 或 `20-services/{name}/` + README」 | 缺 → 拒收 |
| **R13** | 新旧目录过渡期【已结束 2026-09-22】：新文档一律进 §〇 目标态目录；禁止零散迁移（应走 `_win_tasks/docs-migration.ps1` 批量脚本） | 零散迁移 → 回滚 |

| 类别 | 命名建议 | 归档位置 |

| **15. 归档文档** | 原文保留 | `30-cross-cutting-docs/99-archive/` |

### 2.1 元信息头（每份 .md 必带 ≥ 3 行）

```markdown
# <H1 标题>

> 来源: <PMO/Wave/姓名> | 日期: YYYY-MM-DD | 责任人: <角色>
> 版本: v1.0（v0.x 草稿 / v1.0 批准 / v2.0 修订）
> 追溯: PRD-{N} / PMO-{M}（可选）
```

### 2.2 Agent 工作流（写文档时自检 8 项）

- [ ] 归档位置按 §〇 决策树（`00-架构` / engine-* / 20-services / 21-23 / 30-cross-cutting）
- [ ] 头部 3 行元信息完整
- [ ] 版本明确（v0.x → v1.0 必经评审）
- [ ] 文件扩展名在白名单（R4）
- [ ] 文件名小写+短横线+日期（R3）
- [ ] 引用文档用相对路径（R10），无 `<TODO>`/`<TBD>`
- [ ] 不涉及密钥/Token/密码（R7）
- [ ] 新建模块时，新目录 + README 同步建（R12）

### 2.3 文档与代码联动

| 触发事件 | 动作 |
|:--|:--|
| 模块新增/重命名 | 同步开 `engine-{name}/` + `20-services/{name}/` + README（R12） |
| 废弃模块/目录 | 不删，移至 `*-legacy/` 子路径（R9）+ `30-cross-cutting-docs/99-archive/` 登记 |
| PMO 执行完成 | 写 1 份交付报告入对应模块 + commit hash 留痕 |
| 文档变更 | 同步 `.trae/rules/架构铁律.md` 的引用（如引用 `docs/plans/...` 改为 `docs/21-runtime/legacy-plans/...`） |
