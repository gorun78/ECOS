## 〇、数据域二分总则（🔴 全规范判定前提，2026-09-28 v1.1）

ECOS 是强数据访问平台，一切存储对象先判定归属域，再谈 schema / 表 / 载体：

| 域 | 定义 | 载体 | 规范出口 |
|:--|:--|:--|:--|
| **控制域**（平台运行数据） | 平台自身运行所需：元数据、IAM/菜单、管道 DAG 定义、调度计划、审计、本体/KB/Agent/认知**定义态**、runtime 5 表等 | PG（主控制 schema + 五引擎 schema） | 本文件（IR/DR/EN/ST/MC） |
| **业务域**（外部接入数据及其加工产物） | 外部源系统数据 + 近源/DW/知识/应用各层加工数据 | MinIO / `ecos_dw` / Neo4j·向量 / Doris∨ClickHouse | `数据湖存储分层规范.md` v2.0（五层模型） |

**二分铁律**：
1. 控制数据**禁止**登记进五层模型（`layer` 字段仅业务对象），禁止写入业务域载体；
2. 业务数据**禁止**写入控制域 schema（含引擎 schema）；
3. 跨域引用只存**定位符**（对象 key / `schema.table` / datasourceId），禁止复制实体数据或跨域直查（对齐铁律 §3.3、湖规 §〇.3）。

## 二附、Schema 归属红线 ST07~ST09（5+1 口径，🔴 2026-09-28 新增，用户批准）

**归属设计原则**：引擎控制数据只独立这 5 个，其余控制数据一律统一主控制 schema。

| 归属 | 范围 | 内容 |
|:--|:--|:--|
| **引擎 schema ×5（封闭枚举）** | `ecos_data` / `ecos_ontology` / `ecos_knowledge` / `ecos_ai` / `ecos_cognitive` | 五对象引擎（土D/金I/水K/木C/火W）各自治控制数据：管道 DAG、本体定义、KB 元数据、Agent/Loop 定义、认知模型 |
| **主控制 schema ×1** | 现基线 `public`（迁移目标 `ecos_control`，工程清单 #3） | 其余全部控制数据：sysman/IAM、security、runtime（infra/task/monitor/llm-gateway）、workspace、四转化服务 ge/zhi/cheng/ming、dq、菜单、审计等 |
| **业务域（非控制）** | MinIO(近源) / `ecos_dw`(DW) / Neo4j+向量(知识双形态) / Doris∨ClickHouse(应用/物化) | 见《数据湖存储分层规范》v2.0，禁入上述 6 个控制 schema |

| # | 红线 | 处置 |
|:--:|:--|:--|
| **ST07** | 引擎 schema 仅五枚举；`CREATE SCHEMA` / 新表落新引擎 schema = FAIL；横切引擎（security/runtime）与 sysman/workspace/service 层新表一律落主控制 schema | lint 白名单 + Reviewer |
| **ST08** | 业务/外部数据（五层对象）只准落业务域载体；写入任一控制 schema = FAIL | lint + Reviewer |
| **ST09** | 跨引擎只准读写自家控制 schema；跨域访问只走引擎 REST / `runtime-access`，限定名直查他域表 = FAIL（呼应 IR01/IR06 与铁律 §3.3） | ArchUnit + Reviewer |

**存量处置（R9 只加不删）**：现存非五引擎 schema（`ecos_sysman` 20 / `ecos_security` 53 / `ecos_infra` 40 / `ecos_dq` 20 / `ecos_demo` 208 等）标 knownLegacy——不迁移不新建；迁移（若做）另立 PMO 批次 + `v_*` 兼容视图；规则只约束**新增**。

## 二、红线 EN01~EN03（执行 / 事务 / 数据流）

### 执行
| # | 规则 | 处置 |
|:--:|:--|:--|
| **EN01** | 所有 PG 访问必须走 HikariCP 连接池（spring 默认），禁止 `new DataSource()` | 静态检 |
| **EN02** | 事务边界 —— Service 层，单事务最多 1 个 commit 点 | DSL `@Transactional` 同方法 ≠ 跨表 |
| **EN03** | 批量 INSERT/UPDATE —— 必须 `REQUIRES_NEW` 子事务 + 单批 ≤ 100 | 防大事务 + PG MVCC 膨胀 |

### 数据流（跨引擎单向）
```
data-engine (D→I 抽取) ──主写──► 近源层 (ODS)
              │
              ▼
        ge-service (D→I 转化)
              │
              ▼ (读 ODS 只读)
   ontology-engine (业务对象 + 映射契约)
              │
              ▼
        知识工作台 (水K, 业务对象只读)
```
- 写 ODS 只属 `data-engine`（唯一事实源，铁律 §2.4 已证）
- `Ontology` / `Knowledge` 跨引擎读 ODS 只走 `runtime-access`，**不得绕 `BizObject` → 原生 SQL**
- 详细理由见 `架构铁律.md` §0.5 三工作台 5 条边界铁律

## 三、红线 ST01~ST06（三档 + 安全）

### 三档（v1.1 重写：控制域三档同构，差异全部落业务域载体）

| 域/层 | standard | enterprise | ultimate |
|:--|:--|:--|:--|
| 控制域（PG） | 五引擎 schema + 主控制 schema，**三档同构** | 同左 | 同左 |
| 近源 RAW | MinIO（三档同构基线） | MinIO | MinIO |
| DW CURATED | PG `ecos_dw` | PG `ecos_dw` | Doris ∨ ClickHouse 物化（单表 > 100 万行，二选一） |
| 知识·语义图谱 | PG 表承载（`ecos_knowledge` 定义态 + PG 关系表） | Neo4j | Neo4j |
| 知识·向量 | PG + pgvector（未启用时按 MC03 降级存并显式标记） | pgvector ∨ 专用引擎（ADR 定） | 同 enterprise |
| 应用 APPLICATION | PG `ecos_dw` | PG `ecos_dw` | Doris ∨ ClickHouse |

> 载体细节与读写边界见《数据湖存储分层规范》v2.0 §七A「版本×分层存储矩阵」。

| # | 规则 |
|:--:|:--|
| **ST01** | 表名中**禁止**含 `std_` / `ent_` / `ult_` 前缀（用 schema 隔离 + @Profile） |
| **ST02** | 跨档差量化（Neo4j/Doris/ClickHouse/向量引擎启用）必须 `@Profile({enterprise, ultimate})` 或配置开关守卫 |
| **ST09** | （Schema 归属红线见 §二附） |

### 安全（继承架构铁律 §2.4）
| # | 规则 |
|:--:|:--|
| **ST03** | 敏感列（`name` / `phone` / `id_card` / `amount` / `password`）必加 `AES-256-GCM + KMS` 加密，读取解密，响应脱敏 |
| **ST04** | 列级过滤：敏感字段返回前必调 `POST /api/security/cls/columns` |
| **ST05** | 行级过滤：查询前必调 `POST /api/security/rls/apply` |
| **ST06** | 事件审计：写操作必发 Kafka `ecos.audit`（common-api `KafkaTopics.AUDIT` 常量） |

## 四、DDL 模板（新表）

```sql
CREATE TABLE IF NOT EXISTS ecos_{module}_{business} (
    id              VARCHAR(36) PRIMARY KEY DEFAULT gen_random_uuid(),
    -- 业务字段 --
    create_time     TIMESTAMP NOT NULL DEFAULT NOW(),
    update_time     TIMESTAMP NOT NULL DEFAULT NOW(),
    create_by       VARCHAR(100),
    update_by       VARCHAR(100),
    version_no      VARCHAR(20) NOT NULL,
    is_deleted      SMALLINT NOT NULL DEFAULT 0,
    domain          VARCHAR(50) NOT NULL DEFAULT 'default'
);
CREATE INDEX IF NOT EXISTS idx_{table}_{col} ON ecos_{module}_{business}({col});
```

### seed.sql 同步
- 新字典 → seed 必加（最小 3 行示例）
- seed 必须幂等（`ON CONFLICT DO NOTHING`）
- seed 与 V{n} 同 commit（同 PR 同 commit）

## 五、MyBatis Mapper 规范

### 三层（Data / Service / Controller）

| 层 | 职责 | 禁止 |
|:--|:--|:--|
| Data (DAO/Mapper) | 数据库 CRUD（XML） | 业务逻辑 / `if` 业务判断 |
| Service | 业务规则 / 事务 / 参数校验 | `JdbcTemplate` 直接连 |
| Controller | 入参校验 + 调 Service | `JdbcTemplate` 直接连（IR01） |

### XML 模板
```xml
<!-- INSERT -->
<insert id="insertX" parameterType="com.chinacreator.gzcm.xxx.dto.XxxDTO">
    INSERT INTO ecos_xxx (id, name, create_time, create_by, version_no, is_deleted, domain)
    VALUES (#{id}, #{name}, NOW(), #{createBy}, '1', 0, #{domain})
    <!-- 字段顺序必须与 DDL 严格一致 -->
</insert>

<!-- UPDATE 必带乐观锁 -->
<update id="updateX">
    UPDATE ecos_xxx
    SET name = #{name},
        update_time = NOW(),
        update_by = #{updateBy},
        version_no = version_no + 1
    WHERE id = #{id} AND version_no = #{versionNo} AND is_deleted = 0
</update>

<!-- DELETE 必为逻辑删除 -->
<update id="deleteX">
    UPDATE ecos_xxx
    SET is_deleted = 1, update_time = NOW(), update_by = #{updateBy}
    WHERE id = #{id} AND is_deleted = 0
</update>
```

### 禁止
- **禁** `SELECT *`（IR04）
- **禁** `${}` 传参 / `<if>` 多 SQL 拼接（IR05）
- **禁** 循环内查库 / 调远端（后端规范 §7）

## 十附、多库兼容红线 MC01~MC06（🔴 2026-09-28 新增 · 目标态设计约束）

> 设计原则：控制域存储以 PostgreSQL 为当前基线与唯一已认证库，**兼容 MySQL / Oracle / MSSQL / 达梦 / 人大金仓**。
> **MC 条款 = 对新代码的即时约束**（新增 DDL/Mapper 必须可移植）；存量 PG 专有写法按 knownLegacy 逐步收敛，不作批量返工。

| # | 红线 | 说明 |
|:--:|:--|:--|
| **MC01** | 新主键统一 `VARCHAR(36)`，UUID **应用侧生成**；禁在 DDL/INSERT 使用 `gen_random_uuid()` 等 PG 私有函数 | 存量 BIGSERIAL/默认值按 knownLegacy |
| **MC02** | 类型白名单：`VARCHAR/TIMESTAMP/SMALLINT/INTEGER/BIGINT/TEXT`（JSON 以 TEXT/JSONB 双轨存）；禁 `timestamptz` 私有语义、PG 数组、`serial` 裸用 | 达梦/金仓官方 PG 兼容模式亦不保证私有类型 |
| **MC03** | 跨库 SQL 禁 PG 专有语法裸用：`ON CONFLICT` / `RETURNING` / `::` cast / JSONB 操作符 / `<>` 向量运算符 → 必须 MyBatis `databaseId` 方言片段或 Adapter 层，且提供降级分支 | 现状范例（保留）：`PgVectorSupport` 启动探测扩展，不可用则向量链路降级 |
| **MC04** | OLAP 双例外（Doris / ClickHouse）只准承载业务域 DW/应用层；**控制域禁用**；同一部署 `dw.olap.engine=doris|clickhouse` 二选一，禁双 OLAP 并存双写；统一经 `runtime-access` 收口（IR06） | Doris=MySQL 协议、CH=私有方言，均在多库兼容目标之外 |
| **MC05** | 向量数据属业务域知识层载体，禁入控制 schema（同 ST08）；列在 pgvector 未启用档位按 TEXT/JSONB 降级存并带 `_json` 后缀 | 对齐湖规 v2.0 §七A 双形态 |
| **MC06** | schema/库名一律配置化（`ecos.db.control-schema` / `ecos.db.engine-schema.*` / `ecos.dw.*` 取数），DDL/Mapper/yml 禁硬编码 schema 前缀 | 主控制 schema `public`→`ecos_control` 迁移的前置条件（工程清单 #6） |
