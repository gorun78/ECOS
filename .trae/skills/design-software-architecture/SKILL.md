# 软件详细设计说明书

## 输入

| 输入 | 类型 | 必需 | 来源路径 | 用途 |
|------|------|------|---------|------|
| 架构概要设计 | 文档 | 是 | `docs/02设计阶段/02-01架构设计/架构概要设计.md` | 系统上下文、模块划分、技术栈、部署架构基础 |
| 需求文档 | 文档 | 是 | `docs/01需求分析/` | 产品功能清单、需求说明书、PRD |
| 项目配置 | 文件 | 是 | `.hermes/config.json` | 技术栈约束、端口、数据库连接、Hermes 地址 |
| 后端源码 | 代码 | 是 | `backend/src/main/java/` | **反向分析权威来源**，按模块读取 Controller/Service/Entity/Repository/DTO |
| 前端源码 | 代码 | 是 | `frontend/src/` | 页面路由、组件、API 调用模块 |
| 数据库迁移脚本 | 代码 | 是 | `backend/src/main/resources/db/migration/` | 表结构、字段定义、索引、Flyway 版本历史 |
| UI 设计规范 | 文档 | 否 | `docs/01需求分析/02-UI设计/` | 页面交互参考 |
| 历史 ADR | 文档 | 否 | `docs/02设计阶段/02-01架构设计/adr/` | 技术决策背景 |
| 现有系统详细设计 | 文档 | 否 | `docs/02设计阶段/02-01架构设计/系统详细设计.md` | 旧版参考（如存在） |

### 输入校验

| 校验项 | 规则 |
|--------|------|
| 架构概要设计 | 必须存在，否则先执行 Wave 1 产出概要设计 |
| 需求文档 | 必须存在产品功能清单，用于 3.x 各模块的功能范围和验收要点 |
| 后端源码 | 至少存在 Controller 层代码，确认模块划分 |
| 数据库迁移 | Flyway 脚本完整（V1~Vn），DDL 为权威表结构来源 |

### 读取策略

- 概要设计文档：全量读取
- 后端源码：按模块分批读取（每模块涉及文件 < 20 个），不读取全量代码
- 前端源码：仅读路由配置和 API 调用模块，不读组件实现细节
- 数据库迁移：全量读取 Flyway 脚本

## 输出

**唯一输出文件**: `docs/02设计阶段/02-01架构设计/系统详细设计说明书.md`

### 输出校验

| 校验项 | 规则 |
|--------|------|
| 12 章全覆盖 | 不省略任何章节，不允许出现"待补充" |
| 3.x 每模块 13 子节 | 功能目标/范围/权限/规则/流程/页面/接口/数据库/状态/异常/日志/安全/验收，缺一不可 |
| Mermaid 图 | 每模块至少 1 张业务流程图，至少 1 张 ER 图或状态图 |
| 可追溯 | 接口路径、表名、Entity 名称与源码一致 |
| 无秘密泄露 | 不输出密码、密钥、Token 示例值 |

## 设计边界

基于架构概要设计和项目源码反向分析，输出标准 12 章节的《系统详细设计说明书》。必须包含：系统结构、模块功能详细设计（每模块 13 子节）、公共组件/数据/接口设计、安全/非功能/日志/部署设计、附录。

所有图表使用 Mermaid 代码块（erDiagram / flowchart / stateDiagram-v2 / sequenceDiagram 等），禁止外部图片引用。

## 执行流程

### 波次判定

```
架构概要设计.md 不存在 → Wave 1: 先出概要设计
架构概要设计.md 存在 → 直接输出完整系统详细设计说明书（不限制版本号）
```

### 执行步骤

1. 校验输入：架构概要设计存在、需求文档存在、源码可读、Flyway 迁移可读
2. 读取 `架构概要设计.md` 确定模块划分
3. 按模块分批读取源码 Controller/Service/Entity（每模块 < 20 文件）
4. 判定工程类型（旧工程以代码为权威）
5. 输出唯一文件 `docs/02设计阶段/02-01架构设计/系统详细设计说明书.md`
6. 自检：12 章不省略、每模块 13 子节、Mermaid 图完整、可追溯到源码

## 约束

- 旧工程以代码为权威，所有结论可追溯到具体源码文件
- 图前说明目的，图后解释关键关系
- 现状/推断/建议/待确认标注正确
- 禁止输出秘密值（密码、密钥等）
- 所有 Mermaid 图使用独立代码块
