# Detailed Design Directory Template — 标题编号规范与合并方法

## 正确的目录结构

```
docs/
└── 02设计阶段/
    └── 02-02详细设计/
        ├── 00-详细设计总览/
        │   ├── 00-01-设计说明.md
        │   ├── 00-02-功能模块清单.md
        │   ├── 00-03-需求追踪矩阵.md
        │   └── 00-04-模块依赖关系.md
        ├── 01-功能设计/                         # 一级目录
        │   ├── 01-01-系统管理模块/              # 二级目录
        │   │   ├── 01-01-01-功能设计.md         # 三级设计文档
        │   │   ├── 01-01-02-库表设计.md
        │   │   └── ... (7个设计指标)
        │   ├── 01-02-项目管理模块/
        │   └── ... (7个模块)
        ├── 02-公共设计/
        │   └── 02-01 ~ 02-06 (6个文件)
        ├── 03-非功能设计/
        │   └── 03-01 ~ 03-05 (5个文件)
        └── 99-附录/
            └── 99-01 ~ 99-04 (4个文件)
```

## 关键原则

1. **功能作为章节，不创建子目录**：每个 F001-xxx 是文档内章节（##），不是独立文件
2. **三层编号**：`section-module-dim`，如 01-01-02 = 功能设计(01)下第1模块(01)的库表设计(02)
3. **每模块7个设计指标文件**：功能说明、库表设计、接口设计、流程设计、状态设计、字典设计、异常与边界设计

## 合并为系统详细设计.md 的方法

目标是产出 `docs/02设计阶段/02-01架构设计/系统详细设计.md`。

1. 读取所有 D001-D007.md 源文件（arch 产出的干净版本，非二次拆分后的碎片文件）
2. 每个模块的 `# DXXX-模块名` → 降级为 `## N. 模块名 详细设计`
3. 所有模块拼接，`---` 分隔
4. 顶层加 `# 功能设计` 作为一级标题
5. 公共设计和非功能设计作为平级 `# 公共设计` / `# 非功能设计` 追加

**标题层级示例**：
```
# 功能设计
  ## 1. 系统管理 详细设计
    ### 1. 功能说明
      #### 1.1 目标与范围
    ### 2. 库表设计
      ...
  ## 2. 项目管理 详细设计
    ...
# 公共设计
  ## 02-01 公共库表设计
  ...
```

## 常见错误

- ❌ 把 D001-D007 的每个功能拆分成独立文件再合并 → 标题层级全乱
- ❌ 合并时没有降级标题层级 → `# 系统管理` 和 `# 功能设计` 平级
- ❌ 用 `02-02详细设计/` 的碎片文件做源 → 应直接用 arch 产出的 D001-D007.md
- ❌ 每个维度下又按功能创建目录 → 功能应是文档章节不是目录
