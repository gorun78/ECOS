# 详细设计文档目录模板

## 层级规则

- 一级目录：设计大类（如 01-功能设计）
- 二级目录：业务模块（如 01-01-系统管理模块）
- 三级内容：模块的各项设计文档（每个模块 7 个设计指标文件）
- **具体功能作为文档内的章节**，不创建功能目录

## 编号规范

```
01-XX-YY-ZZ-设计指标名称.md
 ^   ^  ^  ^
 |   |  |  └── ZZ: 设计维度编号 (01-07，对应功能说明/库表设计/接口设计/流程设计/状态设计/字典设计/异常与边界设计)
 |   |  └───── YY: 模块编号 (01-07)
 |   └────────── XX: 大类编号 (如 01=功能设计)
 └─────────────── 一级大类编号
```

## 功能编号（文档内章节格式）

每个功能的编号使用 `F001`、`F002`... 等固定编号，在功能设计文档内作为章节标题：

```markdown
## 1.1. 功能说明

### 1.1.1 目标与范围
...

### 1.1.2 角色
...

### 1.1.3 验收标准
...

## F001 用户认证

目标、范围、业务规则...

## F002 角色管理
...
```

## 模块合并标题层级

当多个分散文件合并为一份 `系统详细设计.md` 时：

```markdown
# 系统详细设计

## 1. 系统管理 详细设计
### 1.1. 功能说明
  #### 1.1.1 用户管理
    ##### 目标
    ##### 角色
    ##### 验收标准
  #### 1.1.2 角色管理
### 1.2. 库表设计
  #### 1.2.1 system_user
...

## 2. 项目管理 详细设计
...
```

层级：`#` 文档标题 → `##` 模块 → `###` 设计维度 → `####` 功能 → `#####` 子项
