### Task 5 — SQL 查询控制台结果错误修复 ✅

**根因**: 后端 `execute()` 返回 `columns` 为对象数组 `[{name, label, type}]` + `rows` 以 `columnLabel` 为键。前端多处把 `columns` 当字符串数组处理, 导致 `result.columns.map(c => <th>{c}</th>)` 显示 `[object Object]`。

**修复点 (3 处)**:
1. [ConnectionsTab.tsx \(InlineSqlConsole\)](file://////wsl$/Ubuntu/home/guorongxiao/ECOS/ecos_frontend/src/pages/data-workbench/tabs/ConnectionsTab.tsx) — `result({ columns: colLabels, ... })` 提取 `c.label || c.name || c`
2. [sql-query-console/index.tsx](file://////wsl$/Ubuntu/home/guorongxiao/ECOS/ecos_frontend/src/pages/sql-query-console/index.tsx) — 同样提取列名 + 修 `total` (后端返回 `rowCount`) + 修 `executionTimeMs` (后端返回 `elapsedMs`) + ResultTable 传参类型修复
3. [SqlQueryConsole.tsx](file://////wsl$/Ubuntu/home/guorongxiao/ECOS/ecos_frontend/src/pages/SqlQueryConsole.tsx) — 同样提取列名

**类型**: [sql-query-console/types.ts](file://////wsl$/Ubuntu/home/guorongxiao/ECOS/ecos_frontend/src/pages/sql-query-console/types.ts) `QueryExecuteResponse.columns` 改为 `(string | { name, label, type })[]` 兼容两种格式

**验收**: SQL 控制台输入 `SELECT * FROM td_datasource LIMIT 5` 后, 列表正常显示 (列名 + 行数据, 无 `[object Object]`)

## 五、技术债 / 遗留问题 (供下个 PMO 指令)

1. **SQL 控制台三套实现分裂** — `ConnectionsTab.InlineSqlConsole` / `SqlQueryConsole.tsx` 老版 / `sql-query-console/index.tsx` Monaco 版 — 建议统一为 Monaco 版
2. **`AsyncTaskCenterView` 纯 mock UI** — 7 条硬编码任务 + `setInterval` 随机进度, 无后端 API; 建议后续接入 `ITaskManagementService`
3. **`QueryExecutionServiceImpl` 直接 `DriverManager.getConnection`** — 不走 runtime-access Connector, 铁律 2.5 偏离; Pipeline 节点已改用 `JdbcConnector.executeSql`, 后续查询链也应收敛
4. **`DataSourceEntity` 手写 getter/setter**, 未用 Lombok; `QueryController` 入参用 `Map<String,Object>`, 违反后端开发规范(强类型 DTO)
5. **`MetadataCollectTaskRegistrar` 启动时注册**: git 仓库目录首次使用需 `git init` — 当前实现依赖 `GitService.commit` 的幂等性, 若 git 服务对未 init 目录报错, 需预处理
6. **定时策略 cron 解析**: `AutoCollectScheduler` 是 60s 扫描 + `simpleCronMatch` 简化匹配, 真 cron 库支持待补充
