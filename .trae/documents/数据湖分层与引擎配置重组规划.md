## 1. 摘要

### 1.1 业务目标

| # | 目标 | 落点 |
|:--|------|------|
| G1 | 多源异构数据源同步到数据湖，形成**近源层** | 数据源同步 → 采集型管道 → MinIO 近源区 |
| G2 | 数据管道与数据质量**基于近源层**处理，形成 **DW 层** | 管道读近源区，产出落 DW 层表 |
| G3 | 本体与知识**从 DW 层**取数 | 本体自动发现 / 知识抽取面向 DW 层表 |
| G4 | 引擎配置项按分层**重组** | 引擎配置面板由 7 组重构为 4 段，后端提供分段端点 |

### 1.2 交付范围（用户已拍板）

| 项 | 决策 |
|:--|:--|
| 实施范围 | **扩到近源层 zone 落地**：配置重组 + `zone` 列 DDL + MinIO 新前缀 + `SINK_MINIO` 写入带 zone + 新链补写 `layer`。**不做** `SOURCE_MINIO`（读湖） |
| 语义层配置 | 数据工作台**保持 4 段**，`semantic` 段为占位空态；语义层配置归**本体工作台**；本次**存储层规划写入规则文件**供其他工作台引用 |
| 后端参与度 | **新增 `GET /api/v1/engine/data/settings/groups` 分段端点**，作为分层归属的真相源，前端消费 |

### 1.3 核心策略

- **不改任何 `config_key`**，只改分组归属 → 无 `sys_config` 数据迁移。
- 旧 `PREFIX_TO_SUBGROUP` / `groupBySubGroup()` / 前端 `flattenConfig()` **保持原样**（保证既有拼键不错位）；分段走**新增**的独立映射表与新端点。

## 3. 规划一：数据湖分层模型

### 3.1 五层定义（沿用 `DataLayer` 枚举 + 中文别名）

| 枚举 | 中文别名 | 定义 | 物理载体 | 生产者 | 消费者 |
|:--|:--|:--|:--|:--|:--|
| `SOURCE` | 源系统 | 外部业务系统原始库 | 外部 PG/MySQL/Oracle/CH… | — | 采集型管道 |
| `RAW` | **近源层** | 原样落湖、不做业务加工 | **MinIO 数据湖** | 采集型管道（`SINK_MINIO`） | 管道、数据质量 |
| `CURATED` | **DW 层** | 清洗/转换/关联后的主题明细 | DW 库表（PG / Doris） | 数据管道、数据质量 | 本体、知识、管道 |
| `SEMANTIC` | 语义层 | 本体/实体/关系 | 本体引擎存储 | 本体引擎（ge 格物） | 知识引擎（zhi 致知） |
| `APPLICATION` | 应用层 | 面向场景的聚合宽表/指标 | DW 库表 | 聚合管道 | 场景工作台 |

> 五行对齐：`CURATED→SEMANTIC` 即 **ge 格物（D→I）**，`SEMANTIC→K` 即 **zhi 致知（I→K）**。

### 3.2 近源层两 zone

| 维度 | `STRUCTURED`（结构化近源区） | `UNSTRUCTURED`（非结构化近源区） |
|:--|:--|:--|
| 内容 | 表数据的 CSV 快照 | 原始文档（PDF/Word/Excel/图片…） |
| 格式要求 | 需 schema/列序稳定、可按列裁剪 | 二进制原样、保留原文件名 |
| 分区策略 | `dt=YYYY-MM-DD` 日期分区 | 按 `docId` 寻址，无日期分区 |
| 消费方 | 数据管道（SQL 可读） | 解析器 → 抽取文本 |
| 生命周期 | 按 `dw.lake.retention_days` 滚动清理 | 长期保留（原文不可再生） |

**物理隔离**：同一 bucket 内前缀分区，**不新增 bucket、不新增 Docker 容器**。

### 3.3 MinIO 对象 key 规范

```
结构化（本批次实现）：raw/structured/{source}/{table}/dt=YYYY-MM-DD/{table}_{ts}.csv
非结构化（P4 实现）：raw/unstructured/{source}/{docId}/{originalFileName}
旧前缀（保留可读，不迁移）：datalake/{datasourceId}/{table}_{ts}.csv
```

- `{source}`：上游数据源标识（采集型管道取 `datasourceId`；普通管道取数据源 name 的小写短横线化，缺省 `default`）
- `dt=` 分区段：字段名固定 `dt`（与 `dw.lake.partition_by` 默认值一致；该配置接入列 P2）
- 节点配置显式指定 `objectName` 时**以其为准**（既有行为，保留）

### 3.4 端到端数据流

```
① 采集链（G1）
   外部数据源(SOURCE) ──SOURCE_JDBC→SINK_MINIO──▶ MinIO raw/structured/{source}/{table}/dt=… (RAW)
   状态：✅ 本批次打通（key 加 zone+分区、登记 layer=RAW/zone=STRUCTURED）

② 加工链（G2）
   MinIO raw/structured (RAW) ──数据管道──▶ DW 层表 (CURATED)
   状态：❌ 缺 SOURCE_MINIO → 管道无法读湖（P2 关键缺口）；本批次仅保证 SINK/OUTPUT_OBJECT 产出标记 layer=CURATED

③ 质量链（G2）
   DW 层表 (CURATED) ──数据质量规则──▶ 评分/告警
   状态：⚠️ 规则/状态机/告警已具备，但 buildContext 空转不取数（P3）

④ 语义链（G3）
   DW 层表 (CURATED) ──本体自动发现/建模──▶ 本体(SEMANTIC) ──KbEngineGraphSyncClient──▶ 知识(K)
   状态：⚠️ 通道已通（POST :18086/api/v1/kb/graph/sync），但自动发现源是「数据源元数据」而非 DW 表（P3）
```

### 3.5 `zone` 列 DDL（本批次执行）

```sql
ALTER TABLE td_data_resource ADD COLUMN IF NOT EXISTS zone varchar(16);
COMMENT ON COLUMN td_data_resource.zone IS
  '近源区：STRUCTURED=结构化近源 / UNSTRUCTURED=非结构化近源 / NULL=非近源层';
```

纯加列、无回填，零数据风险。

