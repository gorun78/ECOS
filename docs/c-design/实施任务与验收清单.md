# ECOS 场景工作台与认知引擎：实施任务与验收清单

> 本文件是 Coding Agent 的执行计划。所有测试状态必须以实际运行结果为准。

## 1. 实施原则

- 先审计、后实现；先契约和测试、后代码。
- 采用增量改造；保留既有 API、数据表、前端路由和用户未提交更改。
- 每个阶段必须产出真实测试证据，不允许只添加测试名称或空壳测试。
- 任何依赖缺失必须如实报告，禁止以静态 mock 作为端到端成功证明。

## 2. 阶段 0：仓库与契约审计（必须先完成）

### 任务
- [ ] 读取架构铁律、AGENTS/Trae 规则、ADR、PRD 与详细设计。
- [ ] 查明 workspace/cognitive/ai/security/runtime-task 的实际模块与源码路径。
- [ ] 列出所有现有场景 API、认知 E1-E4 API、OpenAPI operationId 和响应包络。
- [ ] 查明 Blueprint、binding、binding link、状态枚举、完整度算法和现有迁移。
- [ ] 查明 Hypothesis/Belief/Evidence/Mind/Cognitive Model 的实际存储与写入归属。
- [ ] 查明前端路由、现有场景页面、认知组件、统一 API client、i18n、主题和 task-center。
- [ ] 运行当前相关单测/集成测试并保存基线。
- [ ] 输出 `implementation-audit.md`，记录 `EXISTS/PARTIAL/MISSING/CONFLICT/NOT_VERIFIED` 与证据。

### 阶段退出标准
- 不存在未记录的 API/DB/状态机冲突；
- 如有冲突，已经列出 ADR/裁决问题，涉及写权威/安全/迁移的子任务不得越过冲突继续改造。

## 3. 阶段 1：契约与安全守护

- [ ] 统一场景/认知链路关联键：traceId、requestId、scenarioId、blueprintId/version、contextDigest、runId。
- [ ] 确认所有新增/变更 API 在 OpenAPI/API 前置件中登记。
- [ ] 检查新增 Controller 的认证、授权、密级、租户范围、审计与错误包络。
- [ ] 确保 security-engine/PDP 不可用时受保护写操作 fail-closed。
- [ ] 增加/补齐完整度、bindingType、状态机、runMode、E1-E4 的契约测试。
- [ ] 增加架构守护：禁止新增 `cognitive_context`、认知业务事实表、第二套 Agent Runtime、私有调度器和模型供应商直连。

### 阶段退出标准
- API 契约 lint 通过；
- 安全负向测试通过；
- 架构守护测试能捕获禁止事项。

## 4. 阶段 2：场景工作台纵向闭环

- [ ] 复用现有 Scenario Blueprint 实体/JSONB 与绑定/连边模型，不创建平行模型。
- [ ] 后端完整度是唯一权威来源；前端只展示。
- [ ] `E_req` 从后端规则/配置推导；`presentEdges` 是真实有效边。
- [ ] 孤岛绑定可在 DRAFT 显示与修复，但激活/发布被阻断。
- [ ] 场景详情展示目标、范围、版本、绑定图、缺口、验证状态。
- [ ] 业务语言入口不要求用户先理解技术术语。
- [ ] Blueprint 保存、验证、审批、发布、运行都绑定版本并记录审计。
- [ ] Sandbox 与 Formal 分离，正式运行拒绝 sandbox 产物。
- [ ] 复用现有 runtime-task/AsyncTaskCenterView 处理长任务。
- [ ] UI 对 empty/404/403/503/网络错误分别呈现，不伪装成功。

### 阶段退出标准
- SW-01 至 SW-10 有可运行自动化测试；
- 完整度与后端响应一致；
- 沙盘隔离服务端负向测试通过；
- 旧场景 API 与页面回归通过。

## 5. 阶段 3：Context Builder 与认知契约

- [ ] 在 cognitive-engine 内实现 Context Builder 应用服务（不新建服务/上下文表）。
- [ ] 通过既有 API/服务访问 D/I/K/C/能力目录，禁止跨域直读业务表。
- [ ] 按调用者权限过滤所有资产与来源。
- [ ] 返回 sources、gaps、conflicts、warnings、contextDigest。
- [ ] 对相同规范化引用集合生成稳定 digest。
- [ ] 缺少关键输入时返回明确 gap，不允许模型补造。
- [ ] E1-E4 端点路径/参数/响应以现有代码为准，禁止猜路径或破坏签名。
- [ ] 明确 Evidence/Hypothesis/Belief 的来源、版本、状态与反证字段映射。
- [ ] 所有认知执行引用 contextDigest 与来源资产版本。

### 阶段退出标准
- CE-01、CE-02、CE-10 通过；
- 上游依赖不可用时错误语义不被折叠；
- 无新增权威业务数据复制。

## 6. 阶段 4：Framework Registry 与策略选择 MVP

- [ ] 注册首批四个框架：问题定义、证据评价、溯因/竞争假设、情景/敏感性。
- [ ] 定义框架 Schema 和版本不变性测试。
- [ ] 策略选择先硬约束过滤，再排序。
- [ ] 每个被排除框架都返回原因码。
- [ ] 计划草案含依赖 DAG、输入输出契约、预算、验证与停止条件。
- [ ] 计划验证覆盖环路、缺输入、无效 Schema、缺能力、权限、预算。
- [ ] 真实执行仍由既有 W Agent Runtime/ToolExecutor 承担。
- [ ] 版本切换/重规划必须记录原因和实际使用版本。

### 阶段退出标准
- CE-03、CE-04、CE-05 通过；
- 无第二套 Agent Loop；
- 超预算和无进展能可靠终止。

## 7. 阶段 5：年度经营预测端到端验收

固定验收包建议：
- 目标年度：2027；
- 项目：3 个；
- 部门：2 个；
- 期间：12 个月；
- 情景：基准 + 验收延期；
- 输入包括合同基数、归属比例、实现率、成本归集/分摊、正式口径、历史画像与假设版本。

### E2E 步骤
1. 财务/经营角色确认口径版本、公式、生效期和批准人。
2. 数据管理员导入基准数据并修复故意注入的 DQ 错误。
3. 经营负责人运行基准预测，企业/部门/项目三级金额与手工金标准一致。
4. 从企业利润下钻至某项目某月某环节，查看合同基数、归属比例、实现率、公式、源记录和证据。
5. 复制“验收延期”情景，只改变目标项目指定月份的验收率；比较结果只在目标范围变化。
6. 风险项生成经营动作，填写负责人、期限、预期影响、控制 KPI、审批人。
7. 回灌实际，查看原预测、实际、误差和待复审假设。
8. 使用受控 AI 提问预测与风险，回答必须引用 forecastRunId、caliberId、asOfTime、置信/不确定性和可点击证据。
9. 关闭 cognitive-engine，确认场景页面不白屏且显示 503/降级状态。
10. 关闭 security-engine/PDP，确认受保护写操作拒绝。
11. 验证相同输入/版本重放的确定性计算一致。
12. 验证 Sandbox 产物无法被正式运行引用。

### 业务红线（任一失败则 E2E FAIL）
- 任一金额无法追溯到输入快照/公式/证据；
- LLM 文本替代确定性金额；
- security-engine 不可用时业务写操作放行；
- 认知引擎新增业务事实表或 `cognitive_context` 表；
- 跨引擎 import impl/私建 Driver/私建调度；
- 既有 API 路径或签名被破坏；
- Sandbox 产物污染正式运行；
- 单次偏差自动改生产规则/知识/模型；
- 测试未执行却被报告为通过。

## 8. Definition of Done

每个功能必须同时满足：
- [ ] 需求/设计/代码/测试追溯关系明确；
- [ ] 代码符合现有架构与风格；
- [ ] 输入、输出、状态、错误、权限与审计均有测试；
- [ ] 正常路径、边界、失败、依赖不可用和权限拒绝已覆盖；
- [ ] 前端有 loading/empty/error/forbidden/degraded 状态；
- [ ] i18n、四主题、键盘/可访问性遵循现有规范；
- [ ] 既有相关测试无回归；
- [ ] 实际测试命令及输出记录在实施报告；
- [ ] 未完成项、风险和未验证事实明确列出。
