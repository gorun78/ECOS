# 详细设计：ECOS 场景工作台（Scenario Workbench / workspace）

> 文档版本：v1.0  
> 日期：2026-10-29  
> 实施定位：对既有 workspace/场景工作台的增量设计，不授权重写现有功能。  
> 主责：workspace 后端与场景工作台前端；协作：cognitive-engine、ai-engine、security-engine、data-engine、ontology-engine、kb-engine、runtime-task、预测业务域。

## 1. 目标与非目标

### 1.1 目标

场景工作台是企业业务人员进入 ECOS 的业务语言入口。它将“我要解决什么经营问题”转化为版本化的 Scenario Blueprint，并围绕蓝图管理：
- 场景定义、范围、目标、成功标准和约束；
- 业务对象/数据/本体/知识/认知/能力等资产绑定；
- 绑定关系、依赖图、缺口任务和完整度；
- 预检查、测试、演练、审批、发布与运行；
- 运行结果引用、证据下钻、失败解释和受控反馈。

首个端到端场景为“企业年度经营预测”。场景工作台不是聊天壳，不自行计算利润，也不是 Agent Runtime。

### 1.2 非目标

- 不在 workspace 复制数据、本体、知识、认知资产的权威存储。
- 不把所有业务逻辑塞进 Blueprint JSON。
- 不自建 Agent loop、模型路由、权限引擎、任务调度器或规则引擎。
- 不把“蓝图完整度 100%”等同于业务结果正确。
- 不以 LLM 文本代替确定性业务计算、业务审批或测试证据。

## 2. 用户工作流与信息架构

### 2.1 主要流程

1. 用户从业务语言入口创建或选择场景（例如“2027 年度利润预测”）。
2. 填写目标年度、组织/项目范围、指标口径、截至时间、成功标准与约束。
3. 工作台展示场景组成图：业务对象树、资产绑定/依赖关系、执行流程、认知能力。
4. 系统按后端规则计算完整度，列出缺失/冲突项及可执行的修复任务。
5. 用户可以请求 AI 提出绑定/缺口/假设候选；所有候选必须带来源与不确定性，不直接成为权威绑定。
6. 执行预检：依赖健康、输入快照、口径版本、数据质量、权限、必需能力和预算。
7. 执行验证/沙盘演练；查看步骤轨迹、结果、证据与错误。
8. 根据风险等级进入审批，审批通过后发布不可变蓝图版本。
9. 正式运行绑定已发布蓝图版本与输入快照；结果通过 `runId`/业务运行 ID 回链。
10. 实际结果回灌后，Outcome Evaluator 产生评估与更新候选，用户批准后进入下一版本，不自动覆盖旧版本。

### 2.2 页面布局

复用当前 workspace 路由和页面组件，按现状映射，不另造平行页面。目标信息架构：
- 顶部：场景名称、状态、版本、最近运行、当前口径/范围；
- 左栏：业务对象树/场景节点导航；
- 中栏：场景组成关系图与执行流程（业务对象、资产绑定、依赖边、缺口标记）；
- 右栏：按所选节点切换“属性/绑定”“完整度与缺口”“认知面板”“运行/测试结果”“审批/发布历史”；
- 场景首页使用业务语言；高级模式可以暴露 Goal、Blueprint、Context、Framework 等技术信息，但不要求业务用户先理解这些概念。
- E1-E4 认知卡片沿用现有组件与 API 接缝；不得为新页面复制一套认知查询逻辑。

### 2.3 页面状态

每个异步区块均需支持 `loading / success / empty / degraded / error / forbidden`：
- `[]`：请求成功但没有记录，显示空态引导；
- `404`：请求目标不存在，显示资源不存在；
- `503`：依赖未启用/不可用，展示降级提示；
- `403`：显示无权限，不能降级为显示未过滤数据；
- 网络错误：保留 traceId/requestId（如果后端提供），可重试；
- 不能把错误转换成空数组，不能以 mock 数据覆盖错误态。
场景列表、图、右侧认知卡片应分别处理状态，避免单一依赖失败导致整页白屏。

## 3. Scenario Blueprint 逻辑模型

### 3.1 模型定位

`ScenarioBlueprint` 是 workspace 持有的场景定义与发布载体，具有稳定 ID 和不可变版本。它包含场景配置、目标、约束、资产绑定、依赖边、验证规范与发布信息。它只保存引用和配置，不复制外部资产正文。

建议逻辑字段（先对齐现有实体/JSONB，再决定字段新增，不得直接照此新建表）：

```json
{
  "scenarioId": "scenario-annual-forecast",
  "blueprintId": "bp-annual-forecast",
  "version": 4,
  "name": "2027 年度经营预测",
  "description": "预测收入、成本与利润并识别经营风险",
  "domain": "enterprise_operations",
  "lifecycleStatus": "DRAFT",
  "runMode": "FORMAL",
  "goal": {
    "statement": "形成可追溯的年度经营预测",
    "successCriteria": [
      "金额可追溯至输入快照与公式",
      "正式业务口径已批准",
      "所有必需验证通过"
    ]
  },
  "scope": {
    "period": "2027",
    "caliberId": "caliber-01",
    "asOfTime": "2026-10-29T00:00:00Z",
    "organizationRefs": [],
    "projectRefs": []
  },
  "bindings": [],
  "edges": [],
  "requiredCapabilities": [],
  "validationProfileRef": "scenario-validation/1",
  "createdAt": "...",
  "createdBy": "...",
  "updatedAt": "...",
  "publishedAt": null
}
```

`runMode` 与 `lifecycleStatus` 必须正交：草稿可以被沙盘运行，已发布蓝图也可能被复制到沙盘；“演练/正式”不能只靠名称、标签或 UI 状态判断。

### 3.2 绑定模型

必须先检查现有绑定实体与 `ecos_scenario_binding_link` 等在途契约。不要创建第二套绑定表。逻辑上每个绑定包含：
- `bindingId`；
- `bindingType`（严格复用现有枚举，禁止前后端各造词表）；
- `targetRef`：目标资产类型、稳定 ID、版本/快照引用；
- `role`：该绑定在场景中的角色；
- `required`；
- `scope`：组织/项目/期间/口径范围；
- `provenance`：人工/规则/AI 候选及证据引用；
- `status`：有效、待校验、冲突、失效等（以现有状态枚举为准）。

既有设计提及“六类、三层绑定”和子图+横切+出口的组成模型。Coding Agent 必须从现有 `bindingType` 枚举、实体和测试中读取其精确定义，不得在本文中重新发明六类名称。三层语义也必须与现有前后端契约对齐。

### 3.3 连边与完整度

- 连边是组成模型的结构事实；绑定节点存在不等于绑定关系完整。
- `presentEdges` 必须代表真实存在且通过校验的连边，不可仅由前端节点数量推断。
- 必需边集合 `E_req` 由后端基于场景类型/验证配置/绑定类型规则推导。
- 完整度唯一算法由后端提供，按有效连边覆盖率计算：

\[
completeness = \frac{|E_{present} \cap E_{required}|}{|E_{required}|}
\]

如果既有契约对分母、可选边、无必需边场景有更细定义，沿用现有已批准规范并补测试；前端只展示服务端返回值，不自行重算。

- 孤岛绑定：存在绑定但没有满足契约的关联边时，应显示孤岛原因；按当前需求，孤岛绑定不能通过激活门禁。
- `DRAFT` 可保留孤岛并展示修复建议；进入 `ACTIVE`/正式发布前必须通过绑定/连边校验。
- 对重复边、目标版本失效、跨租户引用、无权资产、类型不兼容、循环依赖和必需边缺失分别返回结构化 issue。

### 3.4 缺口（Gap）模型

Gap 是根据 Blueprint 与当前依赖状态计算的诊断结果，默认不作为权威资产永久写入。每个 gap 至少包含：
- `gapCode`、`severity`、`title`、`description`；
- `affectedNodeRefs`、`affectedEdgeRefs`；
- `requirementRef`/规则版本；
- `suggestedAction`（仅建议）；
- `blocking`；
- `evidenceRefs`；
- `detectedAt`。

修复任务如果需要长期跟踪，应创建到现有任务中心/runtime-task/工单底座，不能在 workspace 再建私有任务调度。

## 4. 场景生命周期与守卫

### 4.1 逻辑状态

先映射现有状态字段与枚举。以下是目标语义，不允许不经迁移评估就替换存量枚举：

`DRAFT → VALIDATING → READY → APPROVED → PUBLISHED → ACTIVE`

异常/分支：
- `VALIDATION_FAILED`：必需检查未通过；
- `NEEDS_INPUT`：关键业务口径/输入缺失；
- `PENDING_APPROVAL`：等待审批；
- `REJECTED`：审批拒绝；
- `DEPRECATED`：不再建议新建使用，但历史版本可查；
- `DISABLED`：因安全/依赖问题禁止执行。

### 4.2 转移守卫

| 操作 | 必须满足的条件 | 失败语义 |
|---|---|---|
| 保存草稿 | Schema 合法、用户有编辑权 | 400/403 |
| 验证蓝图 | 所有引用可解析；完整度和依赖校验可执行 | 返回验证报告，不改发布态 |
| 标记 READY | 所有阻断级 Gap 已解决；非阻断项可解释 | 409 + Gap 列表 |
| 提交审批 | Blueprint 版本固定，测试报告关联当前版本 | 409/422 |
| 批准 | security-engine 授权，必要时四眼原则满足 | 403/409 |
| 发布 | 审批通过、版本不可变、依赖版本固定、正式运行检查通过 | 409/422 |
| 正式运行 | 引用 PUBLISHED/ACTIVE 的版本；输入快照/口径合法；安全策略允许 | 拒绝或 NEEDS_INPUT |
| 复制到沙盘 | 创建新的 sandbox 分支/版本，明确隔离标记 | 不能直接改正式版本 |
| 停用 | 有权用户/策略允许；记录原因 | 403/409 |

`ACTIVE` 的确切含义应与现有状态一致；若当前枚举已经有 `ACTIVE`，不能另造同义状态。

## 5. 沙盘隔离

### 5.1 铁律

1. `runMode` 是独立的运行维度，至少区分 `SANDBOX` 与 `FORMAL`。
2. Sandbox 运行产物必须带可验证的 `runMode=SANDBOX`/sandbox lineage 标记。
3. 正式运行在服务端拒绝引用沙盘产物；不能依赖前端隐藏按钮。
4. 沙盘写入仅允许进入明确的沙盘存储/白名单；正式事实、已发布本体、正式知识和生产认知资产不得被沙盘直接覆盖。
5. Sandbox 产物晋升为正式资产时必须走正式提案、验证、审批、发布流程；禁止直接改标记“转正”。
6. 缺少 runMode 或 lineage 的历史产物不得默认视为正式可信数据；按兼容策略隔离并审计。

### 5.2 必测用例

- Sandbox 不产生正式业务写入；
- 正式运行引用 Sandbox 产物返回拒绝；
- Sandbox 复制不修改源 Blueprint；
- Sandbox 的假设/证据不自动写入生产 K/C 资产；
- Sandbox 运行的审计记录能追溯来源 Blueprint 版本；
- 服务端 API 直接调用也无法绕过隔离。

## 6. 场景工作台与认知引擎契约

场景工作台通过任务契约与 cognitive-engine/ai-engine 协作，不直接调用 LLM 供应商或认知存储表。

逻辑请求：

```json
{
  "requestId": "req-...",
  "scenarioId": "scenario-annual-forecast",
  "blueprintId": "bp-...",
  "blueprintVersion": 4,
  "goal": {
    "type": "BUILD_OR_RUN_SCENARIO",
    "statement": "预测 2027 年度经营结果并说明风险",
    "successCriteria": ["金额可追溯", "关键风险有证据", "必需测试通过"]
  },
  "scope": {
    "period": "2027",
    "caliberId": "caliber-01",
    "asOfTime": "..."
  },
  "runMode": "SANDBOX",
  "budgetRef": "policy-budget-ref"
}
```

实际 DTO 应沿用现有 `ApiResponse`、认证上下文、traceId、命名风格和 API 版本。不得将上述示例直接当成新增 API 的最终路径或响应包络。

跨引擎关联字段优先统一：`traceId`、`requestId`、`scenarioId`、`blueprintId`、`blueprintVersion`、`runId`/`forecastRunId`、`contextDigest`、`capabilityId`。若已有字段命名不同，建立映射而不是平行造字段。

## 7. 业务年度经营预测的场景工作台要求

首期业务路径：
1. 业务语言创建“2027 年度经营预测”；
2. 选择组织/项目/期间/批准口径；
3. 检查数据完整性和质量；
4. 核验本体关系、指标定义、K 层历史画像/假设版本；
5. 创建确定性预测运行并冻结输入快照；
6. 展示企业/部门/项目层级利润、收入成本瀑布、覆盖率和最大风险；
7. 支持下钻到合同、期间、环节、公式、源记录与证据；
8. 复制“验收延期”等情景，只变更选定项目/期间的假设；
9. 创建有负责人、截止日、预期影响、控制指标和审批人的经营动作；
10. 回灌实际，比较预测/实际/误差并创建复审候选。

每个正式金额必须具备 `forecastRunId + caliberId + asOfTime + inputSnapshotRef + formulaRef/version + evidenceRefs` 六要素。缺少任一必需项不得显示为已验证正式结果。

## 8. API 设计要求

### 8.1 先盘点，再决定新增

Coding Agent 必须查找当前 workspace Controller、OpenAPI、BFF 代理与已有接口。优先复用已有端点；新增接口遵守：
- 唯一 `operationId`；
- 统一响应包络与错误码；
- 默认认证，匿名端点必须有明确登记；
- 参数/响应 Schema 与前端契约一致；
- 权限在服务端检查；
- 写操作幂等或有并发控制；
- 分页、超时、错误语义明确；
- 通过 OpenAPI lint 和契约测试。

### 8.2 目标 API 语义清单（路径以现有 OpenAPI 为准）

- 查询场景列表/详情；
- 创建/更新草稿；
- 查询 Blueprint 版本与变更记录；
- 查询绑定、依赖图和完整度；
- 执行 Blueprint Validate；
- 查询 Gap/验证报告；
- 创建/查询 Sandbox Run；
- 提交审批、审批、发布；
- 查询运行结果与 trace；
- 查询场景关联的认知 E1-E4 面板；
- 创建/查询 Outcome Evaluation 或更新候选。

不要把这些语义机械地全部新增成新端点。已有等价端点应优先保留并补契约。

## 9. 安全、审计与可观测性

- 所有读写均使用现有身份、租户、角色、密级、RLS/CLS 和策略上下文。
- 任何写操作必须由 security-engine/PDP 授权；策略服务不可用时默认拒绝。
- 场景蓝图的保存、验证、提交审批、批准、发布、运行、复制沙盘、停用均应留下可追溯审计事件。
- 日志不记录凭据、完整敏感业务数据或不必要的 prompt 内容；记录稳定 ID、版本、traceId、错误分类和脱敏后的诊断信息。
- 运行失败必须标明失败阶段：输入检查、绑定检查、依赖检查、认知构建、计划验证、执行、结果验证、审批或发布。

## 10. 前端实现约束

- 使用项目当前 React/TypeScript/路由/状态管理模式；不得引入第二套前端框架。
- 所有新文案通过现有 i18n（`useLanguage`/当前 namespace 机制）；禁止硬编码中文。
- 遵循现有四主题 token，禁止用硬编码白/黑背景色替代主题系统。
- 图标使用现有 `lucide-react`。
- API 调用复用统一 API client/auth helper；不重复解析 JWT，不自建 authHeaders。
- 长任务复用 `runtime-task` 和 `AsyncTaskCenterView`/现有 task-center 服务。
- 认知 E1-E4 右栏沿用既有 `ScenarioCognitionPanel`、`HypothesisList`、`BeliefList`（如果现有实现名称不同，以实测为准），避免重复实现。
- 每个主要组件必须有加载、空、错误、403、503、刷新和必要的取消状态。
- 页面不计算完整度、财务金额、置信概率或权限。

## 11. 验收用例

### SW-01 业务语言入口
用户从场景首页以业务语言创建/进入年度经营预测，不需要先理解 Goal/Causal 等技术术语。

### SW-02 完整度单源
给定相同 Blueprint，前端展示完整度必须与后端完整度接口一致；更改边后完整度由服务端重新计算。

### SW-03 孤岛阻断
存在孤岛绑定时可以保存在草稿并显示修复原因；进入正式可发布状态时被阻断。

### SW-04 E1-E4 语义
认知服务返回空集合、404、503 时，前端分别显示空态、不存在、依赖不可用；不能互相折叠。

### SW-05 沙盘隔离
Sandbox 产物不能被 Formal Run 引用，任何直调 API 的绕过尝试都失败并审计。

### SW-06 Blueprint 版本
发布版本不可被原地修改；编辑已发布场景必须创建新草稿/新版本；历史运行仍关联原版本。

### SW-07 安全失败关闭
security-engine/PDP 不可用时，发布、审批和正式写操作均拒绝。

### SW-08 预测金额可追溯
每个正式金额可定位到运行 ID、口径、截至时间、输入快照、公式版本和证据；LLM 不产生金额。

### SW-09 运行与取消
长任务进入统一任务中心，显示进度/状态/失败原因；取消遵守 runtime-task 契约。

### SW-10 无伪成功
依赖关闭或 API 失败时不显示静态成功数据；记录 traceId 并展示可操作错误。
