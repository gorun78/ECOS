### 4.2 风险应对措施

#### R1 (cognitive 重写延期) — **最高优先级应对**
**应对**：
1. Phase 3 内做 PMO-32 (决策五元组) + PMO-35 (SpEL 可解释) 高优先 (合计 8 人日, 不浪费)
2. Phase 4 内做 PMO-33 (跨引擎编排) + PMO-34 (非结构化解析) + PMO-36 (Pipeline 4 件) 14 人日
3. **缓冲周 (Phase 3 末) 专门做 cognitive 的 CausalReasoner 重写** (CausalReasonerServiceImpl 726 行重写)
4. **新增后端 DevOps 支援 (1 人)**:
   - Phase 3 第 1 周支援 Causal 重写
   - Phase 4 第 1 周支援 Skeleton
5. **降级方案**: 若 Phase 4 仍未出 Causal ≥3 层，**Phase 5 联调降级到 ≥2 层** (产品理解报告 P9 §K4 已说明)

#### R2 (前端大文件拆分)
**应对**：
1. 拆前先写 E2E (ecos-tests) 锁定关键行为
2. 拆不改业务逻辑 (TDD)
3. 每周 10 次 git commit + 每次回编译验证
4. **新增 FE 支援 (1 人)**:
   - 09 月支援 AiGuardrailsView 拆分
   - 10 月支援 AIPCopilotDrawer i18n

#### R3 (多租户 RLS 集成)
**应对**：
1. 50 越权 .mjs 写在 Phase 0 末 (验证场景边界)
2. P1-T4 单独 3 天 + 1 天 buffer
3. 集成测试 (Testcontainers) 含 PG 多 Schema 验证
4. 若 security 不可用 → **立即回滚** + **默认 DENY 仍生效**

#### R4 (LLM 限流/降级)
**应对**：
1. llm-gateway 集成 3 Provider (DeepSeek + OpenAI + Azure)
2. 调用计账 (Counter), 限流时自动切换 + 友好错误提示
3. 72h Soak 模拟 3 Provider 轮流 (每个 20h)

#### R5 (PG/Neo4j 资源)
**应对**：
1. **09 末 (Phase 2 内) 向 DevOps 申请 Soak 3 集群 (1 周)**
2. 集群角色隔离:
   - PG: 4C/16GB / 256GB SSD (primary + 2 replica)
   - Neo4j: 4C/16GB / 256GB SSD
   - MinIO+OPA+FE+BE: 4C/8GB 各 3
3. Soak 期间资源监控 (Prometheus + Grafana)
4. 资源不足时**降低并发** (≤50 → 30 → 10) 但 **不降 72h 时长**

#### R6 (单测覆盖率 9% → 60%)
**应对**：
1. 60% 整库为底线 (root pom jacoco)，80% 关键模块 (sysman/security/data/kb/onto)
2. **测试人材 1 人专职 Phase 3-5**
3. 代码生成 (Mockito + Testcontainers 模板) 提效
4. 单测代码 from 后端 T7 开始持续补 (每周 4 天)
5. **禁止强制 100%** — 先能跑再说

#### R7 (P99 < 500ms)
**应对**：
1. Phase 4 末 (Oct 17) 跑 Profiler 抓热点 (JFR + 火焰图)
2. N+1 查询优先 (data-engine Query 链路为主打击对象)
3. 缓存 (Caffeine L2 + Redis L3) 重点打 hot path
4. 若达不成 → 降级到 P99 < 1s (不阻塞 Phase 5 但增加优化项)

#### R10 (72h Soak 内存泄漏)
**应对**：
1. 每周 1 次 24h Soak (Phase 4 末 + Phase 5 前)
2. jmap dump 自动化 (heap > 80% 自动 dump)
3. 泄漏点 (Cache / Neo4j session / SSE 连接池) 专门检查
4. Soak 失败 → 不交付 Phase 5, 回滚

#### R12 (security 降级放行 — 灾难)
**应对**：
1. **默认 DENY 是铁律** — 代码层面 throw DefaultDenyException (硬性)
2. 任何人 **不允许** 写 "security-engine 不可用 → allow"
3. 72h Soak **必含** security-engine down 30 min 故障演练
4. 故障演练期间所有查询 100% 403 → business 回归证明
5. 若发现 allow 代码 → **立即阻断** + 全量代码扫描
