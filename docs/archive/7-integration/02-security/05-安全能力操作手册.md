# 05-安全能力操作手册

> 来源：肖国荣 | 日期：2026-08-24
> 用途：给所有引擎（data/ontology/kb/cognitive/ai）提供 security-engine 安全能力的接入方法
> 强制依据：ARCHITECTURE-RULES.md 2.4 安全接入铁律（违反 = 验收失败）

## 一、总则（三条原则）

1. **所有安全检查统一走 security-engine REST API**，各引擎不在自身代码重复实现权限/脱敏/审计逻辑
2. **审计日志集中写 security-engine**，各引擎不维护自己的审计表
3. **安全引擎不可用时默认 DENY**（宁可误拒不可误放），不得降级为放行

## 二、安全能力清单与调用格式

> 端点均双前缀可用：`/api/security/*` 和 `/api/v1/security/*`（Gateway 路由重写兼容）

### 2.1 认证 JWT（前端专用）

| 项 | 值 |
|----|----|
| 端点 | `POST /api/v1/auth/login` |
| 调用方 | 前端（其他引擎不直接调，Gateway JwtFilter 统一拦截验证） |
| 用途 | 登录获取 token，后续请求带 `Authorization: Bearer <token>` |

### 2.2 ABAC 策略评估（操作授权）

| 项 | 值 |
|----|----|
| 端点 | `POST /api/v1/security/policy-engine/evaluate` |
| 调用时机 | 操作类能力执行前：Agent 工具调用、Function 执行、知识抽取 |
| 用途 | OPA 真实裁决该操作是否允许 |

**请求**：
```json
{
  "policy": "agent-tool-call",
  "input": {
    "userId": "u_001",
    "role": "analyst",
    "action": "query_db",
    "resource": "td_customer"
  }
}
```

**响应**：
```json
{
  "code": 0,
  "data": { "allow": true, "policy": "agent-tool-call", "reason": "role allowed" }
}
```

### 2.3 RLS 行级安全（查询前注入 WHERE）

| 项 | 值 |
|----|----|
| 端点 | `POST /api/security/rls/apply` |
| 调用时机 | data-engine 执行查询 SQL 前 |
| 用途 | 返回当前用户可见范围的行级过滤条件，拼入 WHERE |

**请求**：
```json
{ "tableName": "ecos_order", "userId": "u_001" }
```

**响应**：
```json
{
  "code": 0,
  "data": {
    "rlsCondition": "tenant_id = ? AND dept_id IN (?, ?)",
    "params": ["t_001", "d_001", "d_002"]
  }
}
```

**使用**：data-engine 把 `rlsCondition` 拼到原 SQL 的 WHERE，`params` 追加到参数列表。**无 RLS 策略时返回空条件（放行），有策略时必须注入，不得绕过。**

### 2.4 CLS 列级安全（查询后过滤敏感列）

| 项 | 值 |
|----|----|
| 端点 | `POST /api/security/cls/columns` |
| 调用时机 | 查询结果返回前端前 |
| 用途 | 返回当前用户可见的列清单，过滤掉无权看的敏感列 |

**请求**：
```json
{ "tableName": "ecos_order", "userId": "u_001" }
```

**响应**：
```json
{
  "code": 0,
  "data": { "visibleColumns": ["id", "order_no", "amount", "created_at"] }
}
```

**使用**：data-engine 返回结果时，只返回 `visibleColumns` 中的列，`customer_phone` 等敏感列被过滤。

### 2.5 数据脱敏（敏感字段返回前）

| 项 | 值 |
|----|----|
| 端点 | `POST /api/security/mask` |
| 调用时机 | 敏感字段（手机/邮箱/身份证/金额/密码）返回前端前 |
| maskType | `SHA256` `MD5` `PHONE` `EMAIL` `ID_CARD` `AMOUNT` |

**请求**：
```json
{ "value": "13812345678", "maskType": "PHONE" }
```

**响应**：
```json
{
  "code": 0,
  "data": { "original": "13812345678", "masked": "138****5678", "maskType": "PHONE" }
}
```

### 2.6 审计日志（查询 + 写入）

| 项 | 值 |
|----|----|
| 查询 | `GET /api/security/audit-logs`（`?userId=&action=&from=&to=`） |
| 写入 | `POST /api/v1/security/audit/log`（Phase 2 补实现） |
| 调用时机 | 所有写操作完成后**异步**写入，不阻塞主流程 |

**写入请求**：
```json
{
  "userId": "u_001",
  "action": "CREATE_ORDER",
  "resource": "ecos_order/12345",
  "result": "SUCCESS",
  "detail": "{\"amount\": 1000}"
}
```

### 2.7 数据权限策略（DataPermissionController）

| 项 | 值 |
|----|----|
| 用途 | 数据权限策略 CRUD（定义谁可访问哪些数据） |
| 调用方 | 前端安全中心管理页 |

### 2.8 token 黑名单（强制下线）

| 项 | 值 |
|----|----|
| 机制 | 强制下线时 token 进 BlacklistStore（standard=Db / enterprise=Redis），JwtFilter 检查黑名单 |
| 调用方 | 前端"强制下线"按钮 → 后端 AuthController |

## 三、各引擎接入指南

| 引擎 | 接入时机 | 接入端点 | 接入 Phase |
|------|---------|---------|:---:|
| data-engine | 查询前 RLS / 查询后 CLS / 返回前 mask / 写操作 audit | rls/apply + cls/columns + mask + audit/log | Phase 3 |
| ontology-engine | Function 执行前 ABAC 授权 | policy-engine/evaluate | Phase 4 |
| kb-engine | 知识抽取前 ABAC 授权 + 抽取结果 audit | policy-engine/evaluate + audit/log | Phase 5 |
| cognitive-engine | 诊断/推理前 ABAC 授权 | policy-engine/evaluate | Phase 6 |
| ai-engine | Agent 工具调用前 ABAC 授权 + 工具执行 audit | policy-engine/evaluate + audit/log | Phase 7 |

## 四、调用规范（所有引擎必须遵守）

| 规范 | 值 |
|------|----|
| 请求超时 | 5 秒（security-engine 应快速响应） |
| 失败处理 | 默认 DENY，不降级为放行 |
| 审计写入 | 异步，不阻塞主流程 |
| 认证 | 所有 `/api/security/*` 端点需 JWT Bearer Token |

## 五、快速示例（data-engine 查询全链路）

```bash
# 1. 查询前：RLS 注入行级过滤
RLS=$(curl -s -X POST http://localhost:8080/api/security/rls/apply \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"tableName":"ecos_order","userId":"u_001"}')

# 2. 查询后：CLS 过滤敏感列
CLS=$(curl -s -X POST http://localhost:8080/api/security/cls/columns \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"tableName":"ecos_order","userId":"u_001"}')

# 3. 敏感字段脱敏
MASK=$(curl -s -X POST http://localhost:8080/api/security/mask \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"value":"13812345678","maskType":"PHONE"}')

# 4. 写操作后异步审计
curl -s -X POST http://localhost:8080/api/v1/security/audit/log \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"userId":"u_001","action":"CREATE_ORDER","resource":"ecos_order/12345","result":"SUCCESS"}'
```

> **注意**：请求/响应字段以 Controller 实际实现为准，PMO 测试时逐条验证准确性，如有出入修正本手册。
