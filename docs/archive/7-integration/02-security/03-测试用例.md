# 02-security 测试用例

> 来源：肖国荣 | 日期：2026-08-24
> 依据：01-需求文档.md + 02-测试方案.md
> 优先级：P0=裁决正确性 / P1=核心能力 / P2=UI / P3=收尾

## 一、RLS 行级安全（P0）

| 编号 | 用例 | 步骤 | 预期 |
|------|------|------|------|
| TC-RLS-01 | 策略 CRUD | RlsController POST/GET/PUT policies | CRUD 全通，策略表落库 |
| TC-RLS-02 | apply | POST /api/security/rls/apply {tableName, userId} | 返回 rlsCondition（拼出 WHERE）+ params |
| TC-RLS-03 | 多租户隔离 | 两个不同 tenant 用户 apply 同表 | 返回**不同** WHERE 条件（各自 tenant_id） |

## 二、CLS 列级安全（P0）

| 编号 | 用例 | 步骤 | 预期 |
|------|------|------|------|
| TC-CLS-01 | 策略 CRUD | ClsController policies CRUD | 全通，落库 |
| TC-CLS-02 | columns | POST /api/security/cls/columns {tableName, userId} | 返回 visibleColumns（敏感列过滤） |
| TC-CLS-03 | 角色差异 | admin vs 普通用户查同表 | admin 全列，普通用户敏感列被过滤 |

## 三、ABAC 策略（P0）

| 编号 | 用例 | 步骤 | 预期 |
|------|------|------|------|
| TC-ABAC-01 | OPA evaluate | POST /api/v1/security/policy-engine/evaluate | 真实 OPA 裁决，返回 allow/deny |
| TC-ABAC-02 | 策略 CRUD | AbacController + PolicyEngineController policies | CRUD 全通 |
| TC-ABAC-03 | 路径对齐 | `/api/v1/policy-engine` 和 `/api/v1/security/policy-engine` 同端点 | 双前缀都 200 |

## 四、脱敏（P1）

| 编号 | 用例 | 步骤 | 预期 |
|------|------|------|------|
| TC-MASK-01 | SHA256 | mask 对密码字段 | SHA256 哈希 |
| TC-MASK-02 | PHONE | mask 手机号 13812345678 | 138****5678 |
| TC-MASK-03 | EMAIL | mask 邮箱 test@example.com | t***@example.com |
| TC-MASK-04 | ID_CARD | mask 身份证 | 前6后4保留，中间脱敏 |
| TC-MASK-05 | AMOUNT | mask 金额 | 金额脱敏 |
| TC-MASK-06 | 联动 | 改脱敏规则 → 查 data-engine | PipelineEvent DATA_MASKING_RULES_CHANGED 触发，缓存刷新 |

## 五、审计（P0 写入 + P1 查询）

| 编号 | 用例 | 步骤 | 预期 |
|------|------|------|------|
| TC-AUDIT-01 | 查询 | GET /api/security/audit-logs + /audit | 返回日志列表 |
| TC-AUDIT-02 | 写入 | POST /api/v1/security/audit/log（**先补实现**） | 异步写 ecos_audit_log，不阻塞调用方，随后可查到 |

## 六、会话管理 / token 踢出（P1）

| 编号 | 用例 | 步骤 | 预期 |
|------|------|------|------|
| TC-TOKEN-01 | 强制下线 | 管理员强制下线某用户 → 该用户再请求 | token 进黑名单，请求被拒（401/403） |

## 七、前端 SecurityCenter（P2）

| 编号 | 用例 | 步骤 | 预期 |
|------|------|------|------|
| TC-FE-01 | PreventTab 事前 | ABAC/RLS/CLS/脱敏策略管理 | 页面可用，CRUD 走通 |
| TC-FE-02 | DetectTab 事中 | 策略配置（1173 行） | 无"建设中"占位，配置可操作 |
| TC-FE-03 | AuditTab 事后 | 审计时间线+筛选 | 日志展示 + 筛选可用 |
| TC-FE-04 | GuardrailsView | /guardrails 页面 | 护栏管理可用 |

## 八、端点全覆盖 + 死代码清理（P1 + P3）

| 编号 | 用例 | 步骤 | 预期 |
|------|------|------|------|
| TC-API-01~13 | 13 Controller 端点 | 读 @RequestMapping → curl 每 Controller | 全非 500/404 |
| TC-CLEAN-01 | 死代码清理 | grep 确认 datapermission 旧 RLS/CLS impl 零引用 | `git rm` 清理，编译通过 |

## 九、安全管控配置（P0，前后端协同）

| 编号 | 用例 | 步骤 | 预期 |
|------|------|------|------|
| TC-CLEAR-01 | 准入等级拦截 | 低等级用户（L1）访问 L3 接口（/api/v1/system/） | 403 拒绝 + 审计 clearance_level_insufficient |
| TC-CLEAR-02 | 准入等级优先级 | 用户级 L4 覆盖角色级 L1 | User > Role > 全局默认，用户级生效 |
| TC-WS-01 | 工作站绑定校验 | 用户绑定工作站 A，从工作站 B 登录 | 拒绝 + 审计 workstation_mismatch |
| TC-AUDITMODE-01 | 审计力度分级 | full 模式用户执行操作 | DB + 哈希链双写；basic 只记关键操作 |
| TC-SANDBOX-01 | 高危指令沙盒审查 | sandbox_mandatory 用户 Agent 执行 DELETE | 沙盒审查拦截 + 审计，不放行 |

## 用例统计

- P0：14 个（RLS 3 + CLS 3 + ABAC 3 + 安全管控 5）
- P1：13 个（脱敏 6 + 审计 2 + token 1 + 端点 13 合 1 组）
- P2：4 个（前端）
- P3：1 个（死代码）
- **总计约 32 个用例**

## 执行顺序

P0 裁决正确性（RLS/CLS/ABAC）→ P1 脱敏/审计/token/端点 → P2 前端 → P3 死代码清理。
**审计写入（TC-AUDIT-02）是唯一补实现项，需 BE 先补端点再测**；死代码清理放最后（避免影响测试环境）。
