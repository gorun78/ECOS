## 一、模块定位

security-engine = 横切安全（护），认证/授权/审计/脱敏/ABAC/RLS/CLS。所有引擎的数据访问都要过它的权限裁决。**安全引擎不是独立业务，是横切所有模块的能力**——Phase 2 排第二（紧跟 sysman 地基）。

## 一·五、需求合理性审计标准

每个需求进入测试前，过 3 维度审计：

| 维度 | 判断问题 | 标准 |
|------|---------|------|
| 合理性 | 这个需求真的需要吗？ | 有消费者/业务场景/符合产品定位；无消费者或历史过度设计 → 剔除 |
| 可闭环 | 能验证吗？ | 有明确验收标准 + 有表/端点/前端入口支撑；缺闭环条件 → 补或延后 |
| 优先级 | 现在做还是以后做？ | P0 阻塞 → 现在；纯体验打磨 → 延后不阻塞本轮 |

**审计结论三选一**：✅ 进入测试 / ⚠️ 进入测试+修复（缺失但需求合理）/ ❌ 剔除或延后（不合理或非阻塞）

### 4.9 安全管控配置落地（4 项，前后端协同实现）

> 数据模型已建好（V24 `td_user_security_profile`/`td_role_security_profile` 表 + SecurityProfile 实体字段齐全 + 种子数据 R001-R003）。本需求是**管控逻辑落地**——让 4 个配置真正起作用，而非只有 CRUD。

#### 4.9.1 安全准入等级（✅ 已实现，联调验证）

- **管控内容**：用户/角色有准入等级（L0公开-L4绝密），接口用 `@MinimumClearance` 标注最低等级，`ClearanceInterceptor` 拦截校验——用户等级 < 接口等级 → 403 拒绝 + 审计
- **优先级**：User级 > Role级 > 全局默认
- **路径前缀默认**：`/api/v1/security/`→L2、`/api/v1/system/`→L3、其余→L1
- **现状**：✅ 已完整实现（ClearanceInterceptor + @MinimumClearance）
- **联调**：验证拦截生效（低等级用户访问高等级接口被 403）

#### 4.9.2 绑定物理工作站（⚠️ 补登录校验）

- **管控内容**：`linked_workstation` 存 MAC/IP/主机名，用户只能在绑定工作站登录，异地登录 → 拒绝 + 审计
- **后端实现**：登录成功后（AuthController）校验客户端 IP/MAC vs linked_workstation，不匹配 → 拒绝 + 审计记录 `workstation_mismatch`
- **前端实现**：UserEditModal/SecurityConfigPanel 编辑工作站绑定，自动获取展示当前客户端 IP/MAC 供绑定
- **现状**：⚠️ CRUD 有（SecurityProfileController），登录校验缺失

#### 4.9.3 双写审计力度（⚠️ 补分级双写）

- **管控内容**：`audit_mode` 三级——basic（只记关键操作：登录/删除/权限变更）、detailed（+请求参数/响应摘要）、full（DB + `AuditHashChainService` 哈希链双写，防篡改）
- **后端实现**：AuditAspect/AuditLogService 根据用户 audit_mode 决定记录粒度；full 时同时写哈希链
- **前端实现**：SecurityConfigPanel 编辑审计力度 + 展示哈希链验证状态
- **现状**：⚠️ CRUD 有，分级双写缺失（AuditHashChainService 已存在但未与 audit_mode 联动）

#### 4.9.4 高危指令沙盒审查（⚠️ 补审查逻辑）

- **管控内容**：`sandbox_mandatory=true` 的用户/角色，其 Agent 执行高危指令前，强制沙盒模拟审查，确认无风险才放行
- **高危指令清单**：删除数据（DELETE/DROP）、批量修改（批量 UPDATE）、系统命令（exec/rm/mv）、DDL、越权 SQL
- **后端实现**：Agent 工具调用前（ai-engine ToolExecutorService），检查用户 sandbox_mandatory，命中高危清单 → 调 SecuritySandboxService 审查（模拟执行 + 风险判定），高风险 → 拒绝 + 审计
- **前端实现**：SecurityConfigPanel 开关 + AgentTestConsole 展示沙盒审查拦截记录
- **现状**：⚠️ CRUD 有，审查逻辑缺失（SecuritySandboxService 目前是脱敏/过滤仿真，无高危指令审查）
