# Phase 3 差距分析：g（数据工作台轻量版）+ cheng（知识引擎重点补）

> 肖国荣 / 2026-08-07 | 基线: Phase 1+2 已完成，数据工作台骨架完整，知识工作台前端丰富但认知引擎核心空

---

## 一、总体判断

**数据工作台（Part A）**：前端骨架远超预期——12个Tab + Pipeline可视化编辑器 + 数据血缘DAG + 质量仪表盘，但存在三个核心问题：
1. **体重超标**：DataWorkbenchLayout 3791行，6个文件>800行
2. **硬编码中文泛滥**：DataWorkbenchLayout 418行中文硬编码，全局约2000+行未i18n化
3. **后端断层**：血缘引擎返回空、DQ无调度执行、Pipeline同步等

**知识工作台（Part B）**：前端12个Tab丰富，但**认知引擎是空壳**——因果推理返回空列表、情景模拟返回假数据。这是Phase 3最核心的差距。

## 七、决策点（已确认 2026-08-07）

1. **数据源类型**：✅ 保留6种DB（Oracle/MySQL/PG/SQLServer/达梦/金仓），不砍。向导式接入需适配所有类型。
2. **血缘视图**：✅ 保留DataLineage(GraphCanvas方案223行)，删除LineageMapView(1233行)。后端血缘统一走JSqlParser。
3. **KnowledgeView合并**：✅ pages/KnowledgeView.tsx(134行)作统一Shell入口，aiworkbench/KnowledgeView.tsx(2073行)拆分为独立Tab并入Shell。
4. **认知引擎方案**：✅ 混合方案（KG+LLM融合），认知引擎定位为**项目场景工作台支撑引擎**——提供因果推理/情景推演/混合推理三大能力给场景落地。kb-engine只管知识库生命周期（存储/检索/抽取/同步），不越界做推理。
5. **范围**：✅ 不接受裁剪，完整实现全部差距项。

### 引擎职责边界（2026-08-07明确）

```
kb-engine（知识库生命周期）          cognitive-engine（场景推理）
├─ 知识抽取/入库                     ├─ 因果链推理（≥3层）
├─ KG存储/检索/同步                  ├─ 情景推演（What-if）
├─ 向量索引/RAG检索                  ├─ 混合推理（RAG+KG+规则）
├─ 规则CRUD+版本管理                 ├─ 诊断报告生成
├─ 实体链接                          ├─ 根因定位+建议
└─ 合规规则图谱关联                  └─ 项目场景工作台API
```
