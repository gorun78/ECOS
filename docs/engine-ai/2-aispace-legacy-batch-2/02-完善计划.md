# ECOS 产品化完善方案：Phase 2 — AI工作台完善计划

> 来源: `01-差距分析-v2.md` | 参照: Palantir AIP 五层架构 + OAG 8步闭环 | 总工期: 12-14周

---

## 〇、总体策略

四步走：
1. **先补缺**（ai-engine企业级能力缺口）→ 可观测/护栏/会话压缩/容错
2. **再治标**（前端地基：i18n+拆分+UX）→ 让代码可维护
3. **后补核**（Ontology ActionType + OAG闭环）→ 让AI"懂业务"
4. **终亮剑**（Agent平台+评估+画布）→ 交付完整AI工作台

## Phase 2-0：ai-engine企业级补齐（2周）

> 来源: ai-engine审计 | 综合评分: 3.20/5 (加权) | 目标: 4.0/5

### 审计结论

ai-engine核心引擎扎实（80文件/36Controller/25Service），核心路径可用。但3项P0阻塞生产上线：

| 维度 | 评分 | P0发现 |
|------|:--:|------|
| Tool系统 | **4.5/5** | ✅ 8内置工具+3执行模式+Schema校验完整 |
| 配置体系 | **4.5/5** | ✅ L1→L2→L3三层覆盖设计精良 |
| Agent Loop | **4.0/5** | ⚠️ 5级解析回退优秀，但缺整体超时+真流式 |
| 会话管理 | **3.5/5** | 🔴 无上下文压缩，长会话OOM风险 |
| Agent模板 | **3.5/5** | ⚠️ 6模板质量高但toolWhitelist未校验 |
| 多Agent | **3.0/5** | ⚠️ 单层委托可用，缺并行编排 |
| 模型路由 | **3.0/5** | 🔴 仅1个Provider(DeepSeek)，无故障转移 |
| 错误处理 | **2.5/5** | 🔴 缺异常分类体系+指数退避 |
| 安全护栏 | **2.0/5** | 🔴 **代码写了但未接入主流程！** AgentLoopService.run()全程无Guardrails调用 |
| 可观测性 | **1.5/5** | 🔴 零trace/metric/alert，仅日志 |
