## §1 项目概述

### 1.1 定位

ECOS（Enterprise Cognitive Operating System）企业认知操作系统，核心链路：数据治理 → 知识图谱 → LLM Agent 部署。

### 1.2 架构

**单体 fat-JAR 架构** — `gateway` 唯一 Spring Boot 入口（端口 8080），非微服务。

```
前端 (:3000) → Gateway (:8080) → 服务层(四转化) → 引擎层(五对象+一护)
```

**三层模型**：

| 层 | 命名 | 成员 |
|----|------|------|
| 引擎层（五对象·五行） | 土·D / 金·I / 水·K / 木·C / 火·W | data / ontology / kb / cognitive / ai |
| 服务层（四转化·格致诚明） | ge(D→I) / zhi(I→K) / cheng(K→C) / ming(K→W) | 4 个服务模块 |
| 横切层（护+器） | security(护) / runtime(器) | security-engine + runtime-access/task/monitor/llm-gateway |

### 1.3 技术栈

| 侧 | 技术 | 版本 |
|----|------|------|
| 前端 | React / TypeScript / Vite / Tailwind | 19 / 5.8 / 6 / 4 |
| 后端 | Java / Spring Boot / MyBatis / Maven | 17 / 3.2.2 / 3.0.3 / 3.9.11 |
| 数据库 | PostgreSQL / Neo4j / MinIO / OPA | 16 / 5.26 / 最新 / 0.63 |
| 包管理 | pnpm (前端) / Maven (后端) | — |

### 1.4 三版本发布

| 版本 | Maven Profile | 数据库 | 适用 |

### 4.2 API 路径一致性 — **P1**

前端存在**三套路径体系**并存，存在维护混淆风险：

| 路径体系 | 前缀 | 使用者 | 说明 |
|:--------:|:-----:|:------:|------|
| A | `/api/v1/ecos/*` | `ontologyApi.ts` 本体 CRUD (L65) | `const BASE = "/api/v1/ecos"` |
| B | `/api/v1/ontology/*` | `ontologyApi.ts` mapping/export/data/proposal (L419-768) | 多处独立常量 |
| C | `/api/v1/engine/ontology/*` | `ontologyApi.ts` 引擎端点 (L257) | `ENGINE_BASE` |

根因分析:

1. **路径分裂**: `ontologyApi.ts` 同时使用 `/api/v1/ecos/` 和 `/api/v1/ontology/` 两个前缀，指向不同后端 Controller。语义上 `ecos` 和 `ontology` 指向同一业务域，路径不统一易维护混淆。

2. **EngineMonitor URL 拼接**（`EngineMonitor.tsx` L120/135/150）:
   ```typescript
   const data = await apiFetch(`/api/v1/engine/${engine}/health`);
   // engine = 'security'|'data'|'ontology'|'cognitive'|'knowledge'|'ai'
   ```
   这里拼接逻辑**正确** — `engine` prop 是受限 union type，拼出合法路径。**无 bug**。

3. **`configPath` 覆盖风险**（L53）:
   ```typescript
   data: { configPath: '/api/v1/engine/data/settings' }
   ```
   `data` 引擎有单独 `configPath`，其他引擎走 `${engine}/config`。当前代码正确，但缺少防御性校验。
