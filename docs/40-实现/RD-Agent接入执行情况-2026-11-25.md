## 一、逐节对照

### §5.1 数据模型 — 完整落地 ✅

- `ecos_scenario_run` 八列全部在真库：`run_level` / `parent_run_id` / `sota_run_id` /
  `branch_key` / `loop_index` / `experiment_spec` / `budget` / `stop_reason`（V365）
- `ecos_scenario_run_artifact` 产物引用表（`storage_ref` / `digest` / `size_bytes`）
- 遵守「不新建 `scenario_experiment` 平行表」：谱系长在运行表上

### §5.2 API 六端点 — 六项全在，两处偏离 ⚠️

| 端点 | 状态 |
|---|---|
| `POST .../research-runs/prepare` | ✅ |
| `POST .../research-runs` | ✅ 同步；`?async=true` 走 runtime-task（异步为默认之外的可选） |
| `GET .../research-runs` | ✅ |
| `GET .../research-runs/{runId}` | ✅ 含产物引用 |
| `GET .../research-runs/{a}/compare/{b}` | ✅ 已补树关系（见 §5.2 树对比） |
| `POST /research-runs/{runId}/approve` | ✅ **但未走 WAgent Candidate 通道** |

**偏离 1（架构）**：报告要求审批「走现有 WAgent Candidate 咽喉」，实际实现是独立的
`ecos_scenario_run_approval` 表 + 自有语义。代码注释引用了 §5.5「候选唯一通道」，
但**实际未接入那条通道**。

**偏离 2（树对比，已修）**：报告要求「升级现有两两对比为树对比」。
首版只做逐字段对比；2026-11-25 补 `tree` 段（relation / commonAncestor / 两侧深度），
以父链回溯判定，不靠 `loop_index` 猜。

### §5.3 前端 — 四项达成 ✅

研究模式面板（默认折叠、不扰动原路径）、谱系树缩进 + SOTA 高亮、审批入口 + 凭据输入、
不新增顶级路由（复用 `#/workbench/:scenarioId`）。

### §5.4 沙盒七项约束 — **基本未实现** ❌（最大缺口）

| 报告要求 | 实际 |
|---|---|
| 独立容器、非 root、只读根文件系统 | 无 |
| 出口白名单、禁连生产库 | 无 |
| CPU/内存/时长配额、超时强杀 | 无 |
| 只读快照 + 租户标记 + sha256 | 无 |
| 研究专用短期令牌 | 无 |
| 产物落 MinIO、DB 存引用 | 表已建，**无写入路径** |
| 全链路审计留痕 | 无 |

实际实现的只是**一个 HTTP 客户端壳**：配置 `ecos.research.sandbox.base-url` 即
POST `{baseUrl}/research/rounds`。隔离、配额、凭据、快照、审计全无。
报告把 R2「沙盒任意代码执行」列为**极高风险**，此块未做即风险敞口完全存在。

### §4 执行序列 — implement 与 sandbox_run 缺失 ❌

报告五步 `hypothesize → implement → sandbox_run → evaluate → record`：
已实现 **hypothesize / evaluate / record** 三步；`implement`（沙盒内生成代码）与
`sandbox_run`（真隔离执行）**完全没有**。只读执行器仅做「查绑定 / 查知识命中 / 聚合读数」。

**这意味着 RD-Agent 的核心能力（代码进化）未接入**，当前是只读研究循环。

### §5.5 候选治理 — 部分达成 ⚠️

业务真值优先（显式 `degraded=true`）✅；失败闭合（不返回 200 空结论）✅；
不自动写蓝图/指标 ✅；「候选唯一通道」未接入 WAgent ❌（同 §5.2 偏离 1）。

### §6 Phase 0 清单 — 0/8 ❌

| 条目 | 状态 |
|---|---|
| Context Pack 导出 + 列白名单 + 脱敏 + sha256 | 未做 |
| Linux 容器 + Python 3.10/3.11 + rdagent 锁版本 | 未做 |
| LLM DeepSeek chat + embedding 密钥注入 | 未做 |
| L1/L2 结果作基线对照 | 未做 |
| 固定 `loop_n=5` 实跑 | 未做（活体验证用 maxLoops=2~3） |
| 失败注入（代码错/超时/缺列） | 未做 |
| 谱系 + SOTA 报告 + 蓝图草案 | 未做 |
| 三方评审（业务 owner + 架构 + 安全） | 未做 |

> 澄清：`ecos_backend/scripts/verify-research-lineage.mjs` 是**谱系结构校验器**
> （7 条不变量、不连库），**不是** Phase 0 要求的**数据快照验证**，两者不可混为一谈。

### §8 八条红线 — 七条守住，一条打折

守住：①不在 JVM/宿主机执行代码；③不自动写蓝图状态机；⑤不新增容器（仍 9）与模块；
⑦不引第二套运行存储；⑧L1/L2 零行为变化（`run_level` 缺省 NULL，不指 L3）。

打折：②「不直连生产库」——**没有沙盒即无从谈起**；客户端仅转发到外部地址，
无法保证对端不连生产库。

### §九 七个待裁决问题 — 均未获答复 ❓

Q1 定位确认、Q2 试点场景（报告建议 `sc_ent2_group_month`，实际验证用 `sc001`）、
Q3 沙盒容器授权、Q4 自动化等级上限、Q5 数据出域边界、Q6 P1-18 前置、Q7 文档提交。

## 三、结论与后续前置

已完成的部分经审、经测、经活体验证，可作为 Phase 1 的接入底座。

但**报告的真目标——在隔离沙盒里跑 RD-Agent 代码进化循环——尚未实现**。当前物的准确
名称是「L3 只读研究循环骨架」。

继续推进绕不开三项必须先决的事项（均需用户裁决，见同批对话）：

1. **沙盒容器授权**（报告 Q3）：不授权则 §5.4 与 §4 的 implement/sandbox_run 永远缺位。
2. **Phase 0 是否真做**：需 Linux 环境 + rdagent + 真实数据快照；报告定位其为「零 ECOS 代码变更」
   的独立验证，与当前产物不重叠。
3. **审批是否改走 WAgent Candidate 通道**：涉及复用既有候选状态机，改动面大于当前独立表。
