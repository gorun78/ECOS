## 二、批次拆解（G1–G5 → PMO-73.1 ~ 73.5）

> 原子任务格式遵循铁律 §5.2：单文件/单模块 + 验收方式 + 不跨批次预创建文件。每批次执行时以独立 PMO 指令下发，本文件只定任务卡与验收门。

### G1（PMO-73.1）后端基础设施收敛 —— P1 债清偿

| Task | 文件/路径 | 操作 | 验收 |
|:--|:--|:--|:--|
| T1 | `data-engine-impl/.../service/QueryExecutionServiceImpl.java` | 两处 `DriverManager.getConnection` 改注入 runtime-access `JdbcConnector.executeQuery`；同法处理 `DataDescriptionDiscoveryImpl`、`MetadataRowCountService`；`BaseJdbcAdapter` 先裁定（连接测试属数据源适配器职责可豁免，须在类注释+本文件登记裁定结论） | mvn install 通过；SQL 控制台 PG 查询回归 curl 200；grep 业务代码 `DriverManager.getConnection` 仅剩裁定豁免项 |
| T2 | `data-engine-impl/.../metadata/MetadataCollectGitArchive.java` | repoRoot 规范化 + `normalized.startsWith(repoRootPath)` path-traversal 校验，非法配置拒绝并 warn 日志 | 单测：恶意 repoRoot（`../`）被拒；正常归档回归通过 |
| T3 | ArchUnit 规则（PMO-C 已建的 5 条依赖规则同处扩展） | 新增规则：`engine/**`、`services/**`、`workspace/**` 禁调用 `java.sql.DriverManager`（runtime-access 白名单） | CI pr-gate 新规则绿；故意违规样例被拦截 |
| T4 | `services/datanet/.../GitController.java` 等 Git 入口 | 复核 repoRoot 来源（sys_config）读取路径与 T2 校验联动，无绕过入口 | grep 全部 repoRoot 消费点均过校验 |

## 三、执行顺序与依赖

```
G1（后端收敛）──┐
                ├──► G3（集成测试，依赖 G1 收敛后的稳定接口面）──► G5（收尾）
G2（前端收敛）──┘        （G2 与 G1 前后端分离，可并行）
G4（AI 护栏）── 独立并行，但 T1 完成前 G3-T1 的 OPA 用例只测 security 侧
```

- **可并行**：G1 ∥ G2 ∥ G4；
- **硬依赖**：G3 在 G1 之后（避免对将改动的 QueryExecutionService 写测试）；G5 最后（T1 命名统一影响面广，放收尾窗口）；
- **节奏建议**：每批次一个执行会话，批内 Task 按序提交、批间 clean commit（Git 提交规范：working tree 不夹带）。

## 四、统一验收门（每批次必过）

1. **V1–V4 验证四步法**（铁律 §5.4）：文件生存 → 集成点 grep → 编译（后端 `mvn install`、前端 `npm run lint`）→ 启动 + curl/浏览器验收；
2. **Git 凭证**：每 Task 独立 commit（`type(模块): 动宾描述`），`git log --grep` 可溯源，working tree 未提交变更不算交付；
3. **安全强制卡**（§2.4-8）：G1-T2、G4-T1 为涉安全 Task，评审记录必须显式列出 security-engine 集成项，grep 命中 0 判 FAIL；
4. **禁改清单**：既有 API 路径/签名不改（G2-T3 属"前端内部函数迁移+签名对齐后端既有契约"，不新增/不修改后端端点）；无 DDL；无新 Maven 模块/容器。
