## §背景

来源：`docs/9-checks/2026-09-05-前端界面操作实现情况检查报告.md` §2.1 + §6（协调请求 1/2）。

本批次覆盖：
- **3 项 cognitive 端点补齐**（对应 §2.1 #14/#15/#16）：`POST /api/v1/cognitive/plan`、`GET /api/v1/cognitive/plan/{id}`、`POST /api/v1/cognitive/optimize`
- **2 项 ontology 端点补齐**（对应 §2.1 #19/#21）：`GET /api/v1/engine/ontology/workflow/definitions`、`GET /api/v1/ontology/versions/diff`
- **1 项 data-engine 路径修正**（对应 §2.1 #24）：`/api/v1/engine/data/query/templates`（复数）现有路径下新增 frontend 兼容别名 — **本批不直接改既有路径**（违反 §0.2 "API 只增不改"），而是让前端改路径（PMO-44 T3），本批次仅确认后端 `/templates` 复数路径健康
- **1 项 Portal 全局搜索**（对应 §6 #4：后端补 `Portal*Controller`，filter 重写已留，未实现）：`GET /api/v1/portal/search?q=&type=`

> 注：本批次 cognitive 不涉及任何 DB schema 变更（推理实时计算，§0.3/§3.3）；ontology 不改 workflow 存储结构，仅暴露 definitions HTTP 端点。

## §禁止清单（铁律继承 + 本指令特有）

1. ❌ cognitive 不新增 DB 表（§0.3 禁止清单）
2. ❌ cognitive 不引入规则引擎（SpEL 即可，§0.3）
3. ❌ 不 implements IEngine 之外的已有业务接口（多 Bean 冲突）
4. ❌ 新增引擎端点必须追加到对应引擎 AGENTS.md 端点清单（§2.3）
5. ❌ 新增 Controller 到引擎时必须在 `GatewayApplication.exculdeFilters` 排除旧位置副本（§2.2）
6. ❌ Portal 搜索端点如做 RLS 注入，必须走 security-engine 的 `POST /api/security/rls/apply`（§2.4）
7. ❌ 不动 `GET /api/v1/engine/data/query/templates` 复数路径本身（API 只增不改）
