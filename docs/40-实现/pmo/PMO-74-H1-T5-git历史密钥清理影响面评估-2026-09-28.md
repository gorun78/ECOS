## 二、风险定性

1. **泄漏面**：旧私钥在 2 个提交中可被任意 clone 者取回；`cef4c36` 之后的所有历史均可回溯。故旧钥必须永久作废（已作废：新钥登录链路生效，旧钥不再被任何运行模块加载）。
2. **历史清理的代价**：`git filter-repo` 会重写 544 个提交的 SHA → 所有分支、所有已 clone 工作副本、所有外部 PR/CI 引用同时失效，需全员重新 clone；GitHub 侧旧对象在服务端仍缓存一段时间（须再提工单/等待 GC）。属**不可逆共享动作**。
3. **不做历史清理的残余风险**：仓库泄露面仍存在「一把已作废的私钥」。因新钥从未进入 git（只存在于本机 `~\.config\ecos\` 与环境变量），残余风险为**信息泄漏**而非**可利用凭证**，可接受至发布窗口。

## 三、执行预案（发布窗口到期时按序执行，需用户再次批准）

```powershell
# 0) 全员冻结：合并所有在途分支，通知重新 clone 的时间点
# 1) 镜像备份（必须）
git clone --mirror https://github.com/gorun78/ECOS.git D:\backup\ECOS-mirror-<date>.git
# 2) 副本内重写（不在工作副本直接跑）
git filter-repo --invert-paths --path-glob '*.yml' --anchored-path regex:application\.yml  # 实际应精确到 2 个 blob
#    推荐口径：--strip-blobs-with-ids <旧私钥 blob sha>（先 git log --all --find-object 取 blob id）
# 3) 校验：git log --all -S"BEGIN PRIVATE KEY" 为空；mvn clean install -DskipTests 全绿
# 4) 强推 + 通知：git push --force --mirror（仅镜像仓库允许）→ 全员重新 clone
# 5) GitHub：提工单清理旧对象缓存；检查 fork / Actions 缓存制品
```

**回退路径**：第 1 步的 mirror 仓库即完整回退点；重写全过程在副本内进行，工作副本不受影响。
