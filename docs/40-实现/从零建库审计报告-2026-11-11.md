## 一、结论先行

「从零建库」跑不绿，**不是某一枚迁移写错**，而是**两套 DDL 从未对齐**：

| | 迁移链（`02-flyway-migration/gateway`，278 枚） | ST07 基线（`01-ddl-多方言/postgresql`，9 枚） |
|---|---|---|
| 表放哪 | **`public`**（V47 Step 2 的 76 条 `SET SCHEMA` 全部已注释作废） | **域 schema**（`ecos_ontology` / `ecos_data` / `ecos_ai` …） |
| 谁引用谁 | 硬编码 `public.ecos_ontology` 等 | 不引用迁移链 |
| 是否完整 | **否**——链头就断（见 §三） | 是（但只覆盖 V200 之前的 schema 集） |

两者都能「独立存在」，但**没有任何一方是完整的从零基线**：单跑迁移链缺建表，单跑 ST07 缺后续演进。

## 二、四组实测数据

| # | 组合 | 结果 | 说明 |
|:-:|---|---|---|
| ① | 空库 + 纯迁移链 | **142 / 279**（FAIL 136） | 链头即断：V4.4 要 `ALTER TABLE ecos_ontology`，但全链**从未** `CREATE` 该表 |
| ② | 空库 + V329 锚表 + 迁移链 | **193 / 279**（FAIL 86） | 补 30+ 张锚表后 +51 |
| ③ | ST07 + V329 + 迁移链 | **214 / 279**（FAIL 65） | 域 schema 表让裸名可解析，但 `public.X` 硬编码仍失配 |
| ④ | ST07 + 迁移链（早期） | **222 / 279**（FAIL 56） | 迭代重跑收敛值（幂等链自愈到上限） |

> 关键观察：**④ > ③**。说明 V329 里为 `public` 建的那批表，在 ST07 已建域 schema 表的情况下**反而制造了冲突**（同名表两处，解析歧义）。
> 反向也成立：**② > ①**。说明不铺 ST07 时，public 锚表是必需的。

**结论：两种基线互斥，必须二选一，不能混跑。**

## 四、第二类根因：版本序倒置

即使表存在，列也常常「后建先用」：

| 脚本 | 需要 | 该列在何时才有 |
|---|---|---|
| V39 | `ecos_dq_rule.code` | 更晚版本 |
| V42 | `ecos_ontology_entity.status` | V122 |
| V154 | `ecos_rls_policy`（表） | V164 才建 |
| V13 | `sys_config.config_type` | 无迁移添加 |

## 五、第三类根因：stale 镜像解析歧义

`application.yml:15` 的 search_path 首位是 **`ecos_control`**：

```
currentSchema=ecos_control,ecos_data,ecos_ontology,ecos_ai,ecos_cognitive,ecos_knowledge,ecos_infra,ecos_dw,public
```

因此**裸表名**（`ecos_ontology_entity`、`ecos_dq_rule`、`ecos_tool_definition`）会先命中 `ecos_control` / `ecos_ai` 下的**历史镜像表**，而那些镜像缺后续版本的列。

实测同名表分布：

| 表 | 存在于 |
|---|---|
| `ecos_ontology_entity` | `ecos_control`、`ecos_ontology`、`public` |
| `ecos_dq_rule` | `ecos_control`、`public` |
| `ecos_tool_definition` | `ecos_ai`、`public` |
| `sys_config` | `ecos_control`、`ecos_sysman` |

这与 V327 修的是**同一病根**（V327 已入库，只修了本体/认知两处）。

## 六、两条路线与代价

### 路线 A：迁移链为唯一真源（推荐）

- **做法**：V329 继续补 `public` 侧锚表 + 补列，直到 279/279 绿；`cli-e2e` 只跑迁移链，不铺 ST07。
- **代价**：
  - 需再补 37 张表 + 10 个列（约 3~5 轮迭代）
  - ST07 将成为「不参与建库的死文件」——需在铁律里明确它的定位（或降级为参考文档）
- **符合性**：符合「DDL 单源在迁移链」，但会让 ST07 名存实亡
- **已完成**：V329 已推进到 193/279（+51）

### 路线 B：ST07 为基线 + public 同构副本

- **做法**：承认 ST07 是权威 schema，V329 为 37 张表建 `public` 侧同构**视图或表**，使 `public.X` 与 `X` 都能解析。
- **代价**：
  - 同名两份，读写歧义风险
  - 与铁律「不做 DDL 双源」直接冲突
  - 视图无法承载 `ALTER` / `INSERT`（迁移链里有大量 `ALTER TABLE public.X`）
- **符合性**：**可能违反 §3.1 DDL 单源**

### 路线 C：混合（已证伪）

- 实测 ③（ST07+V329+链）= 214 **低于** ④（ST07+链）= 222。
- V329 为 public 建的表在 ST07 场景下制造解析冲突 —— **该路线不成立**。
