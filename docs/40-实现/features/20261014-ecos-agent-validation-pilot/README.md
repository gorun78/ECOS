# ECOS 端到端智能体验证试点：2027 年度经营预测

> 状态：试点方案与可选真实环境验收脚手架；不是已通过的运行报告。
> 基线：master @ cf1721f41ff6558d23e898e36ca4289d23b08c06（2026-10-14 核查）。
> 核心需求来源：`docs/20-需求/PRD-09-年度经营预测场景需求规格-2026-09-28.md`、PRD-10 W Agent 需求、场景工作台契约及当前控制器实现。

## 1. 为什么选择这个场景

优先选用仓库已定义的 `p-2027-profit`（现有前端 E2E 测试中的年度经营预测场景 ID），而不是另造一个演示业务。PRD-09 已把业务边界明确为：目标年度 2027、月度期间、3 个项目、2 个部门、基准与“验收延期”两类情景；金额必须由确定性计算产生，LLM 不得生成或修饰预测数字。

这个场景可以在一次试点中覆盖 ECOS 的主要逻辑链：
- D / 数据：项目、部门、期间、经营事实和数据质量。
- I / 本体：已审批的经营预测口径及其版本。
- K / 知识：数值画像、经审批假设及证据引用。
- C / 认知：诊断、假设、反事实/情景比较及来源追溯。
- W / AI 编排：Goal → Plan → Run/Step → Candidate；不越权写入其他领域。
- 场景工作台：场景上下文、运行、结果解释、人工决策、行动和反馈。

**数据策略：优先读取 ECOS 测试/验收环境中已有的真实记录。不得把本文件、人工构造的 CSV 或 LLM 输出冒充生产数据。** 若环境没有所需事实或已审批口径，报告“数据前置缺失”，不要自动造数补齐。

## 2. 验证目标与不在范围内的内容

目标：
1. 验证真实业务场景能否解析出数据、口径、知识和认知依赖。
2. 验证同一输入可重复运行、幂等键有效、来源与版本可追溯。
3. 验证缺数据、缺口径、无权限、认知服务不可用时是否 fail-closed。
4. 验证 W Agent 只编排和提出候选，不越过人工审批或领域写入门禁。
5. 形成一份可复现的“通过/失败/阻塞”证据报告。

本试点不自动批准经营决策、不执行真实业务动作、不修改生产数据、不新增数据库表、不运行未经授权的迁移。第一轮只在隔离的开发/验收环境运行。

## 3. Agent 角色定义

名称：**ECOS 经营预测与决策验证 Agent（Pilot）**

角色：基于受控领域 API 的编排 Agent；它不是新的业务数据权威，也不是利润数字生成器。

### 输入
- 场景 ID（验收环境中确认的现有场景）。
- 目标期间与 as-of 时间。
- 已审批的口径 ID + 版本。
- 事实数据范围（项目、部门、月份）。
- 已审批画像/假设的来源引用。
- 用户目标、约束、情景覆盖项和运行模式。

### 输出
- 依赖检查报告（每项附真实 API/对象引用、版本、状态）。
- 预测运行 ID、真实运行状态及结果引用。
- 结果证据包引用（口径、快照、画像/假设、事实来源）。
- 基准与情景的差异摘要；所有数字必须来自确定性服务。
- 供业务人员审核的 Candidate（建议，不是已批准决策）。
- 待人工确认的决策/行动建议。
- 运行错误、缺失依赖和审计追踪。

### 禁止行为
- LLM 计算、补齐、插值或润色 P10/P50/P90、收入、成本、利润等数字。
- 事实缺失时静默填 0、均值或“合理估计”。
- 把 503/501/403 或缺失 reader 伪装成空结果或成功。
- 直接读写任何 Engine 的数据库表。
- 未经审批发布 Candidate，或直接执行现实业务动作。
- 把 Agent 运行成功等同于业务审批通过。

## 4. 标准执行流程

1. **Goal 解析**：把“验证 2027 年度经营预测闭环”转成可检查的目标、范围和验收条件。
2. **依赖盘点**：检查场景、已审批口径版本、事实数据质量、画像/假设及认知能力。所有来源均用权威 API/引用。
3. **Plan 生成**：生成只读预检、基准运行、情景复制/比较、证据读取和人工审核步骤。
4. **Run / Step 执行**：先只读预检；满足前置条件后，才允许在隔离环境创建正式测试 run。记录每一步的输入引用、状态和错误。
5. **确定性计算**：调用 ECOS 预测运行服务。Agent 只能解释结果，不能生产结果数字。
6. **认知分析**：若认知依赖未启用，明确标记为阻塞；不得用 LLM 推理伪造认知引擎结果。
7. **Candidate 生成**：输出差异与建议，附来源、口径版本、运行 ID、证据引用。
8. **Review / Approve**：由具备权限的人审核。试点默认只生成候选，不自动批准。
9. **业务消费**：仅在审批通过且现有受控 API 已接通时，才进入行动环节；第一轮不执行外部业务动作。
10. **Feedback**：记录人工判定、偏差、问题和复测结果，关联原场景、运行 ID 与版本。

## 5. 数据契约与来源映射

| 逻辑输入 | 权威来源/已知契约 | 验证要求 |
|---|---|---|
| 场景 | 现有场景服务；已存在测试引用 `p-2027-profit`，仍须在目标环境确认 | 场景可读、期间/范围符合授权 |
| 经营口径 | `GET /api/v1/ontology/calibers?code=MANAGEMENT_FORECAST` | 必须是 APPROVED 版本；禁止猜测版本 |
| 经营事实 | PRD-09 记录的 `ecos_dw.ecos_biz_stage_fact`、`ecos_dw.ecos_biz_cost_fact`、`ecos_dw.ecos_biz_resource_fact`、`ecos_dw.ecos_biz_project_attribution` 对应数据域读通道 | 实际行存在、期间覆盖完整、DQ 通过；Agent 不直连数据库 |
| 画像 | `/api/v1/knowledge/profiles` | 保存 profile 版本和证据引用 |
| 假设 | `/api/v1/knowledge/assumptions` | 仅使用已审批假设，保存审批与版本引用 |
| 预测 run | `POST /api/v1/workspace/forecast-runs` | 请求六要素、幂等键、内容指纹齐备；依赖缺失应真实失败 |
| 运行状态/结果/证据 | `GET /api/v1/workspace/forecast-runs/{runId}`, `/results`, `/evidence` | 状态、P10/P50/P90、快照和来源一致 |
| 情景对比 | `GET /api/v1/workspace/forecast-runs/compare?baselineRunId=...&candidateRunId=...` | 对比由后端完成；不由 Agent 重新算数 |
| 场景认知 | `GET /api/v1/business/scenarios/{id}/cognition/{detect,hypotheses,beliefs,operation-eval}`，以源代码实际映射为准 | 503/缺 Mind 需显式标记阻塞 |

注：本表是试点的契约清单，不代表所有依赖在部署环境均已接通。PRD-09 v1.3 明确指出：代码在位和单元门禁通过不等于六演练或整条业务链已验收；真实运行前必须重新核对部署环境。

## 6. 验收场景

| 编号 | 场景 | 预期结果 |
|---|---|---|
| P-01 | 所有依赖齐备，执行基准预测 | 真实 run 完成；结果来自确定性服务；有口径/快照/来源引用 |
| P-02 | 同一幂等键、同一内容指纹重试 | 返回同一 run 或明确的幂等复用结果，不重复制造业务结果 |
| P-03 | 缺少任一必填要素 | 400，不能创建 run |
| P-04 | 口径不是 APPROVED | 发布/正式运行门禁拒绝；不得自动挑选其他版本 |
| P-05 | 缺少必要事实或 DQ 未通过 | 阻断运行并指出缺失；不静默补 0 |
| P-06 | ForecastRunGateway / snapshot reader 未装配 | 真实 501/503 阻塞；不得 mock-success |
| P-07 | 认知引擎不可用 | 保留 503 和 trace 信息；界面显示降级，不生成伪认知结论 |
| P-08 | 用户无权限 | 403/OPA 拒绝；不泄露越权字段 |
| P-09 | 复制“验收延期”情景 | 产生独立候选 run；基准 run 不变；差异由后端确定性比较 |
| P-10 | 预测区间缺 P10/P50/P90 任一值 | 缺失值保留 null/显式缺失；禁止 LLM 或前端插值 |
| P-11 | Candidate 审核被拒绝 | 不发布、不执行行动；保留审计轨迹 |
| P-12 | 人工反馈改变关键假设 | 创建新版本/复核记录，不覆盖历史 run 与已发布版本 |

## 7. 运行方法

### 7.1 只执行安全预检

在仓库根目录的 `ecos-tests` 中设置 `.env`，仅包含有权限的验收环境凭据：

- `ECOS_API`
- `ECOS_USER`
- `ECOS_PASS`

执行：

```bash
npm run test:api -- tests/api/annual-forecast-agent-pilot.spec.ts
```

该阶段只验证缺必填字段的请求会被拒绝，不会创建预测 run。

### 7.2 允许创建真实验收 run（显式 opt-in）

必须先确认目标是隔离的开发/验收环境，并从该环境的权威接口获取真实参数；不得从本文件抄写虚构 ID。然后在 `ecos-tests/.env` 或环境变量中设置：

- `ECOS_PILOT_EXECUTE=1`
- `ECOS_PILOT_SCENARIO_ID`
- `ECOS_PILOT_RUN_TYPE`
- `ECOS_PILOT_CALIBER_ID`
- `ECOS_PILOT_CALIBER_VERSION`
- `ECOS_PILOT_AS_OF_TIME`
- `ECOS_PILOT_SNAPSHOT_ID`
- `ECOS_PILOT_FORMULA_VERSION`
- `ECOS_PILOT_IDEMPOTENCY_KEY`

其中 snapshot 与 formula version 必须来自已验证的实际数据链路；如果当前系统尚无可用 snapshot reader，则不要启动真实 run，应把结果登记为 P-06 阻塞。

执行同一测试文件。它将创建 run、检查状态/结果/证据并以相同幂等键重放一次。运行会写入验收环境记录，因此必须由环境负责人明确授权后再执行。

## 8. 完成判定

只有 P-01、P-02、P-03、P-04、P-05、P-06、P-07、P-08、P-09、P-10、P-11、P-12 均有真实证据，才能判定 ECOS 端到端逻辑闭环通过。未运行、依赖未装配或没有真实数据的项目统一标记为 BLOCKED / NOT RUN，不能按通过处理。

本次提交只提供试点契约和真实环境验收脚手架，不宣称已连接运行中的 ECOS 实例，也不宣称已完成业务闭环验收。
