# L3 研究沙盒：部署与隔离验证

> 版本：v1.0（2026-11-25）｜依据：可行性报告 v2.0 §5.4｜授权：用户裁决「要」（建沙盒容器）
> 前置变更：容器基线由 9 增至 **10**（本轮用户明确授权，非默认放宽）

---

## 一、它是什么

沙盒有**两档能力**：

**① 声明式算子**（默认、确定性）：收 `{snapshot.rows, experiment{groupBy,filters,metrics}}`，
返回 `{metric, insight, snapshotDigest}`。算子只有 6 个：
`count / sum / avg / min / max / distinct_count`。

**② 受控 Java 代码执行**（2026-11-25 用户授权「要做」）：`POST /research/execute`
收 Java 源码，容器内 `javac` 编译后以独立子进程运行，返回 stdout/stderr 与
`METRIC <数字>` 指标。

### 代码执行的安全模型（必读）

**主防线是容器，不是静态检查。** 这是本设计最重要的一句话：

| 层 | 作用 | 是否安全边界 |
|---|---|---|
| 容器（无网络/只读根/cap-drop/非 root/配额） | 真正挡住越权 | **是** |
| 一次性子进程 + 硬超时强杀 | 挡住死循环/挂起 | 是 |
| `-Xmx` 与输出限额 | 挡住内存/日志炸弹 | 是 |
| 静态 API 筛查（8 条 deny 规则） | 让常见误用快速失败 | **否，仅防呆** |

**为什么强调「静态检查不是边界」**：实测已证明——`Files.writeString` **未**被
静态规则命中（我刻意没把 `writeString` 列进去，因为正常业务也可能用到近似写法），
但容器只读根把它挡成了 `FileSystemException`。这说明**绕过静态检查是可行的**，
而容器层兜住了。

**因此**：不要因为「静态检查过了」就认为代码安全；安全来自容器配置。
反过来说，若要放宽容器配置（比如给沙盒加网络），必须同步重新评估整体风险。

### 残余风险（诚实登记）

1. **容器逃逸**：若存在 Docker/内核 0day，代码可逃出容器。缓解：容器非 root、
   cap-drop ALL、无 docker socket。**无法完全消除**。
2. **CPU 耗尽**：超时强杀是「事后」，恶意代码仍可在超时窗口内跑满 CPU。
   缓解：`cpus: 1.0` 配额，不拖垮宿主。
3. **`/tmp` 可写**：编译工作需要，`tmpfs` 60m 且 `exec`（JVM 必需）。
   恶意代码可在 `/tmp` 写文件，但随容器销毁消失，且不触达宿主。
4. **静态规则可绕过**：见上，已由容器兜底，但意味着**不能仅靠静态检查做准入**。

## 二、部署

```bash
# 1) 构建镜像（宿主机预编译，因本机 Docker Hub 不可达）
cd ecos-docker/research-sandbox
powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1

# 2) 启动（已在 docker-compose.yml 中登记）
cd ..
docker compose up -d research-sandbox

# 3) 探活
curl http://127.0.0.1:18099/health
```

**接入 workspace**（沙盒档默认不启用，须显式配置）：

```powershell
$env:ECOS_RESEARCH_SANDBOX_BASE_URL='http://127.0.0.1:18099'
powershell -File _win_tasks/start-backend.ps1 -Modules gateway,sysman,workspace -Profile enterprise
# 日志出现「L3 沙盒研究执行器已启用 baseUrl=...」即生效
```

未配置该环境变量 ⇒ 沙盒 Bean 不装配，自动回落只读档（fail-closed 到「不执行代码」）。

## 三、隔离验证（2026-11-25 全部实测）

**自动化门禁**：`bash ecos-docker/research-sandbox/verify-isolation.sh`
（15 项断言，真实打容器，无 mock）→ 正式容器 **PASS=15 FAIL=0**。

**反证（必须做，否则 PASS 可能是假绿）**：用同一门禁跑一个**故意放松隔离**的
对照容器（root + 可写根 + 有网络）→ **FAIL=4**，其中「出网可达 200」
「根文件系统非只读」被正确判红。证明门禁不是恒绿。

| # | 约束 | 验证方式 | 结果 |
|---|---|---|---|
| A | 容器健康 | `docker inspect .State.Health` | healthy |
| B | 正常计算可用 | 1..100 求和 | `measuredMetric=5050` |
| C | 网络 API 被拒 | `new Socket(...)` | code=403（静态层） |
| D | 起进程被拒 | `Runtime.exec("id")` | code=403（静态层） |
| E | **只读根生效** | 写 `/app/pwn` + 查 `ReadonlyRootfs` | BLOCKED 且 cfg=true |
| F | **完全无出网** | 容器内 `curl example.com` | `HTTP=000` |
| G | 超时强杀 | 无限循环 timeoutMs=3000 | `timedOut=true` |
| H | 内存炸弹受限 | 无限 new long[1e6] | `OutOfMemoryError` |
| I | 输出炸弹截断 | 打印 20 万行 | `truncated=true`, 262144B |
| J | 攻击后仍健康 | 上述全部跑完 | healthy |
| K | 非 root/无 cap/只读根 | `id -u`、`CapEff`、inspect | 10001 / 全 0 / true |
| L | 无 socket 无宿主卷 | `ls`、`docker inspect .Mounts` | 均无 |

### 网络口径（重要，勿随意改）

沙盒**不能出网**，但宿主机必须能调用它。本机实测：
`--internal` 网络下 Docker 的端口发布**完全不生效**（宿主机访问不到），
故采用 `bridge + DNS 黑洞`（`dns: 127.0.0.1`，容器内无可用解析器）。

若未来要更硬的出网隔离，应改为「双网络 + 内部代理网关」，
**不要**简单切 `internal`——那会直接断掉调用面。

## 四、已知边界（诚实登记）

1. **代码执行是 Java，不是 Python**：RD-Agent 原生的 CoSTEER 生成 Python。
   本沙盒因本机 Docker Hub 不可达（拉不到 python 镜像）改用 Java。
   模型需按 Java 语法生成代码；若要 Python，须先解决镜像来源。
2. **快照极简**：后端目前只发 `scenarioId/loopIndex/hypothesisCount` 三列。
   真实业务度量须由上游按场景口径导出后注入；`ecos_dw` 业务数据当前近乎为空
   （实测仅 2 行），没有可研究的真实业务切片。
3. **无审计落库**：沙盒自身只写 stderr 单行日志（不记请求体），
   未接 ECOS 审计表。报告 §5.4「全链路审计」尚未闭环。
4. **无短期令牌**：报告要求「研究专用短期令牌」，当前仅中继调用方凭证头。
5. **单副本**：无水平扩展、无队列；并发靠容器内 4 线程池。
6. **代码执行未接进研究循环**：`/research/execute` 端点已可用且有隔离门禁，
   但 `ScenarioResearchRunService` 的循环**尚未调用**它（循环仍走声明式算子）。
   要接进去需要「假设→生成代码→执行→按指标评估」的生成器，属下一步。
