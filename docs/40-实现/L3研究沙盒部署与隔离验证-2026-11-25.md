# L3 研究沙盒：部署与隔离验证

> 版本：v1.0（2026-11-25）｜依据：可行性报告 v2.0 §5.4｜授权：用户裁决「要」（建沙盒容器）
> 前置变更：容器基线由 9 增至 **10**（本轮用户明确授权，非默认放宽）

---

## 一、它是什么

一个**声明式算子沙盒**：收 `{snapshot.rows, experiment{groupBy,filters,metrics}}`，
返回 `{metric, insight, snapshotDigest}`。支持的算子只有 6 个：
`count / sum / avg / min / max / distinct_count`。

**它不做任意代码执行**——这是对报告 R2「极高风险」的正面回应。
沙盒里没有解释器入口、没有 `eval`、没有任何第三方包。即便容器失陷，
攻击者拿到的也只是一个只会做聚合的服务。

## 二、部署

```bash
# 1) 构建镜像（宿主机预编译，因本机 Docker Hub 不可达）
cd ecos-docker/research-sandbox
powershell -NoProfile -ExecutionPolicy Bypass -File build.ps1

# 2) 启动（已在 docker-compose.yml 中登记）
cd ..
docker compose up -d research-sandbox

# 3) 探活
curl http://127.0.0.1:18099/health
```

**接入 workspace**（沙盒档默认不启用，须显式配置）：

```powershell
$env:ECOS_RESEARCH_SANDBOX_BASE_URL='http://127.0.0.1:18099'
powershell -File _win_tasks/start-backend.ps1 -Modules gateway,sysman,workspace -Profile enterprise
# 日志出现「L3 沙盒研究执行器已启用 baseUrl=...」即生效
```

未配置该环境变量 ⇒ 沙盒 Bean 不装配，自动回落只读档（fail-closed 到「不执行代码」）。

## 三、隔离验证（2026-11-25 全部实测）

| # | 约束 | 验证方式 | 结果 |
|---|---|---|---|
| A | 宿主机可调用 | `curl 127.0.0.1:18099/health` | 200 `{"code":0,...}` |
| B | 容器不能出网 | 容器内 `curl example.com` | `HTTP=000`（失败） |
| C | 非 root | `id -u` | `10001` |
| D | 根文件系统只读 | 容器内 `touch /app/x` | `Read-only file system` |
| E | 能力已清空 | `/proc/self/status` 的 `CapEff` | `0000000000000000` |
| F | 无 docker socket / 无宿主卷 | `ls /var/run/docker.sock`；`docker inspect .Mounts` | 不存在 / 空 |
| G | 资源配额 | `docker inspect` | mem=192m, pids=48, cpus=0.5, readonly=true |
| H | 功能正确 | 分组求和 EAST=300 / WEST=80 | 通过，spread=220 |
| I | 失败显式 | 传不存在的字段 | `code=400 「快照中不存在字段」` |

### 网络口径（重要，勿随意改）

沙盒**不能出网**，但宿主机必须能调用它。本机实测：
`--internal` 网络下 Docker 的端口发布**完全不生效**（宿主机访问不到），
故采用 `bridge + DNS 黑洞`（`dns: 127.0.0.1`，容器内无可用解析器）。

若未来要更硬的出网隔离，应改为「双网络 + 内部代理网关」，
**不要**简单切 `internal`——那会直接断掉调用面。

## 四、已知边界（诚实登记）

1. **声明式而非图灵完备**：不支持任意 Python/Java 代码。RD-Agent 的
   `Coder`（CoSTEER）能力**未接入**，当前只能做确定性聚合。
2. **快照极简**：后端目前只发 `scenarioId/loopIndex/hypothesisCount` 三列。
   真实业务度量须由上游按场景口径导出后注入；`ecos_dw` 业务数据当前近乎为空
   （实测仅 2 行），没有可研究的真实业务切片。
3. **无审计落库**：沙盒自身只写 stderr 单行日志（不记请求体），
   未接 ECOS 审计表。报告 §5.4「全链路审计」尚未闭环。
4. **无短期令牌**：报告要求「研究专用短期令牌」，当前仅中继调用方凭证头。
5. **单副本**：无水平扩展、无队列；并发靠容器内 4 线程池。
