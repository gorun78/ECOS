## 一、一句话结论

现网 `sys_man` 共 **16 个 schema / 665 张表**；按 ST07「5+1」口径，**合规承载面 = 五引擎 schema + 主控制 `public` + 业务域 `ecos_dw`**，覆盖 **324 张表**；其余 **341 张表**落在 5 个 knownLegacy schema（`ecos_security`/`ecos_sysman`/`ecos_infra`/`ecos_dq`/`ecos_demo`）+ 4 个空壳 schema 内 → 全部标 knownLegacy，**规则只约束新增**（ST07 附注），存量不迁不删。

## 四、按规范新增内容

### 4.1 向量形态（湖规 v2.0 §〇-B、§七A）——实查更正

| 事实 | 实查结果 |
|:--|:--|
| pgvector 扩展 | **已安装**：`pg_extension` = `vector 0.6.2`（另有 `pg_trgm` / `pgcrypto` / `plpgsql`），**未新增容器** |
| 真实向量列 | `ecos_knowledge.knowledge_embedding.embedding_vec`（`vector` 类型，全库仅此 1 列 + 1 个 HNSW 索引 `idx_knowledge_embedding_vec_hnsw`） |
| 嵌入调用 | 经 `llm-gateway`：`ai-engine` `LlmController` `POST /api/v1/llm/embedding`；kb 侧 `QueryEmbeddingHelper` 只调该端点（架构铁律 §2.5-2 合规） |
| 可用性守卫 | `PgVectorSupport` 启动探测，不可用则向量链路降级（MC03 合规写法） |
| 数据量 | `knowledge_embedding` / `kb_doc_chunk` / `ecos_dw.doc_chunk` 均 **0 行** → 能力就绪、无端到端实测 |
| 仍在降级的两处 | DQ `DqKnowledgeSinkServiceImpl`（MD5 字节展开 1024 维 → 存 `text`）；cognitive `PrecedentRef`（无向量时回退关键词匹配） |
| 控制域混入 | `public.ecos_knowledge_document.embedding jsonb`（向量数据入主控制 schema，违 MC05 存量） |

> 规范文本原写「pgvector 未装、三处各自 MD5 伪向量」，据本次实查已在两份规范中更正：kb 链路 = 已合规实现（缺数据不缺能力，验收转为 #11 端到端召回）；真实遗留降级点是 DQ 与 cognitive，改挂 **#13**。

## 五、复现命令

```bash
# schema × 表数
docker exec ecos-postgres psql -U postgres -d sys_man -At -F '|' \
  -c "SELECT schemaname, count(*) FROM pg_tables
      WHERE schemaname NOT LIKE 'pg\_%' AND schemaname<>'information_schema' GROUP BY 1 ORDER BY 2 DESC"

# 全量表清单（hex 编码规避 Windows 控制台对非 ASCII 表名的转码损耗）
docker exec ecos-postgres psql -U postgres -d sys_man -At \
  -c "SELECT encode((schemaname||'.'||tablename)::bytea,'hex') FROM pg_tables ..."

  -c "SELECT n.nspname, c.relname, a.attname FROM pg_attribute a JOIN pg_class c ON c.oid=a.attrelid
        JOIN pg_namespace n ON n.oid=c.relnamespace JOIN pg_type t ON t.oid=a.atttypid WHERE t.typname='vector'"

# 规范门禁（18 项）
powershell -NoProfile -ExecutionPolicy Bypass -File _win_tasks/db-migration-lint.ps1
```
