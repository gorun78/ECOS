# L3 研究循环运行手册（Phase 0 离线验证 + 在线联调）

> 版本：v1.0（2026-11-25）｜对应报告：《RD-Agent 能力接入可行性报告》v2.0
> 定位：L3「研究循环」首个可运行切片的操作口径。本手册只讲**怎么跑与怎么验**，
> 设计依据见报告 §5，DDL 见 `docs/50-db_script/02-flyway-migration/gateway/V365__*.sql`、`V366__*.sql`。

---

## 一、它是什么 / 不是什么

**是**：在 L1（问题驱动单轮问答）与 L2（算法型分析）之上的第三层——多轮「假设 → 实验 → 评估 → 记录」，
每轮落一行 `RESEARCH_RUN`，通过 `parent_run_id` / `sota_run_id` / `branch_key` 串成可追溯谱系。

**不是**：

- **不执行任意代码**（只读执行器档）；沙盒档仅在显式配置 `ecos.research.sandbox.base-url` 时启用，且代码执行发生在外部隔离沙盒；
- **不产出正式口径**：研究轮次固定 `run_mode='SANDBOX'`，不计入 `isFormalRunExists`；
- **不自动生效**：审批只留痕，不回写蓝图/指标。

## 二、两条命令（零依赖）

### 1. 生成快照模板

```bash
node ecos_backend/scripts/verify-research-lineage.mjs --export lineage.json
```

### 2. 校验谱系自洽

```bash
node ecos_backend/scripts/verify-research-lineage.mjs lineage.json
# [PASS] 谱系自洽：runs=N approvals=M 全部约束通过   → 退出码 0
# [FAIL] K 条违例 …                                  → 退出码 1，逐条列出
```

脚本**不连库、不启容器、不调模型**，只做结构校验。违例会逐条打印并标出类别（`[分级]`/`[隔离]`/`[谱系]`/`[轮次]`/`[停止原因]`/`[SOTA]`/`[审批]`）。

校验的 7 条不变量：

| # | 不变量 | 为什么必须 |
|---|---|---|
| 1 | `run_level ∈ {RD_AGENT, MENTAL_MODEL, ALGORITHM}` | 分级词表封闭，禁自造层级 |
| 2 | `RESEARCH_RUN.run_mode` 恒 `SANDBOX` | 研究轮次不得污染正式口径 |
| 3 | `parent_run_id` 闭合 | 谱系不允许悬空父 |
| 4 | `loop_index` 沿链不倒退、无环 | 树必须可拓扑排序 |
| 5 | `stop_reason` 词表封闭；中间轮留空 | 停止原因是结论，不是过程噪声 |
| 6 | 至多一条自指 SOTA，且必须 `ACCEPTED` | SOTA 唯一是「比较基准」的前提 |
| 7 | `APPROVED` 必带 `approval_ref` | 禁「生成即审批」 |

**反证义务**：改动脚本后必须构造违例快照确认它仍能变红。已实测——注入 4 类违例（FORMAL 研究轮 / 断链 / SOTA 非 ACCEPTED / 批准缺 ref）后逐条判出、退出码 1。

## 三、在线联调（真实环境）

前置：`gateway:8080` + `sysman:18081` + `workspace:18090` 三 JAR 在跑，`V365`/`V366` 已应用到 `sys_man` 库。

```bash
# 0) 登录取 token（凭据见 .trae/rules/开发环境登录凭据.md，禁硬编码到用例）
TOKEN=$(curl -s -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}' | jq -r .data.accessToken)

# 1) 研究准备（不执行、不落库）
curl -s -X POST http://localhost:8080/api/v1/workspace/scenarios/sc001/research-runs/prepare \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"question":"主要风险根因是什么"}'

# 2) 发起研究循环（同步，预算由后端钳制在 maxLoops<=5 / 单轮<=600s / 总<=1800s）
curl -s -X POST http://localhost:8080/api/v1/workspace/scenarios/sc001/research-runs \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"question":"主要风险根因是什么","budget":{"maxLoops":3}}'

# 3) 谱系列表 / 单轮详情
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8080/api/v1/workspace/scenarios/sc001/research-runs?limit=50"
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8080/api/v1/workspace/research-runs/<runId>"

# 4) 两轮对比（只给原值 + 是否相同，不判优劣）
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8080/api/v1/workspace/research-runs/<a>/compare/<b>"

# 5) 审批（批准必带 approvalRef；驳回可只带 reason）
curl -s -X POST "http://localhost:8080/api/v1/workspace/research-runs/<runId>/approve" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"decision":"APPROVED","approvalRef":"APR-2026-001"}'
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:8080/api/v1/workspace/research-runs/<runId>/approvals"
```

**中文请求体注意**：Git Bash 下 `curl -d '{"question":"中文"}'` 易因编码变成 400。
用文件传：`curl --data-binary @q.json`（`q.json` 由 node 以 utf8 写出）。

## 四、执行器两档

| 档位 | 启用条件 | 代码执行 | 外网 | 行为 |
|---|---|---|---|---|
| `READ_ONLY_PROBE`（默认） | 恒可用 | 否 | 否 | 查绑定、查知识命中、聚合确定性读数；**无业务真值即显式 DEGRADED** |
| `SANDBOX` | 配置 `ecos.research.sandbox.base-url` | 是（外部沙盒） | 否 | POST `{baseUrl}/research/rounds`；应答缺 `metric` 即失败，**不回退冒充成功** |

两档共用同一套预算、谱系、评估与审批语义，换档不改循环行为。

**两档均经实测**：

- 未配置 ⇒ `prepare` 自述 `{"kind":"READ_ONLY_PROBE","codeExecution":false,...}`（活体，经网关）；
- 配置后 ⇒ 启动日志出现 `L3 沙盒研究执行器已启用 baseUrl=...`，Bean 装配无冲突（活体）；
- 沙盒三条 fail-closed 路径由 `SandboxResearchExecutorTest` 5 项单测覆盖：不可达/业务码非 0/缺 `metric` 全部抛异常，**禁静默回退**；成功路径 `data` 原样透出且与只读档评估结论逐字一致。

手动起服务验证时**必须**经 `_win_tasks/start-backend.ps1`（它注入 `JWT_PUBLIC_KEY`）；直接 `java -jar` 会因缺公钥导致所有 token 401，这不是产品缺陷。

## 六、已知边界（诚实登记）

1. **接受门槛依赖知识命中**：`accepted = 绑定>0 且 知识命中>0`。知识库为空时研究必收敛为 `NO_PROGRESS`——这是如实反映，不是缺陷。
2. **业务真值未接入（P1-18）**：所有轮的评估均为「结构评估」并显式 `DEGRADED`，不把结构满足当业务有效。
3. **首切片为同步执行**：报告 §5.2 规划的异步形态（runtime-task）尚未落地，长研究可能触及请求超时。
4. **审批不做角色鉴权**：仅要求已认证主体 + 带 `approvalRef`；是否限定审批角色待治理侧裁决。
5. **`scripts/verify-research-lineage.mjs` 不进 CI**：Phase 0 手工验证工具，未接门禁。
