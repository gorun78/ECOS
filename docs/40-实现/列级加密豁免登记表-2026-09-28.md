## 一、登记规则

1. **粒度**：一列一行。列未建表时以「预登记」状态入表，建表 DDL 合入前必须补齐策略 ID 与裁决点。
2. **四要件缺一不可**（ST03-A 原文）：RLS 策略 + CLS 分级 + 导出/AI 通道强制脱敏裁决点 + 批准人与日期。
3. **只加不删**：列若后续改为加密或废弃，本表原行保留并加注 `[已退出豁免→加密/删除]`。
4. **审批人**：用户（PMO）。AI Agent 不得自行新增或修改本表的批准人字段。

| 字段 | 含义 |
|:--|:--|
| 域/层 | 业务域 `CURATED` / `APPLICATION`（控制域一律不可登记） |
| RLS 策略 | `ecos_rls_policy` 中的策略 ID；未定则填 `TBD-<批次>` 并标阻塞 |
| CLS 分级 | 用户级 > 角色级 > 全局，取生效值 |
| 脱敏裁决点 | 导出与 AI 工具通道各自的具体调用点（路径 + 判定接口） |
| 状态 | 预登记（表未建）/ 生效（表已建且 DDL 已合入）/ 已退出 |
