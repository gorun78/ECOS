## 五、Phase 2 门禁实跑（P-5 结案）

**类**：`ecos_backend/gateway/src/test/java/com/chinacreator/gzcm/gateway/arch/CliContractParityTest.java`（gateway 现有模块，不新增 Maven 模块）

| 方法 | 判据 | 结果 |
|:--|:--|:--|
| `everyCommandMapsToOpenApiOperation` | 命令 operationId 必须在契约中存在；命令记录禁带 path/url；flag 参数名须溯源到契约 query 参数 | PASS |
| `noCommandTargetsServicePortDirectly` | CLI 源码零 service 端口 / 零 `jdbc:` / 非 :8080 主机地址；且必须保留默认 :8080 | PASS |
| `everyContractPathExistsInController` | 每条 implemented 契约路径必须由 Controller 静态映射覆盖（解析 `@*Mapping` + `*ApiPaths` 常量拼接） | PASS |
| `contractRegistryNonVacuous` | 契约可解析、sha 与清单绑定、operationId 与 (method,path) 全局唯一、**清单↔契约逐条同源**、计数下限 87 | PASS |

**跑法（实跑命令）**

```bash
mvn -o -f ecos_backend/pom.xml -pl gateway test -Dtest=CliContractParityTest -DfailIfNoTests=false
# Tests run: 4, Failures: 0, Errors: 0 — BUILD SUCCESS
mvn -o -f ecos_backend/pom.xml -pl gateway test -Dtest=RepoTestSurfaceExecutabilityTest -DfailIfNoTests=false
# Tests run: 11, Failures: 0, Errors: 0（新增测试类未撞测试面可执行性棘轮）
```

**扫描规模**（证明门禁非空转）：Controller 路由 **1344** 条 `(method,path)`；`*ApiPaths` 常量 **156** 个（按「类名.常量名」限定解析）；契约 **84 paths / 87 operations / 3 文件**。

**变异探针（3 次，均先证「改上了」再看红，随后复原）**

| # | 注入 | 期望变红的方法 | 实测 |
|:--|:--|:--|:--|
| 1 | 清单命令改指 `ghostOperation` | `everyCommandMapsToOpenApiOperation` | 红：命令映射到契约中不存在的 operationId |
| 2 | CLI 源码注入 `http://localhost:18089` | `noCommandTargetsServicePortDirectly` | 红：出现非网关地址 |
| 3 | 手改清单某条 path 为 `/api/v1/cognitive/not-models` | `contractRegistryNonVacuous` | 红：清单与契约逐条不一致 |

另：`everyContractPathExistsInController` 在开发过程中**自然变红过三轮**（18 → 8 → 4 条未命中），分别暴露「ApiPaths 同名常量串味」「无参注解/局部常量未解析」「AI 能力双前缀缺陷」，修复解析器与契约状态后转绿——非为凑数制造的假红。

### 门禁顺带发现的既有缺陷

**D-CLI-1（P1，已修复 ✅ 2026-11-09）**：`AiCapabilityController` 类级 `@RequestMapping(AiCapabilityApiPaths.BASE_PREFIX)` 叠加方法常量（常量已含 `/api/v1/ai` 全路径）⇒ 实际注册为 `/api/v1/ai/api/v1/ai/capabilities/...`。活体 OPTIONS 修复前证据：单前缀 `/api/v1/ai/capabilities/{id}/execute` → **404**；双前缀 → **200 Allow: POST**。
**修法（用户授权）**：删类级前缀；`@GetMapping(PATH_CAPABILITIES)` 局部常量改为 `AiCapabilityApiPaths.CAPABILITIES_COLLECTION`；删 `PATH_CAPABILITIES`；类头 Javadoc 加防回归注记。
**验证**：`AiCapabilityControllerPathContractTest` 2/2（单前缀命中 handler、双前缀不命中）；重打 fat jar（reactor 内 `-am package`，不污染 .m2）重启 gateway 后 OPTIONS 活体复验——单前缀 `execute`/`tasks`/`status` 均 200 且 Allow 正确，双前缀 404。契约 3 条已回 `implemented` 并写 `x-fix-2026-11-09`。

**D-CLI-2（P2，已绕行）**：`/api/v1/cognitive/health`（`CognitiveEngineHealthController`）被 `GatewayApplication.java:86-88` 的 excludeFilters 排除（与 ai-engine `CognitiveController` 同路径冲突）⇒ 经网关实测 **404**，仅能直连 aiming 服务。CLI 只允许经网关，故 `doctor` 的认知检查改用网关可达的 `listCognitiveModels`；契约 `getCognitiveHealth` 降为 `partial` 并登记 blocker。
