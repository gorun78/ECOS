## 四、P2 两项裁决（不立项，理由留痕）

1. **多平台网关（企微/钉钉/飞书投递）— 不立项**：ECOS 是企业 Web 控制台形态，外部消息网关与平台安全模型（RBAC/审计/写回治理）不匹配；架构红线「不新增 Docker 容器 / 不新增 Maven 模块」；外部 provider 须经接缝义务登记（参考 CronJob 的 W255 裁决先例）。需要消息触达时应走既有「任务中心 + 告警」通道，而非引入个人 IM 网关。
2. **轨迹数据飞轮 — 不立项（本批）**：hermes 的轨迹生成/压缩/评测闭环服务模型训练，ECOS 无训练链路；现有替代面已覆盖：`sys_agent_call_log` 计量台账、AgentEvaluator 评估报告（本批已增强为 LLM judge）、agent-loop SSE 帧/trace。后续如需评测回归集，复用评估报告导出即可，不新增 trajectory compressor 设施。

## 六、风险与遗留

1. llm/ontology/approval 节点依赖运行期属主端点（buszhi/ontology 可达），开发环境未起全量服务时该三类节点如实报「基址不可解析」，非缺陷。
2. RAG 检索腿在 kb-engine 不可用时降级为空上下文（不参与安全裁决），首字延迟不增加。
3. LLM judge 每题一次额外模型调用，评估成本翻倍；失败回落启发式，评估通道不中断。
4. CronJob 本地通道与 MCP 外部 provider 互斥（provider 可用时只走 provider，沿用 W255 防双调度裁决）。
5. `sessionMessages` 历史回灌窗口 20 条，超长会话由 token 预算裁剪承接。
