## 二、逐要素核对

### 2.1 场景模板 —— ✅ 可用，但只做「轻预填」

已落地：

- 表 `ecos_control.ecos_scenario_template`（V361），字段含 `definition_defaults`、`default_analysis`、`category`。
- 种子共 8 条：
  - V361：`空白场景` / `经营预测` / `成本诊断`；
  - V363：`市场分析会议` / `经营管理会议` / `总经理会议` / `技术管理会议` / `月度生产调度会议`（每条带目标陈述、成功标准、默认分析类型，如市场分析 `["CAUSAL","FORECAST"]`）。
- 端点 `GET/POST/PUT /api/v1/workspace/scenario-templates`（`ScenarioConfigController`），模板页 `#/workbench/templates` 与首页「场景模板」按钮均读真实端点。

缺口：

- 模板只预填「目标 / 成功标准 / 默认分析类型」，**不预置绑定**（数据、本体、知识、编排仍需手工装配）。会议模板因此更像「议程骨架」，不是「开箱即跑的场景包」。
- 模板与场景之间没有版本/来源追溯（场景不记录 `template_id`）。

### 2.2 场景上下文 —— 🟡 覆盖五域，规则/接口两类是空壳

**绑定面（定义页，2026-11-24 裁决后只保留 5 组）**

| 前端组 | binding_type | 后端候选源 | 实况 |
|---|---|---|---|
| 数据集 | `DATASET` | DW 近源/汇聚层 | 真实可选 |
| 本体对象 | `OBJECT_TYPE` | 本体实体（存 **id**，传 code 会 404） | 真实可选 |
| 知识库 | `KNOWLEDGE_BASE` | 知识库列表 | 真实可选 |
| 规则集 | `RULE_SET` | `bindingOptions.ts` 显式返回空并说明 | **0 行；后端只登记、无运行期解析** |
| 逻辑编排 | `PIPELINE` | AIP 编排列表 | 真实可选 |
| （已撤入口）智能体 / 安全策略 / 接口 | `AI_AGENT` / `SECURITY_POLICY` / `INTERFACE` | — | 后端枚举保留，前端不再提供入口；`/available` 无接口注册端点 |

**上下文装配与校验面**

- 预校验 `POST /api/v1/workspace/scenarios/{id}/pre-validate` 三行：`mind`（认知域 Mind 绑定，权威源 E1 detect）、`sandbox_coverage`（画布 ≥6 类资源）、`resources`（DATASOURCE / ONTOLOGY_ENTITY / KNOWLEDGE_ARTICLE / AGENT_PROFILE / SECURITY_POLICY / INTERFACE_REF）。
- 上下文构建 `POST /api/v1/cognitive/context/build`：`CONTEXT_SOURCE_TYPES = DATA_ASSET / ONTOLOGY / KNOWLEDGE / KNOWLEDGE_BASE / COGNITIVE / CAPABILITY`，每条必需资产要 id + version + 时点；要求**有对应 reader**，否则 fail-closed 503。
- 完整度/图谱：`ScenarioCompletenessController`（coverage 三边 MAPPING/EXTRACTION/COGNITION）、`ScenarioBindingLinkController`（链 DAG，缺失边按固定分母计），历史终态曾达 `coverage=1.0 / OK`。

缺口 / 风险：

- **规则上下文空转**：`RULE_SET` 可存不可用，规则库 0 行，且场景运行不消费规则。
- **接口绑定无端点**：`INTERFACE` 无注册列表，前端已撤入口。
- **Context Builder 源类型不全**：绑定里的 RULE_SET / AI_AGENT / SECURITY_POLICY / INTERFACE 无 reader，硬塞会 503；预填只取 datasets/objectTypes/knowledgeBases。
- **蓝图面整体摘除后的孤儿代码**：`blueprint/BlueprintPanel.tsx`、`BlueprintDetail.tsx`、`WizardShell.tsx`、`CapabilityPanel.tsx`、`CompletenessPanel.tsx`、`GapSeveritySummary.tsx`、`FrameworkPanel.tsx` 已无任何挂载点（仅 `ContextBuildPanel` 被 `ScenarioContextBuilder` 复用）。认知框架选择/计划校验随之失去 UI 入口。
- 认知上下文只剩读面：E1 detect、E2 operation-eval 供 L2 摘要；E3 hypotheses / E4 beliefs 在 `forecast` 页只读展示；四卡干预 UI 已于 2026-11-25 下线（`AdvancedDebugPanel` 已物理删除，`CognitionPanel` / `CognitiveRightPanel` 及 E1~E4 Tab 文件仍在磁盘但无挂载点；恢复按现行裁决需重新立项）。

### 2.3 心智模型 —— 🟡 五个真跑，但不能加也不能配

- 目录 `ecos_control.ecos_mental_model_registry`（V363）：`FIRST_PRINCIPLES / INVERT / PROBABILISTIC / COMPOUND / INCENTIVE`，每条 `pipeline_id` 由 V364 回填。
- 承载 `ecos_ai.ecos_aip_pipeline`（`aip-mm-*`）：单 llm 节点 + 各自 systemPrompt（四段式输出），`model=Qwen3.8-27B`，`tenant_id` 必须 `tenant-a`。
- 运行页可选任一模型；`ScenarioQuestionRunService#run` 缺 `pipelineId` 会 409 如实报「未接线」，执行失败落 `degraded=true`，不折成成功。
- 约束（易踩）：llm 节点 config **不要**写死 `prompt: "${input}"`；调 `/api/v1/llm/chat` 必须显式传 `model`；DAO 返回 snake_case。

缺口：

- 只有 `listActiveMentalModels` 读路径，**无心智模型 CRUD**（后端与 UI 都没有），新增模型只能改 DDL/种数据。
- 模型选择与问题意图无推荐关系（前端让用户自选，系统不按意图建议模型）。

### 2.4 运行模式 —— 🟡 三级并存，但入口与能力不对称

| 模式 | 现状 | 入口 |
|---|---|---|
| **L1 问题驱动（agent 式）** | 问题 → 意图识别 → 假设 → 选模型 → 跑 AIP 编排 → 建议；两段式 `prepare/run` | 运行页主面板 |
| **L2 算法分析** | `analysisType = CAUSAL / FORECAST / SIMULATION / PIPELINE`，落 `ecos_scenario_run` 锚点；预测走 `ForecastRunController` 9 条 mapping | **仅后端**；旧「按分析类型发起」折叠器已从运行页摘除，`scenarioAnalysisClient.ts` 无任何 UI 消费方 |
| **L3 研究循环（RD 模式）** | `research-runs/prepare|run|list|detail|compare` + `approve`；同步/异步（runtime-task，缺底座 501）；谱系 `parent_run_id/sota_run_id/branch_key/loop_index`；预算熔断 | 运行页折叠面板 |
| **沙箱** | 自建 `ecos-docker/research-sandbox` 容器；声明式算子（count/sum/avg/min/max/distinct_count），2026-11-25/26 扩到 Java + Python 标准库执行 | 由研究循环 executor 调用 |

| **高级模式** | 原「高级/调试」（运行编排 + 认知四卡）已于 2026-11-25 下线 | 无（能力下线，非遗漏） |

L3 沙盒边界（实施文档 v1.0 自查，2026-11-25）：

- 已做：非 root + 只读根 + tmpfs、无出网（DNS 黑洞）、CPU/内存/PID 限额、sha256 摘要、独立容器。
- 未做：出口白名单（现为全禁）、**超时强杀**、产物落 MinIO（表已建无写入路径）、审计留痕、研究专用短期令牌。
- RD-Agent 五步中只做 `hypothesize / evaluate / record`；`implement / sandbox_run` 的原生代码进化（CoSTEER）**未接入**——当前是「只读研究循环 + 受控代码执行」，不是自动代码进化。

### 2.6 六大类认知算法 —— 🟡 有点状真实实现，整体远未覆盖清单

先看「算法库」现状：`ecos_control.ecos_algorithm_registry`（V361）只有 **4 条 / 3 类**：

| id | 名称 | analysis_type | 实际承载 |
|---|---|---|---|
| `alg-causal-diagnose` | 因果诊断 | CAUSAL | `/cognitive/diagnose` |
| `alg-forecast-deterministic` | 确定性预测（六要素） | FORECAST | `/cognitive/forecast-runs/compute` |
| `alg-simulation-scenario` | 情景仿真 | SIMULATION | `/cognitive/scenario/simulate` |
| `alg-counterfactual` | 反事实推演 | SIMULATION | `/cognitive/counterfactual` |

**关键事实**：问题驱动运行里 `algorithmId` 只被**落库与回显**，执行的是心智模型编排（LLM），**算法没有被执行**。所以「六大算法」在当前主链路上是「推荐 + 登记」，不是「计算」。

逐类核对：

| 类 | 用户清单 | 现有 | 判断 |
|---|---|---|---|
| 1 信念与证据 | 贝叶斯 / PGM / 证据融合 / 置信度校准 / D-S 理论 | 方法目录有 `BAYESIAN_UPDATE`（`calibrated=false`、`probabilitySemantics=NONE`）；认知域有信念分布 E4 + 证据挂载；`MentalInvalidationDetector` 用「同 metric 相对漂移 > 15%」触发假设失效 | 🟡 只有离散贝叶斯更新的「目录位」与信念存取；无 PGM、无证据融合、无 D-S、无真正校准 |
| 2 因果 | SCM / PC、FCI / do-calculus / PSM、IPW / DR、因果森林 | `CausalDetector` 沿 KG 的 `CAUSES/AFFECTS/CORRELATES` 遍历（置信度 0.8 起、每层衰减 0.05）；`estimateCausalEffect` = `1/(1+最短路径长度)`；`CounterfactualSimulator` 做 do(A) 干预 + 蒙特卡洛 | 🟡 因果链追溯与反事实可用；**效应估计是路径启发式，不是 do-calculus**；无 SCM、无结构发现、无倾向评分/DR/因果森林 |
| 3 预测与状态估计 | 线性/GLM / ARIMA/指数平滑 / RF、GBDT / 时序 NN / 卡尔曼、HMM | 确定性「六要素」预测（口径/时点/快照/公式版本等）+ 预测-实际偏差对比；`GET /datanet/facts/action-outcomes` 读实际 | 🟡 公式型确定性预测；清单里的统计/机器学习/状态空间模型**均未实现** |
| 4 情景仿真与不确定性 | 蒙特卡洛 / 离散事件 / 系统动力学 / 敏感性 / 全局不确定性 | `CounterfactualSimulator`：同 seed 配对采样蒙特卡洛、按分布概率加权期望/方差；`ScenarioSimulatorServiceImpl` 做确定性 delta 推演；方法目录有 `SCENARIO_SENSITIVITY` | 🟡 蒙特卡洛与情景对比真实；无 DES、系统动力学、全局不确定性；敏感性只在方法目录（只读、不执行） |
| 5 决策与优化 | LP/MILP / 多目标 Pareto / AHP、TOPSIS / DP / RL | `Nsga2Optimizer`：真实 NSGA-II（快速非支配排序 + 拥挤距离 + SBX + 多项式变异），但目标函数是 DTLZ-1 **内置基准**，不是业务目标；`/api/v1/pareto/optimize` 有入参校验与落库 | 🟡 Pareto 有真算法但与场景业务脱节；`ParetoOptimizerService` 接口实现是**桩**（固定 0.2/0.25）；无 LP/MILP、AHP/TOPSIS、DP、RL |
| 6 结构 / 异常 / 假设验证 | 图遍历、路径、中心性 / 聚类 / 异常检测 / 假设检验校正 / 漂移变点 | KG 搜索、最短路径、因果路径构建；`MentalInvalidationDetector` 阈值漂移 | 🟡 有图遍历/路径；无中心性、聚类、异常检测、假设检验、统计变点检测；漂移是规则阈值不是算法 |

方法目录（`CognitiveMethodCatalogService`）另登记 5 个内置方法：`ABDUCTION`、`FALSIFICATION`、`VARIANCE_DECOMPOSITION`、`BAYESIAN_UPDATE`、`SCENARIO_SENSITIVITY`——**只读字典**，不参与执行，未校准。

结论：六大类里能称为「真实算法」的是 **蒙特卡洛反事实、确定性预测、NSGA-II（基准目标）、KG 因果遍历** 四项；其余是目录位、启发式或桩。与用户清单的 30 个算法相比，覆盖率低且**没有一条接入场景运行的执行链路**。

## 三、端到端链路现状（可复现的最小口径）

### L1 问题驱动（主链路，UI 可用）

```
输入问题
 → POST /workspace/scenarios/{id}/question-runs/prepare
     （意图识别 + 知识资产/文档假设 + 算法推荐 + 心智模型清单；不执行、不落库）
 → 用户逐条确认假设、选心智模型（可选算法）
 → POST /workspace/scenarios/{id}/question-runs
     （LLM 意图复算 → 装配 prompt/绑定 → AIP 编排执行 → 决策建议 → 落 ecos_scenario_run）
 → GET /question-runs/{a}/compare/{b}（两次运行逐字段对比）
```

已登记的真实耗时（2026-11-24 实施记录）：prepare 7.5s、第一性原理 run 19.4s、逆向 8.6s；`hypotheses/exec_trace/advice` 三列非空、`status=COMPLETED`。

### L3 研究循环（RD 模式，UI 折叠可用）

```
prepare → run(maxLoops 默认 3 / 硬上限 5，预算冻结，SANDBOX 落库)
 → 谱系（parent/sota/branch/loop）→ GET compare（含树关系）
 → approve（APPROVED 必带 approvalRef；独立审批表，未走 WAgent Candidate 通道）
```
