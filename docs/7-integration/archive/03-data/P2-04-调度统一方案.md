# P2-04 调度统一方案

> ECOS data-engine | 2026-08-24 | 跨模块（runtime+data-engine），本轮出方案，下轮实现

## 一、现状

| 任务 | 当前调度方式 | 问题 |
|------|------------|------|
| DQ 巡检 | DqScheduledTask `@Scheduled` + runtime-task 注册 | cron 不生效（runtime-task parseCronToDelay 占位返回 60000ms），双重调度 |
| Schema 检测 | SchemaChangeDetector `@Scheduled` | 同上 |
| Pipeline 执行 | PipelineTaskServiceImpl `new Thread()` | 裸线程，状态不可见 |
| Pipeline 定时 | PipelineScheduler 自建 cron 解析 | cron 不统一 |

## 二、根本问题

runtime-task 的 `TaskSchedulerServiceImpl.parseCronToDelay()` 是占位实现——所有 cron 表达式都返回固定 60000ms（1 分钟），所以各任务用 Spring `@Scheduled` 做实际触发，runtime-task 只做可见性管理。

## 三、方案

### 3.1 修 runtime-task cron 解析

```java
// Before (占位)
private long parseCronToDelay(String cron) {
    return 60000; // 所有 cron 都返回 1 分钟
}

// After (Quartz CronExpression)
private long parseCronToDelay(String cron) {
    CronExpression expr = new CronExpression(cron);
    Date nextFire = expr.getNextValidTimeAfter(new Date());
    return nextFire.getTime() - System.currentTimeMillis();
}
```

引入 `quartz` 依赖（仅 cron 解析，不引入 Quartz Scheduler 完整框架）：

```xml
<dependency>
    <groupId>org.quartz-scheduler</groupId>
    <artifactId>quartz</artifactId>
</dependency>
```

### 3.2 Executor 注册机制

现状 `DefaultTaskExecutor` 是空实现。方案：各引擎注册自己的 Executor。

```java
// runtime-task: TaskExecutorRegistry
public class TaskExecutorRegistry {
    private final Map<String, TaskExecutor> executors = new ConcurrentHashMap<>();
    
    public void register(String taskType, TaskExecutor executor) {
        executors.put(taskType, executor);
    }
    
    public TaskExecutor get(String taskType) {
        return executors.get(taskType);
    }
}
```

### 3.3 TaskType 枚举扩展

```java
public enum TaskType {
    GENERIC,          // 通用
    DQ_SCAN,          // DQ 定时巡检 (data-engine)
    SCHEMA_DETECT,    // Schema 变更检测 (data-engine)
    PIPELINE_EXECUTION, // Pipeline 执行 (data-engine)
    CDC_SYNC,         // CDC 实时同步 (data-engine, flagship)
    KB_INDEX,         // 知识库索引 (kb-engine)
    COGNITIVE_REASONING // 认知推理 (cognitive-engine)
}
```

### 3.4 接入步骤

#### DQ 巡检迁移

```java
// Before: @Scheduled + runtime-task 注册（双重调度）
@Scheduled(cron = "0 0 8 * * ?")
public void executeDailyScan() { ... }

// After: 只走 runtime-task
@PostConstruct
public void register() {
    TaskDescription desc = TaskDescription.builder()
        .taskType("DQ_SCAN")
        .cron("0 0 8 * * ?")
        .build();
    taskScheduler.scheduleTask(desc, () -> executeDailyScan());
}
// 删除 @Scheduled 注解
```

#### Schema 检测迁移

```java
// 同 DQ 巡检模式，taskType = "SCHEMA_DETECT", cron = "0 0 * * * ?" (每小时)
```

#### Pipeline 执行迁移

```java
// Before: new Thread(() -> executionEngine.execute(runId)).start();
// After:
TaskDescription desc = TaskDescription.builder()
    .taskType("PIPELINE_EXECUTION")
    .async(true)
    .build();
taskManagementService.submitAndExecute(desc, () -> executionEngine.execute(runId));
```

### 3.5 状态回调

```java
// 执行完成 → 更新 runtime-task 状态 → 监控可见
taskManagementService.submitAndExecute(desc, () -> {
    try {
        executionEngine.execute(runId);
        taskManagementService.updateStatus(taskId, TaskStatus.COMPLETED);
    } catch (Exception e) {
        taskManagementService.updateStatus(taskId, TaskStatus.FAILED, e.getMessage());
    }
});
```
