# PMO-3I: data-workbench 菜单精简 + 废弃路由清理

> **架构铁律**: 必须遵循 [ECOS架构铁律](../../ARCHITECTURE-RULES.md)
> 来源: 肖国荣 | 日期: 2026-08-25
> 铁律: ①架构规则 4.3 i18n 禁硬编码中文 ②删路由前 grep 确认无组件引用 ③功能合并不改后端 API 路径 ④单文件 ≤300 行

## §背景

DataWorkbenchLayout 内部 9 Tab 有冗余：syncs 与 pipelines 做同一件事（sync 本质是 task_type=SYNC 的 pipeline task），pipelines 列表与 pipeline-builder 编辑器分离导致用户不知道去哪建管道，guide 引导页无用。main.tsx 有 9 条 `<Navigate to="/data-workbench">` 废弃 redirect 路由（旧 URL 残留），增加路由表噪音。

本轮精简菜单 + 清理废弃路由，数据工作台入口从 9 Tab → 6 Tab，全局路由表瘦身。

## §菜单精简方案

| 原 Tab | 动作 | 理由 |
|--------|------|------|
| guide | **删除** | 引导页无用，用户不需要教程 |
| connections | 保留 | 数据源管理，核心功能 |
| syncs | **合并→pipelines** | sync = task_type=SYNC 的 pipeline task，合并后 pipelines Tab 内用 taskType 筛选区分 |
| pipelines | **合并→pipeline-builder** | pipelines 列表作为 pipeline-builder 的入口页（左侧列表+右侧编辑器），不再独立 Tab |
| pipeline-builder | 保留（含列表入口） | 核心功能，列表+编辑器合一 |
| health | 保留 | DQ 健康检查 |
| lineage | 保留 | 数据血缘 |
| sql-query | 保留 | SQL 查询 |
| engine-config | 保留 | 引擎配置 |

**最终 6 Tab**：connections / pipeline-builder / health / lineage / sql-query / engine-config

## §废弃路由清理

main.tsx 中 9 条 `<Navigate to="/data-workbench" replace />`，对应旧 URL 已无组件引用：

| 废弃路由 | 原 URL | 处理 |
|---------|--------|------|
| catalog | /catalog | 删除 redirect + 删除 import DataCatalog |
| dataset_explorer | /dataset_explorer/:assetId? | 删除 redirect + 删除 import DatasetExplorer |
| lineage | /lineage | 删除 redirect（lineage 功能在 data-workbench 内部 Tab） |
| dq_dashboard | /dq_dashboard | 删除 redirect + 删除 import DataQualityDashboard |
| datalake | /datalake | 删除 redirect + 删除 import DataLake |
| datasources | /datasources | 删除 redirect + 删除 import DataSourceManager |
| pipeline | /pipeline | 删除 redirect + 删除 import PipelineBuilder |
| workbook | /workbook | 删除 redirect + 删除 import CodeWorkbook |
| task_center | /task_center | 删除 redirect |

## §Task

### T1 — DataWorkbenchLayout Tab 精简（9→6）

**文件**：`src/pages/DataWorkbenchLayout.tsx`

**操作**：
1. TAB_CONFIG 删除 guide / syncs / pipelines 三项，保留 connections / pipeline-builder / health / lineage / sql-query / engine-config
2. pipeline-builder Tab 改为「列表+编辑器」双面板布局：左侧 Pipeline 列表（含筛选：全部/同步任务/转换任务），右侧 PipelineFlowEditor。选中列表项→右侧加载编辑，点「新建」→右侧空白编辑器
3. 原 syncs Tab 的同步任务数据（fetchDataSyncTasks）合并进 pipeline-builder 列表，用 taskType=SYNC 标记区分
4. 删 guide Tab 后，默认选中 connections Tab
5. i18n：新增/修改的 Tab label 走 `t("dw.xxx")`，不硬编码中文

**验收**：TAB_CONFIG 恰好 6 项；前端 `/#/data-workbench` 显示 6 个 Tab；pipeline-builder 左侧列表显示真实 Pipeline 定义 + 同步任务；0 硬编码中文。

### T2 — main.tsx 废弃路由删除

**文件**：`src/main.tsx`

**操作**：
1. 删除 9 条 `<Navigate to="/data-workbench" replace />` 路由行
2. 删除对应的 6 个无用 import（DataCatalog / DatasetExplorer / DataQualityDashboard / DataLake / DataSourceManager / PipelineBuilder / CodeWorkbook）
3. grep 确认删除的组件未被其他文件引用后再删 import

**验收**：`grep -n "Navigate to=\"/data-workbench\"" src/main.tsx` = 0；`npm run lint` 0 新增错误（被删组件若有其他引用会报错）。

### T3 — 旧 Tab 组件清理

**操作**：
1. T2 删 import 后，grep 确认以下文件是否还有其他引用，无引用则 `git rm`：
   - `src/pages/DataCatalog.tsx`
   - `src/pages/DatasetExplorer.tsx`
   - `src/pages/DataQualityDashboard.tsx`
   - `src/pages/DataLake.tsx`
   - `src/pages/DataSourceManager.tsx`
   - `src/pages/PipelineBuilder.tsx`（注意：不是 data-workbench 下的 PipelineFlowEditor）
   - `src/pages/CodeWorkbook.tsx`
2. data-workbench 下被删 Tab 的组件文件（如有独立的 SyncsTab.tsx / GuideTab.tsx）也 git rm

**验收**：`git status` 显示删除文件；`npm run lint` 0 错误。

### T4 — 编译 + dogfood 回归

**操作**：
1. `npm run lint` 通过
2. dogfood：6 Tab 逐一点开，connections 显示真实数据源、pipeline-builder 列表+编辑器联动、health/lineage/sql-query/engine-config 正常
3. 4 主题切换正常

**验收**：lint 0 错误 + 6 Tab dogfood 全 PASS + 0 硬编码颜色（若 PMO-3H 已完成则继承）。

## §执行顺序

```
T1（Tab 精简）→ T2（删路由）→ T3（删旧组件）→ T4（回归）
```

T1 先做（改 Layout），T2 删路由依赖 T1 确认无引用，T3 清理文件依赖 T2 删 import 后的 grep 结果，T4 回归。

## §禁止清单

1. 改后端 API 路径（功能合并只改前端 Tab 结构，后端不动）
2. 硬编码中文（架构规则 4.3）
3. 硬编码 Tailwind 颜色（架构规则 4.1）
4. 删路由前不 grep 确认引用（会导致编译报错）
5. 跨 Phase 预创建文件
