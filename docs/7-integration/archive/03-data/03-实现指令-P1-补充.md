> **架构铁律**: 必须遵循 [ECOS架构铁律](../../ARCHITECTURE-RULES.md)
> 来源: 肖国荣 | 日期: 2026-08-24
> 铁律: ①架构规则 2.4「data-engine 查询前调 RLS 注入行级过滤，不得绕过」②默认 DENY（RLS 不可用拒绝，不降级放行）③引擎间只调 REST 不调 Impl

## §背景

PMO 已执行 PMO-3A（P0：B1/B2/B3 修复）+ PMO-3B 部分（B5/B6/B7/B8），但 **T8（RLS 安全接入）缺失**——执行的是旧版指令，无 T8。经复验确认：`QueryController.execute()` 直接调 `queryExecutionService.execute()` 查库，零安全调用。这是架构规则 2.4 的强制项，必须补。

## §复验结论（已核实，无需改）

- **B4 血缘端点**：误报。DataLineageController 第 28 行一直有裸 `@GetMapping` 根路径（`?datasourceId&tableName`），复验 curl 200 ✅
- **B5 双系统**：结论正确。前端 3 处引用 `/api/v1/pipeline/definitions`（data-workbench/api.ts L11、aiworkbench/api.ts L131、api.ts L1005），PipelineController 有消费，保留
- **B3 三滤波器**：`/api/v1/datanet/*` 实际通（SecurityConfig permitAll + ClearanceInterceptor 走 PATH_RULES `/api/v1/`→L1，认证用户放行），非 404/403 bug

## §实现要点

1. **调 REST 不调 Impl**（架构规则 2.1）：data-engine 用 RestTemplate 调 `http://localhost:8080/api/security/rls/apply`（或 18081），禁止直接注入 `RowLevelSecurityServiceImpl`。
2. **默认 DENY**（架构规则 2.4 第 6 条）：REST 调用异常/超时/返回空 condition → 返回 403，禁止 catch 后继续裸查。
3. **注入安全**：rlsCondition 来自 security-engine 可信输出，用 SQL 子查询包裹避免破坏原 SQL 语义。
4. **不裸返全列**：CLS 列级过滤/脱敏 的完整对接点已列入 P2-03 安全对接清单（PMO-3C T11），本 Task 只接 RLS（行级）。

## §禁止清单

1. 禁止在 data-engine 内自建 RLS 逻辑（架构规则 2.4 第 7 条，一律走 security-engine REST）
2. 禁止 RLS 失败时降级放行（架构规则 2.4 第 6 条默认 DENY）
3. 禁止直接注入 security-engine 的 Impl Bean（架构规则 2.1 引擎间只调 API）
