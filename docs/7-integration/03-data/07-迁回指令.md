# PMO-3E: data-engine 架构归位（DqController 迁回 + CeosCompatController 拆分真实化）

> **架构铁律**: 必须遵循 [ECOS架构铁律](../../ARCHITECTURE-RULES.md)
> 来源: 肖国荣 | 日期: 2026-08-24
> 铁律: ①数据接入/DQ 归 data-engine（土），违反五对象·五行即迁回 ②CeosCompatController 内存 mock 必须真实化，禁止继续用假数据 ③API 路径不变，前端零改动

## §背景

摸底发现架构错位：数据连接（CeosCompatController）散落在 ontology-engine，DQ（DqController）散落在 buszhi。且 CeosCompatController 是**内存 mock**（seedData 硬编码 doris/postgresql 假数据），前端 connections/syncs Tab 对接的是假数据，不是 data-engine 真实的 td_datasource 表。

本轮迁回 + 真实化，消除架构错位，前端对接真实数据。

## §禁止清单

1. 禁止继续用内存 mock / 假数据冒充真实数据
2. 禁止改 API 路径（前端零改动，只改后端归属 + 数据源）
3. 禁止在 data-engine 内直接操作其他引擎表（架构规则 3.3）
4. 跨引擎只调 REST 不调 Impl（架构规则 2.1）
5. 新增 Bean 加 `ecos` 前缀、过三滤波器

## §Task

### T1 — DqController + DqService + DqRepository + Entity 迁回 data-engine（纯移动）

**文件**（5 个，769 行，从 buszhi 移到 data-engine）：

| 原路径（buszhi/workflow/） | 目标路径（data-engine/quality/） |
|------|------|
| DqController.java | controller/DqController.java |
| DqService.java | service/DqService.java |
| DqRepository.java | repository/DqRepository.java |
| DqRuleEntity.java | entity/DqRuleEntity.java |
| DqIssueEntity.java | entity/DqIssueEntity.java |

**操作**：包名 `com.chinacreator.gzcm.buszhi.workflow` → `com.chinacreator.gzcm.engine.data.quality`；`@RequestMapping("/api/v1/ecos/dq")` 保持不变；Gateway 的 excludeFilters/ComponentScan 相应调整（排除 buszhi 旧位置，纳入 data-engine）。

**验收**：`curl http://localhost:8080/api/v1/ecos/dq/rules` 200；buszhi 下无 Dq*.java 残留。

### T2 — CeosCompatController integration 端点真实化（迁回 data-engine）

**现状**：`GET /api/integration/metadata` 返回内存 mock 的 connections/syncTasks（seedData 硬编码）。

**操作**：在 data-engine 新建 `IntegrationMetadataController`（`@RequestMapping("/api/integration")`），把 connections 改为调 `DataSourceService`（td_datasource 真实表）+ `MetadataCollectionService` 采集的 resources，syncTasks 改为调 `PipelineTaskService` 真实任务列表。字段映射参照前端 `api.ts` 的 `mapDsToConn`（datasourceId→id、datasourceName→name、datasourceType→type、connectionConfig 解析 host/port/database）。删除 CeosCompatController 里的 connections/syncTasks 内存 List + seedData 假数据。

**验收**：`curl http://localhost:8080/api/integration/metadata` 返回 td_datasource 表真实数据（非硬编码 doris/postgresql）；建 1 个数据源后 metadata 列表 +1。

### T3 — CeosCompatController lineage 端点真实化（对接 DataLineageService）

**现状**：`POST /api/lineage/parse` + `GET /api/lineage/impact` 返回内存 mock 血缘。

**操作**：lineage 端点改为调 data-engine 的 `DataLineageService`（已有 JSqlParser 字段级血缘真实实现），删除 CeosCompatController 里的 lineage 内存 Map + seedData 血缘假数据。

**验收**：`curl http://localhost:8080/api/lineage/impact` 返回真实血缘解析结果（非种子假数据）。

### T4 — CeosCompatController ontology 端点归位 + 删除 CeosCompatController

**现状**：`/api/ontology/mappings` + `/export` + `/entities/{type}/instances` 是本体映射（内存 mock）。

**操作**：ontology 端点迁回 ontology-engine 真实本体（如果 ontology-engine 已有对应端点，则直接删除 CeosCompatController 的 ontology 部分；如果缺失，记录缺口不阻塞）。完成 T2/T3/T4 后，`CeosCompatController` 整体删除（拆分吸收完毕）。

**验收**：`grep -r "CeosCompatController" ecos_backend` 无残留（或仅历史注释）；`curl /api/ontology/mappings` 要么 200（归位后）要么明确记录缺口。

## §执行顺序

```
T1（DqController 纯移动）→ T2（integration 真实化）→ T3（lineage 真实化）→ T4（ontology 归位 + 删除兼容层）
```

T1 独立，可先做；T2/T3/T4 是对 CeosCompatController 的拆分，顺序执行。
