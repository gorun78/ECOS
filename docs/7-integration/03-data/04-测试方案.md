## 一、测试策略

**前后端一起联调，不以「后端端点 200」为通过标准。**

三层交叉验证：
1. **前端 dogfood**（browser_exec）走完整用户流，每个交互后查控制台错误 + 后端日志 + DB 落库
2. **后端 curl + JWT** 覆盖 dogfood 没点到的端点
3. **数据一致性**：前端显示 vs 后端返回 vs DB 实际，三者一致才算过

**验收铁律**（对应需求文档十、禁止）：DQ 巡检要看 `ecos_quality_evaluation` 真实落库；Pipeline 要看 run 状态 QUEUED→RUNNING→COMPLETED 流转；血缘要看 JSqlParser 解析出的真实 nodes/edges（非空）；RLS 要看不同租户查同表返回行数不同。

## 三、测试范围（按 ETL 需求文档功能域）

### 3.1 数据接入（需求文档二、三：4 类 + 及时性）

| 接入类型 | 载体 | 本轮测试 |
|---------|------|---------|
| 关系型数据库 JDBC（6 种） | runtime-access JdbcConnector | ✅ 实测（PG 为代表） |
| 文件 CSV/Excel | CsvConnector | ✅ 实测 |
| REST API | RestApiConnector | ✅ 实测 |
| 实时 CDC | FlinkCdcConnector（flagship） | 📄 设计验证（P2-02 已出），本轮不实跑 |

**及时性**：全量（JDBC 分页全量）✅ 实测；增量（时间戳 `updated_at > last_sync`）✅ 实测；实时 CDC 📄 设计验证。

### 3.2 元数据采集 + 目录 + 分类（需求文档 P0-1/P1-1）

- 元数据采集：collect → resources 列表 → 字段 → 预览
- 数据目录：search / dashboard / register / stats
- 分类管理：td_data_category 建表 + CRUD + 树

### 3.3 数据血缘（需求文档 P0-1 B4）

- 字段级 SQL 解析（JSqlParser）：nodes/edges/build/pipeline/{taskId}
- 根路径 `GET /lineage?datasourceId&tableName`

### 3.4 数据质量（需求文档 P0-2/P1-2）

- 规则 CRUD + evaluate + evaluateAll + history
- UNIQUE（重复检测）/ CUSTOM（表达式）真实评估（非硬编码 true）
- DQ 定时巡检（表名 `ecos_quality_rule` + 一次性全量）

### 3.5 Schema 变更检测（需求文档 P0）

- 每小时对比 information_schema + 列级 diff + SHA256
- changes 查询 + acknowledge

### 3.6 Pipeline（需求文档 P0-3/P1-3/P2-1/git 版本管理）

- 任务 CRUD + run/cancel + runs 历史 + steps 详情
- 异步执行（状态流转 QUEUED→RUNNING→COMPLETED）
- 节点真实化（SOURCE_JDBC 连外部源 / TRANSFORM_SQL 真实行数）
- **git 版本管理**：commit/pull/load/branches/branch（PipelineGitService + GitService）
- 双系统梳理：`/api/v1/pipeline`（前端在用，保留）

### 3.7 查询 + UDF + Copilot + Settings（需求文档 P1）

- QueryController：execute/schema/history/template(s)
- UdfController：register/list/test/convert
- PipelineCopilotController：chat
- DataEngineConfigController：settings/defaults/refresh（可配置性 L2）

### 3.8 安全接入（需求文档 P0-4/6.4，架构规则 2.4 强制）

- **RLS 行级过滤**：查询前调 `/api/security/rls/apply` 注入 WHERE（T8）
- **默认 DENY**：RLS 不可用 → 403 不降级
- CLS 列级/脱敏/审计：P2-03 清单已出，本轮验证对接点（不强制全接）

### 3.9 可配置性（需求文档 6.8）

- L1 yml 默认 / L2 引擎配置表（settings）/ L3 Pipeline 级覆盖

### 3.10 版本差异（需求文档 6.7）

- 本轮 standard 版验证（PG + JDBC/CSV/REST + 批处理）
- enterprise/flagship 差异项（Neo4j 血缘落图 / Doris / CDC）为 profile 裁剪，本轮仅确认不报错

## 四、测试方法

### 4.1 前端 dogfood 流程

```
登录 → 数据工作台 → 数据源接入（PG 连接→测试→元数据采集）
→ 数据目录（表/字段/分类树）→ 血缘（选表看 DAG）
→ DQ（建规则→评估→巡检）→ Pipeline（建 2 节点→run→状态）
→ SQL 查询 → 控制台查错
```

### 4.2 后端 curl 覆盖

dogfood 没点到的端点（Schema 检测、UDF、Copilot、Settings、git 版本管理）用 curl 逐个验证。

### 4.3 前后端数据一致性

| 数据 | 前端 | 后端 | DB |
|------|------|------|----|
| 数据源 | 列表 | /api/v1/datanet/datasource | td_datasource |
| DQ 规则 | 建规则 | /quality | ecos_quality_rule |
| Pipeline | run 后状态 | /runs/{runId} | ecos_pipeline_run |
| 分类 | 树 | /category/tree | td_data_category |
