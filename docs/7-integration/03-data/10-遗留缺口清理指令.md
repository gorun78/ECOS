## §背景

PMO-3G 验收后遗留 3 个缺口。肖总实测确认：硬编码颜色 **448 处**（PMO-3G 报告少报为 192），遍布 data-workbench 全目录 30 个文件。data.ts 是死代码（matrixData 全仓 0 引用）。DataWorkbenchLayout 330 行超架构规则 4.6 的 300 行上限。

本轮一次清干净，验收标准是 **grep 硬编码颜色 = 0**。

## §颜色替换指引

读 `src/components/ThemeContext.tsx` 的 `styles` 完整定义，按语义映射：

| 硬编码 | styles 字段 |
|--------|-----------|
| `bg-white` / `bg-slate-900` / `bg-slate-800` 等背景 | `styles.cardBg` / `styles.appBg` / `styles.sidebarBg` |
| `border-gray-200` / `border-slate-200` 等边框 | `styles.cardBorder` / `styles.sidebarBorder` |
| `text-gray-900` / `text-slate-600` 等文字 | `styles.cardText` / `styles.cardTextMuted` |
| 强调色（accent） | `styles.accentText` / `styles.accentBg` / `styles.accentBorder` |

**语义色**（success/warning/danger/info，如血缘节点状态、DQ 结果、Toast 级别）：必须主题感知。light 用 `bg-xx-50 text-xx-700`，dark 用 `bg-xx-500/10 text-xx-300`。ThemeContext 若无语义色 token，补 `styles.success/warning/danger/info` 四组（含 bg + text），不要散落硬编码。

参考 `pages/DataWorkbenchLayout.tsx` 已正确使用 styles 的写法。

## §禁止清单

1. 拆文件后改逻辑（只拆不改）
2. 硬编码颜色换新硬编码（必须走 useTheme styles 或语义色 token）
3. 删色导致功能退化（如画布节点失去状态色）
4. 自定义 SVG（架构规则 4.2，只用 lucide-react）
5. 引入新的 i18n 硬编码中文
6. 跨 Phase 预创建文件
