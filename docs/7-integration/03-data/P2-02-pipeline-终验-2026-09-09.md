## 1. 环境与执行链路

### 1.1 ECOS 链路（生产模式）

```
HTTP POST /api/v1/pipeline/definitions/{id}/execute
  ↓
PipelineController.executeDefinition
  ↓
PipelineService.checkAbacBeforeExecute(id)   # ABAC 前置裁决
  ↓
PipelineSecurityService.evaluateExecute(id)   # 调 security-engine
  ↓
  → 若 security-engine 不可用 → DENY（默认 fail-close，铁律 §2.4-6）
  → 若 OPA rbac 拒 → BusinessException(403, "Pipeline 执行被 ABAC 策略拒绝: DENY")
  ↓
ITaskManagementService.submitTask + executeTask
  ↓
PipelineTaskExecutor.execute
  ↓
PipelineExecutionService.executePipeline
  ↓
按 DAG 拓扑序（Kahn）串行执行节点，按 switch 分发 9 种 type
```

调试链路（绕过 ABAC，直接调 PipelineDebugService）：
```
POST /debug/sessions           → 创建会话（state=created）
POST /debug/{id}/step          → 单步执行下一节点（state=running）
POST /debug/{id}/continue      → 继续到下一断点/结束
POST /debug/{id}/stop          → 中止（state=cancelled）
DELETE /debug/{id}             → 删除会话
```

### 2.3 /execute 被 ABAC 拒绝（关键发现）

curl `POST /api/v1/pipeline/definitions/{id}/execute` → **HTTP 400 + code=403 + "Pipeline 执行被 ABAC 策略拒绝: DENY"**

**根因诊断（5 项已排除，1 项定位）**：
1. ✅ OPA 容器 Up + :8181 API 直连可达，`POST /v1/data/ecos/rbac/allow` 用 `{input:{action,role}}` 正确返回 `{"result":true/false}`
2. ✅ OPA 已加载 `ecos.rbac` policy（`/v1/policies` 可见 strategy 含 pipeline.execute 分支）
3. ✅ gateway :8080 UP（fat-JAR PID 30632，21:00 启动）
4. ✅ token 合法（admin/admin123 → roles=[ROLE_SUPER_ADMIN, admin, SECURITY_AUDITOR]）
5. ✅ `auth.whitelist.paths` 已含 `/api/v1/pipeline/**` 双路径
6. ❌ **PipelineSecurityService.evaluateExecute POST `/api/v1/security/policy-engine/evaluate` 被 Spring Security 拦 403 Forbidden**（gateway 20:54 log 实证：`/api/v1/security/policy-e 403`）

**结论**：当前 OPA `rbac.rego` 只有 4 条规则（pipeline.execute / read / list / get），没有针对 `policy-engine/evaluate` endpoint 的 path 豁免。`PipelineSecurityService` 设计的 `securityBaseUrl` 路由需要 `SecurityConfig` 端点放行。

**已知遗留建议**：
- A. 在 `SecurityConfig.permitAll()` 加 `/api/v1/security/policy-engine/**` 路径，或
- B. 给 OPA 策略加 `pipeline.execute` 改为 `input.role in ["system", "admin", "ROLE_SUPER_ADMIN"]` 让 admin 角色放行

**额外发现 bug**：`PipelineExecutionService.executeTransformSql()` 使用 `JdbcTemplate.update(sql)` 但接受 `SELECT` 型 SQL 时 spring 不支持（`update` 仅 DML），导致 step2 真实语义错误。建议按 `sql.startsWith("SELECT")` 分流 `queryForList` vs `update`。

## 3. ABAC OPA 策略当前规则（rbac.rego）

```rego
package ecos.rbac
default allow = false

# 仅 role=system 允许 pipeline.execute
allow { input.action == "pipeline.execute"; input.role == "system" }

allow { input.action == "read";  input.role != "" }
allow { input.action == "list";  input.role != "" }
allow { input.action == "get";   input.role != "" }
```

→ **当前策略下只有 `system` 角色能 pipeline.execute；admin/SECURITY_AUDITOR 都被拒**。这是策略设计选择**不是 bug**，QA 立场仅做忠实记录。

### 启动顺序

### 登录 + 拿 token
```powershell
$body = '{"username":"admin","password":"admin123"}'
$r = curl.exe -s -X POST "http://localhost:8080/api/v1/auth/login" -H "Content-Type: application/json" -d $body
$r | ConvertFrom-Json | Select-Object -ExpandProperty data | Select-Object -ExpandProperty accessToken
```

### 创建 pipeline → 执行 → 轮询
```powershell
# 创建（body 含 nodes 数组 + edges 数组）

# 执行（会走 ABAC → 当前 OPA 策略下 admin 角色被拒，见 §3）

# 轮询 task 状态（taskId）
curl.exe "http://localhost:8080/api/v1/pipeline/tasks/$taskId/status" -H "Authorization: Bearer $token"

# 查执行历史（按 definitionId）
curl.exe "http://localhost:8080/api/v1/pipeline/definitions/$id/executions?page=1&pageSize=10" -H "Authorization: Bearer $token"
```
