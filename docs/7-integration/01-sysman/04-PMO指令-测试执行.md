## 一、分工

| 角色 | 职责 |
|------|------|
| ECOS-QA | 测试数据准备/清理 + 执行协调 + 测试报告 + 数据一致性验证（前端显示 vs 后端返回 vs DB 落库） |

## 二、执行流程（7 步，严格顺序）

1. **环境准备**：确认 Gateway 8080 在线；前端 `npm run dev` 起 3000
2. **测试数据准备**（QA）：按 `02-测试方案.md` 二·五 准备 `test_` 前缀数据（test_user_01~04 / test_role / test_tenant / test_dict），记录关键配置当前值
3. **用例执行**：P0 登录安全（6 个）→ P1 核心（用户/配置/角色/租户字典/端点）→ P2 体验 → P3 stub。**P0 必须全过才进 P1**
4. **问题记录**：每个失败用例记录（编号/现象/复现步骤/预期/实际）到 `04-测试报告.md`
5. **修复**（FE/BE）：发现 bug 当场修，每 bug 一个 commit（message `I1-fix: 描述`）
6. **复验**：修复后重跑失败用例，回填结果
7. **测试数据清理**（QA）：按 `02-测试方案.md` 二·五 清理，`test_%` = 0，admin 解锁可登录

## 三、验收标准

1. P0 登录安全 6 用例全过（L1 锁定 / L2 首次改密 / L3 强度 / L4 过期）
2. P1 核心 26 用例 ≥ 90% 通过，失败项修复或明确记录
3. P2 体验 6 用例逐项确认（修复或记录为后续排期）
4. P3 stub（AbacPepService）结论明确：该实现→补；纯占位→记录缺口
5. 测试数据清理完成（test_% = 0，admin 可正常登录）
6. 回归：全量编译 BUILD SUCCESS + 铁律5 仍全绿（E2 不回退）
7. 交付物：`04-测试报告.md` + `05-修复记录.md` 回填完整

## 四、禁止清单

- ❌ 跳过 P0 直接测 P1（登录锁死后续全废）
- ❌ 测 L1 锁定后不解锁 admin（影响后续用例，测完立即清 locked_until）
- ❌ 测试数据不用 `test_` 前缀（清理时误删真实数据）
- ❌ 改端点路径 / 响应结构 / SQL 语义
- ❌ 修复 bug 时顺手重构 / 改架构 / 改样式
- ❌ stub 一律补实现（先判断：有表+有消费者→补；纯占位→记录缺口）
- ❌ 动 E2 下沉成果（Controller 无 JdbcTemplate 状态不能破坏）
