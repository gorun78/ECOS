## §3 现场执行结果

### 3.1 阻断 (P0 Blocker)

```
[FAILOVER] 19:13:26  o.s.b.d.LoggingFailureAnalysisReporter:
Parameter 0 of constructor in com.chinacreator.gzcm.engine.ai.service.CognitiveService
required a bean of type 'com.chinacreator.gzcm.cognitive.impl.RuleEngine' that could not be found.
```

**根因**: `ai-engine-impl/CognitiveService.java` 构造器注入 `cognitive.impl.RuleEngine` (impl 类, 不是 api interface), 违反 架构铁律 §2.1 「引擎间只调 API 不调 Impl」。Spring Boot 启动时找不到 `RuleEngine` bean (只有 `RuleEngine` 在 `cognitive-engine-impl`, ai-engine 跨模块引用被上一波 R 系列返工拆分命运断裂)。

**冲突**: 修法应该在 cognitive-engine-api 增加 `IRuleEngine` 接口 (api/impl/boot 三模块), 让 ai-engine-impl 的 CognitiveService 改注入 `IRuleEngine`, 不在 QA 阶段修改 Java (约束 #4 + 重复限制)。

## §4 阻断处理与建议

### 4.1 P0 Blocker (当前)

**位置**: `ecos_backend/engine/ai-engine/ai-engine-impl/src/main/java/com/chinacreator/gzcm/engine/ai/service/CognitiveService.java`
**行**: 26, 33 (字段 + ctor)
**问题**: `import com.chinacreator.gzcm.cognitive.impl.RuleEngine` — impl 模块跨引用, **违反 架构铁律 2.1 「引擎间只调 API」**
**修法** (Fullstack):

```java
// cognitive-engine-api/.../api/IRuleEngine.java (新增)
public interface IRuleEngine {
    List<MatchedRule> evaluate(Map<String, Object> facts);
}

// cognitive-engine-impl/.../impl/RuleEngine.java
// + implements IRuleEngine + @Component 已存在
// ai-engine-impl/.../service/CognitiveService.java
- private final RuleEngine ruleEngine;
+ private final IRuleEngine ruleEngine;
```
**修复代价**: ~15 min (cognitive-engine-api 改 pom → mvn install cognitive-engine-api → 改 ai-engine-impl) | **风险**: 低
