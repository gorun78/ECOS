# 跨引擎编排层设计（OAG 8 步 → 实例级可执行管线）

> 文档编号：ECOS-DESIGN-COG-03 | 版本 v1.0 | 2026-09-01
> 作用：Wave-3B「跨引擎编排层重写」路由图。基于 PMO-33 已落地的 `CognitivePipelineExecutor`，向前输出"OAG 8 步 → 8 个具体节点"的精确契约，向后衔接 Wave-3B 任务清单。
> 依赖：PMO-32（决策五元组）已实施 / PMO-33 骨架已实施 / PMO-35 SpEL 评估 / PMO-34 文档解析

---

## 一、背景

PMO-33 已交付 **可执行编排骨架**：`CognitivePipelineExecutor`（Kahn + 重试 + 并行 + 状态机 + 溯源）+ `EngineCapabilityRegistry`（五类节点路由）+ `CognitivePipelineController`。但现状是 **抽象的 5 节点类型（INGEST/EXTRACT/KG/REASON/DECISION）**，与 ai-engine 侧展示的 **OAG 8 步（需求解读→任务拆解→本体建模→知识抽取→图构建→混合推理→策略生成→决策落地）** 之间 **没有显式映射**，也没有 **面向实例**（一条具体业务需求）的端到端示例。

本次设计：
1. 把 OAG 8 步逐一对齐到一个 `CognitivePipelineNode`，节点类型扩展（**只增**，不删现有 5 种）。
2. 给出 8 步的 **输入 / 输出 / 上游依赖 / 节点 config 形态 / 失败回滚策略**。
3. 给出 **Whisker/Kahn 拓扑** 实际分层（哪些并行）。
4. 给出 **失败降级矩阵**：任一步失败时的 expected observable state。

> 铁律引用：[架构铁律 0.3/2.1](../../ARCHITECTURE-RULES.md)：cognitive 不新增 DB 表（推理实时计算），跨引擎只调 API。本设计内 **零新增 DB 表**（管线执行仍处于 `PipelineExecution` 内存态，持久化到 `ecos_provenance_entry` 由 PMO-33 已建 `ProvenanceService` 完成）。

## 三、OAG 8 步 → 节点 映射

| OAG 步 | 节点 `nodeId` 建议前缀 | 节点类型 `nodeType` | 引擎 / 能力来源 | 输入（节点 config） | 输出（写入 `nodeOutputs[nodeId]`） |
|:--:|----|:--:|------|------|------|
| 1 | `s1_intake` | **OAG_INTAKE** [TBD: 新建] | cognitive-engine 本地（`OagIntakeService` [TBD: 新建]） | `{raw_request: "...", domain: "finance"}` | `{intent_id, slot_map, structured_request{metric, deviation, ...}}` |
| 2 | `s2_plan` | **OAG_PLAN** [TBD: 新建] | cognitive-engine 本地（`OagPlannerService` [TBD: 新建]） | `{intent_id, structured_request}` | `{plan_id, sub_tasks[{sub_task_id, description, depends_on[]}]}` |
| 3 | `s3_ontology` | **ONTOLOGY** [TBD: 新建] | ontology-engine REST `POST /api/v1/ontology/entities/search` | `{sub_task_id, entity_hints[]}` | `{ontology_snapshot_id, entity_ids[]}` |
| 4 | `s4_extract` | EXTRACT（已有） | kb-engine REST `POST /api/v1/knowledge/extract/run` | `{"source": "doc", "files":[...]}` | `{extraction_id, candidate_entities[], candidate_rules[]}` |
| 5 | `s5_build` | KG（已有） | kb-engine REST `POST /api/v1/knowledge/graph/build` | `{"subgraph_id":..., "candidate_ids":...}` | `{kg_ids[], edge_count}` |
| 6 | `s6_reason` | REASON（已有） | cognitive-engine 本地 `KnowledgeReasonerService` | `{"reasonType":"HYBRID", "query":..., "facts":{}}` | `{reasoner_result, causal_depth>=3, reasoning_path}` |
| 7 | `s7_strategy` | **OAG_STRATEGY** [TBD: 新建] | cognitive-engine 本地（`StrategyGeneratorService` [TBD: 新建]） | `{reasoner_result, precedent_ids[]}` | `{strategy{actions[], cost, risk}, precedent_refs[]}` |
| 8 | `s8_decision` | DECISION（已有，PMO-32） | cognitive-engine 本地 `DecisionService` | `{category, scenario, reasoning, outcome, confidence}` | `{decision_id, provenance_ref}` |

**新增 3 个 NodeType 枚举值**（写在现有 `NodeType.java`，**只增不改** 现有 5 种）：`OAG_INTAKE` / `OAG_PLAN` / `OAG_STRATEGY`（`ONTOLOGY` 在节点类型枚举之外，走 `ONTOLOGY` 即可复用，避免与 service 层转化 `zhi` 重名 — 见 §四 命名说明）。

## 四、节点 config 数据契约（JSON Schema 摘要）

每个节点的 `config` 字段是 JSON 字符串。统一骨架：

```json
{
  "node_id": "s4_extract",
  "node_type": "EXTRACT",
  "depends_on": ["s3_ontology", "s2_plan"],
  "endpoint": "http://kb-engine:18086/api/v1/knowledge/extract/run",
  "payload_template": {
    "source": "${{s1_intake.domain}}",
    "files": "${{s2_plan.sub_files}}"
  },
  "on_fail": {
    "max_retry": 2,
    "backoff_ms": 1000,
    "fallback": "SKIP|TERMINATE|DEGRADE",
    "fallback_value": {"extraction_id": "fallback-0", "candidate_entities": []}
  },
  "provenance": {
    "entity_type": "pipeline_step",
    "activity": "execute",
    "agent": "cognitive-engine"
  }
}
```

`payload_template` 语法：`$${{nodeId.path}}` 模板引用上游输出，由 `CognitivePipelineExecutor` 在节点执行前渲染。

## 五、Kahn 拓扑分层（以"首创月度经营诊断"为参考实例）

```
Layer 0:      s1_intake
Layer 1:      s2_plan
Layer 2:      s3_ontology            (parallel)
              s4_extract             (parallel)
Layer 3:      s5_build               (parallel)
              s6_reason              (parallel, 依赖 s3+s4 都完成)
Layer 4:      s7_strategy
Layer 5:      s8_decision
```

`computeLayers()` 已存在（`CognitivePipelineExecutor` L99+），上面分层是实例说明。**并行收益**：Layer 2/3 同层并行，对应 OAG "主线推理" 与 "并行建模" 同时推进。

## 六、失败回滚 / 降级矩阵

| 失败节点 | 默认策略 `fallback` | 副作用 | 用户感知 |
|------|:--:|------|------|
| s1_intake | TERMINATE | 管线立即 FAILED | 提示用户原始需求未能结构化 |
| s2_plan | TERMINATE | 同上 | 提示无法拆解 |
| s3_ontology | DEGRADE（fallback 空快照） | 推理退化为 RAG-only | 响应标注"本体覆盖不足" |
| s4_extract | SKIP | 后续 s5/s6 仍跑，但知识源少 | 响应标注"无新增抽取" |
| s5_build | SKIP | 同 s4 | 同上 |
| s6_reason | TERMINATE | 推理是核心，不可跳过 | 立即报错 |
| s7_strategy | DEGRADE（fallback: 单步 TODO） | 决策仍落地 | 决策附"策略降级"标记 |
| s8_decision | TERMITE（写决策失败 = 事务回滚） | 同 PMO-32 既有 | 提示"决策落库失败" |

回滚原则：**只回滚本批 `ecos_provenance_entry` + `ecos_decision*` 的写入**（DB 事务粒度），不修改 KG / 本体（已落库对象是知识资产，不撤销）。

## 九、验收 curl（端到端）

```bash
# V1: 创建管线（参考实例：月度经营诊断）
curl -s -X POST http://localhost:8080/api/v1/cognitive/pipeline \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "monthly-biz-diagnosis-8step",
    "nodes": [
      {"nodeId":"s1_intake","nodeType":"OAG_INTAKE","config":"{\"raw_request\":\"首创 2025-05 销售同比 -12%\",\"domain\":\"finance\"}","dependsOn":[]},
      {"nodeId":"s2_plan","nodeType":"OAG_PLAN","config":"{\"intent_id\":\"int-001\"}","dependsOn":["s1_intake"]},
      {"nodeId":"s3_ontology","nodeType":"ONTOLOGY","config":"{\"hints\":[\"销售\",\"回款\"]}","dependsOn":["s2_plan"]},
      {"nodeId":"s4_extract","nodeType":"EXTRACT","config":"{\"source\":\"doc\",\"files\":[]}","dependsOn":["s2_plan"]},
      {"nodeId":"s5_build","nodeType":"KG","config":"{\"subgraph_id\":\"sg-001\"}","dependsOn":["s3_ontology","s4_extract"]},
      {"nodeId":"s6_reason","nodeType":"REASON","config":"{\"reasonType\":\"HYBRID\",\"domain\":\"finance\"}","dependsOn":["s3_ontology","s5_build"]},
      {"nodeId":"s7_strategy","nodeType":"OAG_STRATEGY","config":"{\"max_actions\":3}","dependsOn":["s6_reason"]},
      {"nodeId":"s8_decision","nodeType":"DECISION","config":"{\"category\":\"biz_diagnosis\"}","dependsOn":["s7_strategy"]}
    ]
  }'
# 期望：返回 pipelineId

# V2: 执行
curl -s -X POST http://localhost:8080/api/v1/cognitive/pipeline/{pipelineId}/execute
# 期望：execId + status=RUNNING，最终 SUCCEEDED

# V3: 状态（幂等，重放 execId 返回原状态）
curl -s http://localhost:8080/api/v1/cognitive/pipeline/{pipelineId}/execution/{execId}
# 期望：nodeStatuses 8 个节点全 SUCCEEDED，日志含 "Executing layer 2: [s3_ontology, s4_extract] (parallel)"

# V4: 容忍故障（构造 s6_reason 失败）
curl -s -X POST .../execute   # 用例把 s6_reason 改为 TERMINATE
# 期望：管线 FAILED，日志含 "fallback: TERMINATE"，ecos_provenance_entry 写入 FAILED 行
```
