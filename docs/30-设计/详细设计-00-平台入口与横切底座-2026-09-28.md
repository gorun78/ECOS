### 1.2 ADR-15：微服务 v2 的流量现状与切流序列（本册首次登记，须回写 ARCH_SPEC）

**问题**：ARCH_SPEC §2.2 把"7 JAR"写成部署矩阵，容易被下游读成"7 个 JAR 各承流量、已微服务化"。F-1~F-4 实测证明：**流量 100% 由 gateway 单体承载**，5 个 service 是"能启动、不承流"的空壳（datanet 仅 3 个 controller 处于双跑态）。若不固化这一点，各引擎分册会把自己的 service 当成线上事实来设计路由与信任链，导致设计不可落地。

**决策**：

1. **口径唯一化**：`7 JAR` = **7 个可构建可部署产物**（构建与制品口径），≠ 7 个承流单元。承流现状 = **1 个（gateway fat-JAR）**。ARCH_SPEC §2.2 与本册 C.6 的"部署矩阵"列名一律改为「制品 × schema × 档位」，另立「承流矩阵」标注实际流量。
2. **切流不是默认前提**：任何分册不得假设"我的 service 独立承流"。跨服务通信设计必须同时给出 **monolith 态**（同 JVM bean 直调或 REST 到 :8080）与 **split 态**（REST 到 :180xx）两套寻址，且由**同一配置项**切换（见 C.4.3）。
3. **切流序列（S0→S4）**，每个 service 独立走，且每步有门禁：

| 步 | 动作 | 前置 | 退出判据 |
|:--:|:--|:--|:--|
| S0 | 现状：gateway 承全部流量 | — | 全量 E2E + 冒烟绿（当前基线） |
| S1 | service 侧补齐自身 controller（从 engine-impl 的 `@RestController` 迁到 service 扫描包，不复制类） | 该引擎分册 E 章数据契约定稿 | `mvn -f ecos_backend/pom.xml -pl services/{x} -am install` 通过；service 单独启动后本域端点 `curl` 全 2xx/4xx（无 404） |
| S2 | **信任链就位**：gateway strip/重注入 + service `HeaderAuthInterceptor`（C.2） | W02 关闭、`TrustHeaderStripTest` + `HeaderAuthDenyTest` 绿 | 伪造头被剥离、裸调 403；两测试在各 service 均存在且绿 |
| S3 | 开切流开关（C.4.3 的 `ecos.route.<service>=monolith\|service`），灰度按前缀切 | S1+S2 完成；gateway 路由清单与 BFF/vite 前缀单源一致 | 双跑一致性对比脚本（同一请求两态响应逐字段相等，除 `timestamp`）通过 |
| S4 | gateway 清理该引擎的 `@ComponentScan` basePackages，fat-JAR 不再宿主该域 | S3 稳定 ≥1 迭代 | ArchUnit 新增"gateway 不得 import 已切流引擎 impl"规则绿；`backend-module-inventory.md` 承流矩阵更新 |

4. **禁止**：跳过 S2 直接做 S3/S4（= 越权可达独立 service）；在 S4 前删除 gateway 扫描（= 端点 404）；把 vite 18 条 dev 直连当成生产路由证据。

## 四、C 章 技术设计

### C.1 控制流 1：gateway 请求处理链（规定序）

#### C.1.1 现状与目标对照

| 序 | 组件 | 现状 `@Order` | 目标 `@Order` | 变更 |
|:--:|:--|:--|:--|:--|
| 1 | `VersionPrefixRewriteFilter`（`/api/v1/*`→`/api/*` 双路径映射） | `HIGHEST_PRECEDENCE+10` | 保持 | 无 |
| 2 | `RequestContextFilter`（**新增**：生成/接收 `X-Request-Id` → MDC） | 不存在 | `HIGHEST_PRECEDENCE+11` | 新增（F00-11） |
| 3 | `EcosTrustHeaderFilter`（**新增**：无条件剥离 `X-ECOS-*`；JWT 通过后重注入） | 不存在 | `HIGHEST_PRECEDENCE+20` | 新增（F00-03） |
| 4 | `SecurityHeadersFilter` | `1` | `Ordered.HIGHEST_PRECEDENCE+30` | 改（现状值 1 与 +10/+11 混用会乱序） |
| 5 | `JwtAuthenticationFilter`（Spring Security 链内） | filter chain `addFilterBefore(UsernamePassword)` | 保持 | 失败语义收紧（C.2.4） |
| 6 | `RateLimitFilter` | `2` | `5` | 改（须在认证之后，否则匿名流量共享配额） |
| 7 | `QuotaFilter`（租户日配额） | **无注解** | `6` | 新增显式 `@Order` |
| 8 | `springSecurityFilterChain` → DispatcherServlet → `ClearanceInterceptor` → `@RequirePermission` AOP | — | 保持 | 豁免清单单源（C.3.2） |

#### C.1.2 顺序约束（ArchUnit/单测可断言）

```
重写先于鉴权    : VersionPrefixRewriteFilter.order < JwtAuthenticationFilter 所在链
剥离先于鉴权    : EcosTrustHeaderFilter.strip  必须在 JwtAuthenticationFilter 之前
重注入晚于鉴权  : EcosTrustHeaderFilter.inject 在 authentication 成功后（同一 filter 内两段）
限流/配额晚于认证: RateLimitFilter.order(5) < QuotaFilter.order(6)，且均 > JWT 链
```

**为什么限流必须在认证之后**：否则单 IP 匿名洪泛会耗尽真实租户配额（DoS 面）；配额需要 `TenantContextHolder`，其唯一写入点是 JWT 阶段（F-15 现状缺陷根因）。

#### C.1.3 失败语义总表（默认 DENY 的唯一实现口径）

| 触发点 | HTTP | 包络 | 后续 |
|:--|:--:|:--|:--|
| 缺 `Authorization` 且不在匿名清单 | 401 | `code=401 errorCode=ECOS-AUTH-001` | 不透传 `X-ECOS-*` |
| JWT 签名/过期/类型错 | 401 | `ECOS-AUTH-002/003` | 同上 |
| jti 命中黑名单 | 401 | `ECOS-AUTH-004` | 记录审计 |
| 黑名单查询异常（DB 故障） | **503** | `ECOS-AUTH-005` | **fail-closed**（现状 fail-open → W06） |
| JWT 缺 `tenant_id` 且回查失败 | **403** | `ECOS-AUTH-006` | 禁兜底 `tenant-a`（现状 W06） |
| `X-ECOS-*` 由外部携带 | — | — | **无条件剥离后覆盖**（非拒绝，避免破坏浏览器插件） |
| service 侧无 `X-ECOS-USER` 直连 | 403 | `ECOS-AUTH-010` | `HeaderAuthInterceptor`（C.2.2） |
| 准入等级不足 | 403 | `ECOS-AUTH-020` | 文案含所需等级 |
| 限流/配额超限 | 429 | `ECOS-RATE-101/102` + `X-RateLimit-Remaining/Reset` | 重试建议 |
| security-engine 不可用（写操作） | 503 | `ECOS-SEC-501` | DENY（铁律 §2.4） |

### C.2 控制流 2：信任链（ADR-7 落地设计，M0）

#### C.2.1 契约

| 头 | 方向 | 内容 | 生成点 | 校验点 |
|:--|:--|:--|:--|:--|
| `X-ECOS-USER` | gateway→service | userId（JWT `sub`） | `EcosTrustHeaderFilter.inject` | `HeaderAuthInterceptor`（必填） |
| `X-ECOS-ROLE` | 同上 | 逗号分隔角色（`roles` claim） | 同上 | 可选，缺失视为空集 |
| `X-ECOS-TENANT` | 同上 | tenantId | 同上 | 必填（缺失 403） |
| `X-ECOS-DOMAIN` | 同上 | 业务域（数据域二分：`control`/`business` + 具体域） | 同上 | 可选 |
| `X-ECOS-SERVICE` | service→service | 调用方服务标识 + HMAC（`serviceId.sig`） | 新增 `EcosServiceCredentialSigner`（runtime-access） | `HeaderAuthInterceptor` 验签 |
| `X-Request-Id` | 端到端 | traceId | `RequestContextFilter` | 各 JVM MDC |

**为什么需要 `X-ECOS-SERVICE`**：现状内部 REST 调用（`KbEntityInstanceExtractionService` → `:18082`、`SecurityEngineClient` → `:18081` 等）不带任何凭证，`SecurityConfig` 的收敛（F-7）会让它们 401 —— 这就是 ARCH_SPEC 记录的 H10 缺口。切流（S3）前必须补齐，否则拆分即断链。

#### C.2.2 service 侧 `HeaderAuthInterceptor`（新组件，6 个 service 各注册一次）

```
位置: runtime/common-security → com.chinacreator.gzcm.common.security.header.HeaderAuthInterceptor
职责: ① 必存在 X-ECOS-USER + X-ECOS-TENANT，否则 403(ECOS-AUTH-010)
      ② 构造 ServiceContext（ThreadLocal，with clear() 在 afterCompletion —— 现状 ClearanceInterceptor
         的 ThreadLocal<HttpServletRequest> 已有 remove，ServiceContext 必须同样显式清理，防线程池串号）
      ③ 若请求带 X-ECOS-SERVICE → 验签；验签失败 403(ECOS-AUTH-011)
      ④ 匿名清单内的端点（health 族）跳过 ①~③
禁止: 该拦截器不查安全策略表（避免 F-9 扩散）；只还原上下文，裁决交 01 册
```

### C.5 数据流：事件 / 审计 / traceId

#### C.5.1 traceId 流

```
浏览器 ─(无 X-Request-Id)→ BFF：BFF 生成 crypto.randomUUID() 并附加
  → gateway RequestContextFilter：有则透传，无则生成 → MDC.put("traceId")
  → 下游 service：HeaderAuthInterceptor 从 X-Request-Id 再入 MDC（跨 JVM 不断链）
  → 日志：logback pattern `[%X{traceId}]`（全仓新增 logback-spring.xml，F-12 关闭）
  → 响应：ApiResponse.traceId 回填（W09 新增字段）
  → 审计事件：DomainEvent/PipelineEvent 增 traceId 字段（API 只增不改：新字段可选，序列化默认包含）
  → 前端：错误提示展示 traceId 并可一键复制（B 章 3.1 要素 5）
```

#### C.5.2 事件流（含 DLQ）

```
引擎 → runtime-event EventBusService → Kafka <topic>
       失败（序列化/网络/反压）→ <topic>.DLT（统一消费者 DltConsumer）
       DLT 落 ecos_runtime_event_dlq（payload + error + firstSeen）→ runtime-monitor 告警（lag>100/5min）
       重放：运维在告警中心点「重放」→ POST /api/v1/monitor/dlq/{id}/replay → 重新投递，成功则标 closed
```

#### C.5.3 topic 单源（关闭 W12）

```
生成: 构建期由 KafkaTopics 常量反射生成 topic 清单（新增 _win_tasks 之外的产物：gateway/src/main/resources/kafka/topics.txt）
    —— 不改 _win_tasks 脚本集（铁律 #14），生成逻辑放 runtime-event 的单测断言 + compose 文档引用
校验: KafkaTopicParityTest 断言 `KafkaTopics` 常量集 ⊇ compose kafka-init 列表；差集非空 → FAIL
现需补: ecos.data.security-tagged、ecos.ontology.published、ecos.cognitive（代码有、compose 无）
```

#### C.5.4 审计兜底 SLA（关闭 G5-7）

```
Kafka 投递失败 → 同事务外（不阻塞业务）写 ecos_runtime_audit_retry（payload, attempts, nextRetryAt）
AuditRetryTask（runtime-task 注册的 @Scheduled，固定 60s）→ 指数退避重放，≤3 次
3 次仍失败 → runtime-monitor 告警（critical，ack 必须人工）；SLA：从失败到落库告警 ≤ 15min
红线：审计兜底失败**不回滚业务写**（可用性），但告警未 ack 期间该租户写操作计数进入报表（可追溯性）
```
