## 〇、一句话概要

ECOS 数据层 = **单库 5+1 schema（控制域）+ 五层业务域**，当前基线 PostgreSQL 16 + MyBatis（无 JPA）、Flyway 永久禁用、schema 只增不删；控制域三档同构，档差异全部落业务域载体（Neo4j/向量/Doris∨ClickHouse）；主控制 schema 已由 `public` 实跑迁移到 **`ecos_control`**（2026-10-05），连接串过渡 `currentSchema=ecos_control,public`。

## 一、数据域二分（全设计判定前提）

一切存储对象**先判域、再判 schema/层/载体**（两规则文件 §〇 共用口径）：

| 域 | 定义 | 载体 | 规范出口 |
|:--|:--|:--|:--|
| **控制域**（平台运行数据） | 元数据、IAM/菜单、管道 DAG 定义、调度、审计、本体/KB/Agent/认知**定义态**、runtime 表 | PG（主控制 `ecos_control` + 五引擎 schema） | `数据库访问规范.md`（IR/DR/EN/ST/MC） |
| **业务域**（外部接入 + 加工产物） | 外部源系统数据 + RAW/CURATED/SEMANTIC/APPLICATION 五层 | MinIO / `ecos_dw` / Neo4j·向量 / Doris∨ClickHouse | `数据湖存储分层规范.md` v2.0 |

**三铁律**：① 控制数据禁入五层模型 / 业务载体；② 业务数据禁入控制 schema（含引擎 schema）；③ 跨域只存**定位符**（对象 key / `schema.table` / datasourceId），禁复制实体或跨域直查。

## 三、DDL 设计规约（新表落地标准）

### 3.1 命名（DR01~DR08 + ST07）

| 项 | 规约 |
|:--|:--|
| 表名 | 小写 + 下划线 + **`ecos_` 前缀强制**（DR01/DR02）；表单数（DR03） |
| schema 限定 | DDL **必带** `{schema}.` 前缀（DR01 + ST07），裸表名 = FAIL |
| 归属 | 引擎定义态 → 对应五引擎 schema；其余控制数据 → `ecos_control`；业务数据 → 业务域（禁入控制域，ST08） |
| JSON 列 | `TEXT` 存 + `_json` 后缀（DR04 + MC02），**不得**参与 WHERE/JOIN/索引 |
| 布尔 | `is_` 前缀（DR05） |
| 审计 5 件套 | `create_time` / `update_time` / `create_by` / `update_by` / `is_deleted`（DR06，固定名） |
| 版本锁 | `version_no VARCHAR(20) NOT NULL`（DR07，乐观锁） |
| 多租户预留 | `domain VARCHAR(50) NOT NULL DEFAULT 'default'`（DR08） |

### 3.2 主键 / 索引（MC01 + DR）

| 项 | 规约 |
|:--|:--|
| 主键 | 默认 `VARCHAR(36)` UUID**应用侧生成、DDL 无默认值**（MC01，禁 `gen_random_uuid()`）；纯内部 parent-child 可 `BIGSERIAL`（性能优先，knownLegacy 收敛）；联合唯一 `UNIQUE(domain, name)` |
| 常规索引 | `idx_{表名}_{字段}` |
| 唯一索引 | `uniq_{表名}_{字段}` |
| 部分索引 | `idx_{表名}_{partial}` |
| 过期索引 | **不删**，注释 `-- DEPRECATED`（R9） |

### 3.3 类型白名单（MC02，目标态兼容 MySQL/Oracle/MSSQL/达梦/金仓）

`VARCHAR / TIMESTAMP / SMALLINT / INTEGER / BIGINT / TEXT / NUMERIC(p,s) / JSON`
- **金额唯一形态 = `NUMERIC(p,s)`**（精度/标度必须显式，禁裸 `NUMERIC`/`DECIMAL` 无参）
- `JSON` 仅限描述性字段，一旦要检索/约束必须**投影为独立列**
- **禁**：`gen_random_uuid()`、PG `JSONB` 直操（`->>` 运算符）、`timestamptz` 私有语义、PG 数组、`serial` 裸用、`ON CONFLICT`/`RETURNING`/`::` cast 裸写（跨库需 MyBatis `databaseId` 方言 + 降级分支，MC03）

### 3.4 金额列加密判定（ST03 / ST03-A）

- 控制域敏感列（`password`/`id_card`/`phone`/`amount`）**永不可豁免**，必加 `AES-256-GCM + KMS`
- **业务域** `CURATED`/`APPLICATION` 金额列可明文，前提 = RLS + CLS + 审计三重 + 导出/AI 通道经 security-engine 脱敏裁决 + **逐列登记** `docs/40-实现/列级加密豁免登记表`（未登记 = 视同 ST03 违规）

### 3.5 标准 DDL 模板（新表）

```sql
-- 控制域表（schema 名经 MC06 配置化；下方 {schema} = ecos_control 或五引擎之一）
CREATE TABLE IF NOT EXISTS {schema}.ecos_{module}_{business} (
    id              VARCHAR(36) PRIMARY KEY,          -- MC01：应用侧 UUID，DDL 无默认值
    -- 业务字段（类型限 MC02 白名单）--
    amount          NUMERIC(18,2),                    -- 金额唯一形态；ST03/ST03-A
    attrs_json      TEXT,                             -- JSON 只准 TEXT，不参 WHERE/JOIN/索引
    create_time     TIMESTAMP NOT NULL DEFAULT NOW(),
    update_time     TIMESTAMP NOT NULL DEFAULT NOW(),
    create_by       VARCHAR(100),
    update_by       VARCHAR(100),
    version_no      VARCHAR(20) NOT NULL,
    is_deleted      SMALLINT NOT NULL DEFAULT 0,
    domain          VARCHAR(50) NOT NULL DEFAULT 'default'
);
CREATE INDEX IF NOT EXISTS idx_eos_{b}_{col} ON {schema}.ecos_{module}_{business}({col});
```

**附则**（Reviewer 逐条核）：① 表名带 schema 限定；② 需检索/约束的属性必须独立列，不塞 `attrs_json`；③ 金额列落库前 ST03-A 登记表有条目或已加密，两者皆无 = FAIL。

### 3.6 seed 同步

- 新字典 → seed 必加（最小 3 行示例）；seed 幂等（`ON CONFLICT DO NOTHING`）；**seed 与 DDL 同 commit**
- 新增控制域表 DDL 目标一律 `ecos_control` 或对应引擎 schema，**禁再落 `public`**

## 五、三档版本 × 数据层承载（ST01~ST03 + 版本×分层矩阵）

**控制域三档同构**（恒 PG，5 引擎 + `ecos_control`）；档差异**全部落业务域载体**：

| 业务域层 | standard（默认） | enterprise | ultimate |
|:--|:--|:--|:--|
| 近源 RAW | MinIO | MinIO | MinIO |
| DW CURATED（明细） | PG `ecos_dw` | PG `ecos_dw` | **Doris ∨ ClickHouse** 物化（单表 >100 万行）+ PG 保留加工链路 |
| 知识·语义图谱 | PG 关系表（KG 表承载） | Neo4j | Neo4j |
| 知识·向量 | pgvector（已装 0.6.2，基线首选）；缺失时 MC03 降级 TEXT 并标记 | pgvector ∨ 专用引擎 | 同 enterprise |
| 应用 APPLICATION | PG `ecos_dw` | PG `ecos_dw` | Doris ∨ ClickHouse |

**Doris∨ClickHouse 平替**：同一部署 `dw.olap.engine` **二选一**（禁双 OLAP 双写）；经 `runtime-access` 收口（IR06/MC04）；只准业务域，控制域禁入。
**ST 守卫**：表名禁 `std_/ent_/ult_` 前缀（ST01）；跨档能力（Neo4j/Doris/CH/向量引擎）必 `@Profile({enterprise,ultimate})` 或配置开关（ST02）。

## 六、数据流与读写边界（EN 数据流 + 湖规 §四）

```
data-engine (采集 D→I) ──主写──► 近源层 MinIO (RAW/STRUCTURED|UNSTRUCTURED)
                 │
                 ▼ ge 格物(D→I) ─► DW 层 ecos_dw (CURATED: doc/doc_chunk)
                 │            ▼
   ontology-engine (本体 + 映射契约；DW 只读) ─I→K─► 语义层(SEMANTIC)
                 │            ▼
        kb-engine (知识检索 RAG；DW/语义只读)
                 ▼
   cognitive / workspace (场景：经服务 REST 只读)
```

| 对象 | data 引擎 | ontology | kb | cognitive | workspace | 平台自身(sysman/security/runtime) |
|:--|:--|:--|:--|:--|:--|:--|
| 近源层 MinIO RAW | 读写 | 禁直读 | 禁直读 | 禁 | 禁 | 禁（只存定位符） |
| DW 层 CURATED | 读写 | 只读 | 只读 | 只读 | 经 REST 读 | 禁直读 |
| 语义层 SEMANTIC | — | 读写 | 只读 | 只读 | 经 REST 读 | 禁直读 |

- 写 ODS 只属 `data-engine`（唯一事实源）；`ecos_dw` 业务事实/确定性计算产物**必经 data-engine REST 写通道**，引擎禁直写（铁律 §0.6 + ADR-14 + DA05）。
- 跨引擎（ST09）只准读写自家 schema；跨域只走引擎 REST / `runtime-access`，限定名直查他域表 = FAIL。
- 安全（继承 §2.4）：敏感列加密 ST03 / 列级 ST04 / 行级 ST05 / 写操作必发 Kafka `ecos.audit` ST06。

## 十、活库实测发现的治理缺口（诚实登记 · 送审要点）

以下为 reset 后 `sys_man` 活库比对 ST07 归属矩阵得到的**真实偏差**，供确认后续处置批次（本说明书只登记、不擅改）：

1. **`ecos_*` 定义态表跨 schema 重复/错置**：`ecos_biz_contract/department/metric/project/target` **同时**在 `ecos_control` 与 `ecos_cognitive`；`ecos_agent*`（execution/registry/…）在 `ecos_control` 与 `ecos_ai` 并存。需 PMO 裁定**唯一权威 schema**，另一方以 `v_*` 兼容视图或 knownLegacy 收敛（ST07 要求引擎定义态归引擎 schema）。
2. **`ecos_data_*` / `ecos_cognitive_*` 落在主控制 `ecos_control`**（如 `ecos_data_lineage_edge/node`、`ecos_data_pipeline*`、`ecos_cognitive_belief/evidence/hypothesis/model`）：设计上应属五引擎 schema（`ecos_data`/`ecos_cognitive`），现混在主控制。属 reset 前 12→8 大改遗留，处置 = 另立迁移批次 + 兼容视图。
3. **`agent_cost` 月分区表**（`ecos_ai`，14 月分区 + `default` + 母表）：分区维护策略（自动滚动建下月分区、旧分区保留期）目前无调度护栏，建议补 `runtime-task` 分区维护任务。
