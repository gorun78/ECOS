### F10-08 DIKC Readiness 评估与定级（REQ-WAG-08）

```
ReadinessService.assess(questionId, profileId)
  ├─ 并行四层探测（各 Engine 只读端点，超时 3s/层，失败 = UNKNOWN 且计入缺项，禁算 pass）
```

设计：`CommitService.publish(candidateId, approvalToken)` 五步：①校验 token 有效 + 四眼 + 未过期；②经 `CandidateCommitPort` 调属主 Engine 的既有写端点（Agent 不写对方表）；③**定义/版本类资产先 commit+tag 到 Git（runtime-access GitService）再写 DB 在用版本**，DB 不存历史；④发 `ecos.audit` 事件（ST06）；⑤回写 `published_ref`。语义/口径/知识类候选在 `ReviewService` 层拒绝批量接口。验收：`mvn -Dtest=PublishServiceTest#publishWritesGitRefAndDbActiveVersionOnly`、`mvn -Dtest=PublishServiceTest#commitGoesThroughOwnerEngineEndpoint`、`mvn -Dtest=BulkApproveGuardTest#semanticMetricKnowledgeCandidatesRejectBatchApprove`、`mvn -Dtest=ApprovalTest#generatorAndApproverMustDiffer`。

### F10-24 Evidence/Claim 与数字一致性（REQ-WAG-24）
设计：`ecos_wagent_evidence_ref`（**无内容字段**，只存 `evidence_type/source_engine/source_id/version/snapshot_ref/hash/span`，向量与检索片段禁作来源）+ `ecos_wagent_claim`（`claim_type FACT/INFERENCE/RECOMMENDATION`、`numeric_value NUMERIC(18,6)`、`value_source = CM-03/DATA_QUERY/…`、`grade`）+ `ecos_wagent_claim_evidence`（关系表，`PRIMARY KEY(claim_id, evidence_id)`）；`ClaimVerifier` 做三项校验：引用存在性 / 数字一致性（金额必须可追溯到 CM-01~05 或 Data 事实，偏差 >0.01% 即失败）/ 关键 Claim 证据覆盖 = 100%；失败重生成 ≤2 次，仍失败即阻断发布 + 降级标注。验收：`mvn -Dtest=ClaimEvidenceTest#everyCriticalClaimHasAtLeastOneEvidence`、`mvn -Dtest=NumericConsistencyTest#regenerationAttemptsCappedAtTwo`、`mvn -Dtest=NarrativeGuardTest#numberNotFromDeterministicSourceIsRejected`、`mvn -Dtest=EvidenceChainTest#vectorChunkIsNotAcceptedAsEvidence`。

### 4.1 组件落位（不新增模块，全部在既有 jar 内）

```
ai-engine (aiming:18084 / gateway fat-JAR 内嵌)
 └─ com.chinacreator.gzcm.ai.wagent
     ├─ web/        WAgent{Goal,Question,Run,Candidate,Decision,Action,Review,Tool,Playbook}Controller
     ├─ orchestrator/ WAgentOrchestrator(Run 状态机) · PlanBuilder · PlanValidator · StepExecutor · PolicyGuard
     ├─ readiness/    ReadinessService · EngineProbeClient(只读) · ThresholdPolicy
     ├─ tool/         ToolContractRegistry · ToolSearchService · EngineEndpointInvoker · CircuitBreakerView
     ├─ candidate/    CandidateService · ReviewService · CommitService(→GitService via runtime-access)
     ├─ evidence/     EvidenceService · ClaimVerifier · NarrativeGuard
     └─ port/         ITaskManagementService · RuntimeEventPublisher · LlmGatewayClient · SecurityEngineClient
workspace (:18090)  → 只做场景编排入口，调用 wagent 端点（不生产认知对象）
cognitive-engine    → CM Registry + 确定性计算（卷 05）；产物落业务域 ecos_dw（ADR-14）
runtime-task/event/monitor/access/llm-gateway → 横切唯一底座（铁律 §2.5）
```

### 4.2 控制流（Run 主干）

```
POST /api/v1/wagent/questions → Question(open)
  → Orchestrator.createRun()            [幂等键去重]
  → planning: PlaybookSelector → PlanBuilder → PlanValidator(7)
      └─ 任一失败 → failed(E-WA-POLICY / E-WA-SCHEMA / E-WA-BUDGET)
  → PolicyGuard.pre-plan → require_approval? → awaiting_approval
  → plan_validated → executing
      loop for ready steps:
        pre-step → allow | allow_with_mask | require_approval | deny
        resolve_inputs(refs only) → invoke(tool | llm | human_gate | wait_task | sub_run | aggregate)
        post-step → obligations(mask/rowFilter via security-engine)
        output contract validate → StepWriter(run_id, step_key, attempt, hash, level, metrics)
        emit EVT=STEP_COMPLETED → SSE/轮询(F10-16)
      终止: completed | completed_degraded(带 DG 标注) | failed | cancelled | timed_out
  → 结论: NarrativeCompose(llm) → ClaimVerifier(数字/引用/覆盖) → 通过才发布
  → Decision.options → human_gate(选择) → Action.draft → pre-commit 裁决 → CommitService → Git commit+tag → 审计 → 回执
```

### 4.3 数据流（对象流与落位）

```
D: data-engine 冻结快照 → snapshot_ref{id, hash}      → 只引用，Agent 不落事实
I: ontology-engine 口径/版本                          → 只引用（metric_ref + version）
K: kb-engine 画像/规则（12 类）                        → 只引用（knowledge_refs[]）；回流走 Candidate
C: cognitive-engine CM-01~05 计算 → 产物落 ecos_dw(业务域) → Agent 读引用+摘要
W: ai-engine wagent_* 控制面对象（本册 DDL）           ← 唯一新增落位
审计: 全部裁决与发布 → Kafka ecos.audit（ST06，Agent 侧不建审计表）
事件: Outbox → runtime-event → Kafka ecos.* 8 topic（不新增 topic）
```

### 4.4 关键算法

| 算法 | 口径 |
|:--|:--|
| 定级 | 确定性规则（见 F10-10），输入 = 各度 status 集合，输出 A/B/C/D；**LLM 不参与** |
| 数字一致性 | `abs(computed − narrative) / max(\|computed\|, ε) ≤ 1e-4`，来源必须 ∈ {CM-01~05 输出, Data 事实列}，否则 `E-WA-NARRATIVE-NUM` |
| 幂等 | `sha256(tenant + initiated_by + idempotency_key)` 唯一索引；冲突返回既有 `run_id` |
| 熔断 | 滑动窗口 60s，`errorRate > 0.5 ∧ count ≥ 20` ⇒ open 30s ⇒ half-open 1 次探测 |
| 重规划 | 从失败点之后的 Step 重算 Plan；重跑七项校验；`replanCount ≤ 3` |
| 澄清配额 | `clarifyRound` 计数，>2 轮无新增信息 ⇒ `awaiting_input` 挂起并输出缺项清单 |

### 4.5 失败与降级路径

| 故障 | 行为 | DG |
|:--|:--|:--|
| security-engine 不可用 | 默认 DENY + `E-AUTH` + 审计 `GUARDRAIL_FAIL_CLOSED`；L0 只读可按白名单继续 | — |
| llm-gateway 不可用 | 叙述段转模板化输出，数字段不受影响（数字来自 CM） | DG-L1 |
| 画像缺失 | 结论标注"缺历史画像先验，区间偏宽"，需用户确认 | DG-K1 |
| 列权限受限 | 规则/SQL 兜底，标注"口径降级" | DG-C2 |
| 图库不可用或查询受限 | 仅一层邻居 + 超时 3s | DG-C1 |
| 样本 n<30 或 <10 | 展示样本量与区间 / 转趋势判断 | DG-D1 |
| 路由抖动 | 回退链下一候选模型 | DG-M1 |

### 4.6 可观测点（对齐 REQ-AI-03 traceId）

`trace_id` 全链贯穿（HTTP `X-Request-Id` → MDC → `EVT=` 日志 → `ecos.audit`）；每 Step 记 `metrics{latency_ms, tokens_in, tokens_out, cost, policy_decision}`；指标：Run 成功率、各 Step P95、Policy Guard 延迟与 DENY 率、熔断打开次数、Candidate 通过/拒绝率、数字一致一次通过率、澄清率、缺口解决率、结论采纳率、Agent 成本占比（SLO 阈值见 §八）。

### 5.3 错误码语义（附件 §10.4 → ECOS 七类错误 + `E-*`）

| 码 | HTTP | 语义 | 重试 | 用户文案要点 |
|:--|:--:|:--|:--|:--|

| `E-NOT-FOUND` | 404 | 对象不可见 | 否 | 与 403 文案不可区分（防枚举） |
| `E-WA-STATE` | 409 | 状态机冲突 / 口径锁定 / 候选过期 | 否 | 提示当前状态与允许操作 |
| `E-IDEMPOTENT-CONFLICT` | 409 | 幂等键冲突 | 否 | 返回既有 `run_id` |
| `E-RATE` | 429 | 配额/预算超限 | 是（退避） | 提示剩余额度与降级选项 |
| `E-WA-BUDGET` | 429 | Run 预算耗尽 | 否 | 提示拆分问题 |
| `E-WA-DEP` | 502/503 | Engine/底座依赖不可用 | 是 | 可重试 + 降级标注 |
| `E-WA-NARRATIVE-NUM` | 500 | 数字一致性校验失败 | 是（≤2 次） | 阻断发布 + 标注 |

### 9.1 事件模型（附件册三 §11）

#### 9.1.1 事件信封：附件要求 vs ECOS 现契约

附件册三 :859-867 定义 10 字段信封；ECOS 现行唯一信封 = `runtime/common-api/.../common/event/DomainEvent.java:9-15`（全仓共享契约，maven-enforcer 守门，禁依赖业务模块）。对照：

| 附件字段 | ECOS 现状 | 判定 |
|:--|:--|:--|
| `event_id` / `event_type` / `occurred_at` / `payload` | `eventId` / `eventType` / `timestamp` / `payload` | **在位**，命名风格差异（ECOS 驼峰） |
| `aggregate{type,id}` | `aggregateType` + `aggregateId`，且 `KafkaTopics.topicForAggregate()`（:25-37）已实现聚合类型→topic 的**单源路由**（user/role/tenant→`ecos.identity`，dataset/datasource/datafield→`ecos.catalog`，ontology/entity/rule/version→`ecos.ontology`，workflow/task/approval→`ecos.workflow`，agent/mission/tool/execution→`ecos.agent`，knowledge/graph→`ecos.knowledge`，其余→`ecos.audit`） | **在位且优于附件**（附件未定义路由表；本册沿用 ECOS 路由，不自立） |
| `tenant_id` | **缺** | **P0 缺口**：信封无租户维度 ⇒ 附件 §11.4「分区键 = `tenant_id` + `aggregate.id`」在 ECOS 无法成立，跨租户事件隔离失去依据（联动卷 01 多租户 RLS 红线） |
| `trace_id` | **缺**（`traceId` 只存在于 `ApiResponse` 与日志上下文，未入事件信封） | 缺口：与 REQ-AI-03 链路要求不一致 |
| `run_id` | **缺** | Agent 域专属字段，属本册需求 |
| `actor{user_id,via}` | **缺** | 审计必需（谁触发：agent／user／system），联动 ST06 审计链 |
| `schema_version` | **缺** | 附件 §11.4「破坏性变更升版本并双发一个过渡周期」无落点 |

**处置**：5 个缺失字段属 additive，但 `DomainEvent` 是**全仓共享契约**，加字段会影响所有引擎的序列化与消费者 ⇒ 不在本册擅自扩，登记 **R-68**（扩 `DomainEvent` vs 在 Agent 域建 `WAgentEvent extends DomainEvent` 承载 `tenant_id`/`run_id`/`trace_id`/`actor`/`schema_version`）。**本册设计口径**：R-68 未裁前，`tenant_id`/`actor`/`trace_id` 三项以 `payload` 内的**约定键**过渡，并在 §9.6 质量门槛中把"跨租户读写=0"列为**必须实测**项而非仅文档承诺。
