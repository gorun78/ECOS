## 一、结论摘要（TL;DR）

ECOS 在架构意图上**已全面确立**「Git 唯一出口 = runtime-access `GitService`；DB 只存在用版本、历史进 Git（发布 = commit + tag）」的治理模型（架构铁律 §2.5-7/8、后端开发规范 §十一、ADR-18），并已在**部分**控制域对象上真实落地。但「控制域全域统一版本治理」**尚未闭环**，主要现状与缺口如下：

1. **真落地的仅 2~3 处**：本体资产（`OntologyGitServiceImpl`，H4-T4）、数据 pipeline / 元数据（`PipelineGitService` / `MetadataCollectGitArchive`）、sysman 配置同步（`ConfigGitSyncServiceImpl`，H4-T3）。
2. **唯一出口之外仍有直连**：`PipelineGitService` 仍 `import org.eclipse.jgit.api.Git`（违后端规范 §十一.3）；sysman 侧第二套 Git 接口已在收敛（H4-T3）但 `syncFromGit` 仍是 TODO 空实现。
3. **6 类设计资产多数未接入 Git**：知识库资产树 / 认知模型 / 心智模型 / Agent 定义 / 场景定义 / Agent 协同 —— 在后端代码中**未找到** `repositoryId`/`GitService` 归档调用。
4. **W Agent Candidate 发布链路（ADR-18）未工程落地**：`CandidateService` / `CommitService` 为**内存态**，且 `CandidateCommitPort` / `GitArchivePort` / `AuditEventPublisher` 三个 Port **只定义未实现**，默认抛 `UnsupportedOperationException`。
5. **无正式「审计等级 / 双写协议」制度**：`.trae/rules` 与安全域详细设计中**未找到**「审计等级」定义；密级仅以 `clearance_level`（L0~L4）表达，审计完整性以哈希链表达。权威输入所述 L1~L4 审计等级属**建议基线**（源文件 53~62 行自述）。
6. **Git 仓库注册表无 DDL、无注册种子**：`td_git_repository` 仅在 `GitController` 被 SQL 引用，`.sql` 迁移中无建表脚本；语义化 `repositoryId`（`dw-pipeline`/`ontology-model`/…）**未找到**注册数据。
7. **DB 仍存历史版本快照**：`ecos_ontology_version` 表仍存全量 `snapshot` 文本（`V170.1__ecos_ontology_version_snapshot_text.sql`），与「历史只进 Git」相左；4 张废弃版本表（`ecos_ontology_version`/`ecos_object_version`/`ecos_agent_version`/`sys_rule_version`）仍存在。
8. **回滚口径未对齐**：`OntologyVersionService.rollback()` 基于 DB 快照创建新 Draft，而非从 git ref 检出覆写 DB（与 §十一.2 回滚口径不符）。

**已有可复用能力（高价值、建议直接复用）**：runtime-access `GitService`/`GitRepositoryService`、`GitRepoRootResolver`（`ecos_git_repo_root` 单源 + 路径穿越守卫）、`AuditHashChainService`（`ecos_audit_log` SHA-256 链）、`clearance_level` L0~L4 + `audit_mode` 字典、前端 `gitService.ts` 单通道、`V164` RLS/CLS/敏感资产目录脚本。

### 2.4 Git 版本管理 / 配置发布 / 模型注册表 / 版本快照 / 回滚

**现状**
- **唯一出口存在**：`ecos_backend/runtime/runtime-access/…/git/GitService.java`（接口：`commitAllChanges`/`pull`/`createTag`/`getCurrentCommitId`/`diff` + 扩展 `clone`/`push`/`commit`/`createBranch`/`checkoutBranch`/`merge`，多为 `localPath` 入参）；`GitRepositoryService.java`（`getDefaultRepository`/`getRepositoryById`/`listRepositories`/`registerRepository`）；实现 `GitServiceImpl.java`（JGit 封装 —— **允许**，因它就是唯一出口）。

### 2.5 数据库实体 / 迁移 / 领域 API / 权限检查 / 审计事件 / 发布服务

**现状**
