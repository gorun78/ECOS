## 第一部分：知识库工作台增加「认知资产」类型知识

### 1.1 需求定位与关键约束

知识库工作台当前把「知识」限定为 K 类资产（wiki / entity / document / knowledge_set）。议题 1 要求把「认知资产」也纳入知识库内容。

**决定性约束（补充设计 §8.4，逐字）**：

> 「C 与 K 类型清单继续遵循 PRD-04/05 的封闭枚举与互斥守护；**不得把 C 类型经 KB 写入路径静默落成 K 资产**。」

这条约束把「增加认知资产类型知识」锁定为一种**引用态（reference / resolve）**，而非一种**写入态（ingest）**。即：

- 知识工作台**可以展示、检索、跳转、解析**认知资产（Hypothesis / Belief / Decision Basis / Cognitive Model / 经治理的 Pattern·Case）；
- 知识工作台**不得**提供「把认知资产导入为知识条目」的按钮，**不得**复用 `knowledge/services/extract.ts` 的抽取入库链路承接 C 类对象；
- 认知资产的**权威归属仍是 cognitive-engine**，知识工作台只是它的一个只读消费面。

### 1.2 认知资产的五层归类（补充设计 §8.1，落到前端可见性）

| 层 | 内容 | 知识工作台是否可见 | 呈现形态 |
|---|---|---|---|
| A 权威业务事实 | 确定性计算产物、权威数据 | **否**（属业务域/ecos_dw，经 data-engine） | — |
| B 治理后的认知资产 | Hypothesis / Belief / Decision Basis / Cognitive Model / 经治理 Pattern·Case | **是（核心新增）** | 只读卡片 + 生命周期徽标 + 证据链 + 「解析」跳转 |
| C 运行时推理产物 | 单次推理输出 | **否**（默认不落盘） | 若被治理提升为 B 才可见 |
| D 证据引用 | EvidenceRef | **是（作为 B 的从属）** | 证据时间线（复用详设-10 共享件 EvidenceTimeline） |
| E 模型与能力定义 | Model & Capability | **否**（归 AI 工作台能力目录） | — |

> 前端只暴露 **B（+ 其从属 D）**。A/C/E 明确不出现在知识工作台，避免「把运行时产物当知识沉淀」的认知越界。

### 1.4 交互设计方案

#### 1.4.1 信息架构（在既有知识工作台内增维，不新建平行入口树）

```
知识库工作台 (#/knowledge_view)
├─ 总览 overview            （既有）
├─ 资产 assets              （既有 AssetListPage）
│    └─ 类型筛选：全部 | wiki | entity | document | knowledge_set | 【认知资产 ★新增】
│         └─ 选中「认知资产」→ 只读列表（不出现「导入/抽取/新建」按钮）
├─ 检索 retrieve
│    └─ 认知资产检索 ★新增子面：按类型/生命周期/口径/时间范围过滤 + 证据可解析
├─ 治理 govern              （既有，认知资产只读，不进 KB 治理写流）
└─ 配置 config              （既有）
```

- **不新增顶级导航项**，认知资产作为「资产」列表的一个**类型维度** + 「检索」组的一个**只读子面**，符合详设-10 §三「只在既有域内加子 Tab」（R-49）。

#### 1.4.2 认知资产卡片（只读）字段与状态编码

| 区域 | 字段 | 来源 API | 状态编码（色+图标+文字三重，前端铁律/详设-10 无障碍） |
|---|---|---|---|
| 头部 | 资产名、类型（Hypothesis/Belief/DecisionBasis/CognitiveModel/Pattern·Case）、版本 | `GET /api/v1/cognitive/assets/catalog` | 类型用 lucide 图标区分（如 Lightbulb/Scale/Gavel/Brain/Puzzle） |
| 生命周期徽标 | §8.4 状态：DRAFT→CANDIDATE→EVIDENCE_CHECKED→VALIDATED→APPROVED→ACTIVE→SUPERSEDED + CONTRADICTED/EXPIRED/REJECTED/DEPRECATED/SUSPENDED | catalog 返回 `status` | 徽标色板走 `useTheme()` token；异常态用警示色+图标 |
| 信念概率种类 | Belief 专属：`STATISTICAL_PROBABILITY`/`CALIBRATED_MODEL_PROBABILITY`/`UNCALIBRATED_CONFIDENCE`/`UNKNOWN_LEGACY`（§8.3） | resolve 返回 | **必须显式标注种类**，`UNCALIBRATED_CONFIDENCE` 加「未校准」角标，禁与统计概率视觉混同 |
| 证据链 | EvidenceRef 列表、来源、时点 | `GET /api/v1/cognitive/assets/{id}/resolve` | 复用 EvidenceTimeline 共享件 |
| 决策依据 | Decision Basis 只读引用 `decisionId + version + hash`（补充设计 REQ-COG-08） | resolve | 只读，不提供编辑 |
| 操作 | **仅**「解析详情」「查看证据」「跳转到来源场景/蓝图」 | — | **无「导入知识库」「编辑」「发布」**——守住 C/K 互斥 |

#### 1.4.3 关键交互流

1. **浏览**：资产列表选「认知资产」→ 调 `catalog` → 渲染只读卡片网格；空态文案区分「本域暂无已治理认知资产」vs「认知引擎不可用（503）」。
2. **解析**：点卡片「解析详情」→ 调 `resolve` → 右侧抽屉展示信念概率种类、证据时间线、决策依据、生命周期轨迹。
3. **跳转**：卡片「来源」链接到其所属场景/蓝图（跨到场景工作台，见第三部分），保持「引用不复制」。
4. **提案（受控、可选后置）**：若产品要求知识侧能对认知资产发起「更新建议」，走 `POST /api/v1/cognitive/assets/{id}/proposals`，进入**认知域自己的候选状态机**（§7.4 GENERATED→…→APPROVED→APPLIED），**不写 KB 表**。此项列为 P1，默认不在首批。

### 3.3 Blueprint 状态机的可视化（补充设计 §6.3）

主流程 11 态 + 5 异常态，须做成**可读的进度轨**（非原始枚举字符串直显）：

```
DRAFT → DISCOVERING → GAP_ANALYSIS → BLUEPRINT_READY → VALIDATING
      → READY_FOR_APPROVAL → APPROVED → RELEASED → ACTIVE → RUNNING → COMPLETED
异常/回退：NEEDS_CLARIFICATION · BLOCKED · VALIDATION_FAILED · PAUSED · DEPRECATED
```

- 用**步进条 + 状态徽标**（色+图标+文字三重编码）；异常态用醒目色 + 原因 tooltip（记录 actor/时间/原因/traceId/版本，§6.3）。
- **禁止从 DRAFT 直接跳 ACTIVE** 的非法迁移在前端也要有视觉护栏（灰化不可达步骤），与后端状态机一致。
