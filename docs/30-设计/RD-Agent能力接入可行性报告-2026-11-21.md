## 一、结论摘要（v2.0）

| # | 结论 | 判断 |
|---|---|---|
| 1 | 11-24 改造把场景运行从「按分析类型跑」升级为「问题 → 意图 → 假设 → 心智模型/算法 → 执行 → 建议」的**单轮问答**；RD-Agent 模式自然落为**其上的多轮研究循环（L3）** | 成立，且比 v1.0 的 AI 工作台方案**更顺** |
| 2 | 接入点从「AI 工作台新模板」改为「场景运行新增 `runLevel` 分级」：L1 心智模型 / L2 算法 / **L3 RD-Agent 研究循环** | **推荐**，前端改动面最小、用户心智最稳 |
| 3 | L3 的「D（实现并执行）」**必须走隔离沙盒**，不得复用 `workbook` 的宿主机 `python3`/`prlimit` 通道（该通道在 Windows 开发态不可用、无容器隔离） | 红线 |
| 4 | L3 的「R（假设）」直接复用 V363 `hypotheses` 列与现有假设确认交互；L3 的「记录/选优」新增**运行谱系（parent/sota/branch）**，不新增第二套存储哲学 | 只增不改 |
| 5 | 最大阻碍仍是**可信反馈**：`P1-18`（行动结果→实际指标聚合口径缺失）未解前，L3 只能产出「研究建议」，不能自动改正式口径 | 必须先解 |
| 6 | 可行；建议按 **Phase 0（2 周离线验证）→ Phase 1（沙盒接入）→ Phase 2（谱系/审批产品化）** 推进 | 待裁决 |

**一句话结论（v2.0）**：把 RD-Agent 的「R-D-F-R 多轮循环」作为场景运行的高级形态接入是**顺架构**的——它正好补上现有「单轮问答」缺的「多轮自我改进」；但「D 执行」绝不能落在 ECOS JVM 或宿主机，必须落在隔离沙盒，且全部结论只作候选，经审批后才回写蓝图与指标。

## 二、v2.0 接入定位：场景运行的三级形态

11-24 改造后，场景运行已有两级成熟形态。RD-Agent 模式应作为**第三级**接入，而不是新开一套平行系统。

### 2.1 三级运行形态对照

| 级别 | 名称 | 输入 | 执行 | 输出 | 现状 |
|---|---|---|---|---|---|
| **L1** | 心智模型问答 | 用户问题 + 意图 | 单条 `aip-mm-*` 编排（纯 LLM） | 四段式建议 + advice | **已落（V364，5 个心智模型）** |
| **L2** | 算法分析 | 问题 + 选定算法 | `ecos_algorithm_registry` 算法执行 | 结果 + 建议 | **已落（11-24 修复后）** |
| **L3** | **RD-Agent 研究循环** | 问题 + Context Pack + 算法结果 | **假设→实现→执行→反馈→记录 多轮** | 谱系 + SOTA + 候选产物 | **本规划新增** |

### 2.2 为什么落在「场景运行」而不是「AI 工作台」

1. **用户心智一致**：用户在场景里提问，自然期待「再深入一层」就是同一个场景的「研究模式」，不用跳去 AI 工作台。
2. **上下文现成**：场景已有 `Context Pack`（经 `ScenarioContextBuilder` 构建）、六类绑定、假设确认交互（V363 `hypotheses`）——RD-Agent 的 `Scenario` 抽象与这三者**结构同构**，接入几乎零转换。
3. **对比已存在**：`GET /question-runs/{a}/compare/{b}` 已支持两两对比，正是 RD-Agent `Trace` 里「SOTA vs 上一轮」的产品化雏形；L3 只需把它升级为**谱系对比**。
4. **改动面最小**：新增一个 `runLevel` 字段 + 一条异步执行链 + 一个沙盒 client，比「AI 工作台新建整套模板」改动小一个量级。

### 2.3 RD-Agent 抽象 → 三级形态映射（v2.0 更新）

| RD-Agent | v1.0 落点（AI 工作台） | **v2.0 落点（场景运行 L3）** | 复用度 |
|---|---|---|---|
| `Scenario`（背景/数据/环境描述） | 蓝图 + Context Pack | **场景 Context Pack + 绑定 + 口径**（`ScenarioContextBuilder` 已能构建） | **高** |
| `Hypothesis` | 认知域 Hypothesis 候选 | **V363 `hypotheses` 列 + 现有逐条确认交互** | **高**（直接复用） |
| `HypothesisGen` | LLM + 知识库 | **prepare 阶段**（已有意图/假设生成） | 高 |
| `Hypothesis2Experiment` | PlanBuilder | **L3 实验计划**（新增 `experiment_spec`） | 中 |
| `Coder`（CoSTEER） | 无等价 | **沙盒内代码进化**（新增，属沙盒能力） | 低（缺口） |
| `Runner`（DockerEnv） | 新沙箱 | **隔离沙盒执行**（新增 client） | 低（缺口） |
| `Feedback` | 认知 outcome | **算法结果 + 业务真值 + LLM 自评（降级）** | 中（受 P1-18 限制） |
| `Trace`（DAG/SOTA/多起点） | WAgent run steps | **V363 `exec_trace` 扩展 + 新增 `parent_run_id`/`sota_run_id`/`branch_key`** | 高 |
| `LoopBase`（恢复/预算/并行） | WAgentOrchestrator | **runtime-task 异步作业 + 预算/断点**（复用 WAgent 语义） | 高 |
| Knowledge Base | 认知资产 | **运行谱系即知识**（SOTA 方案沉淀为可复用模板/候选） | 中 |

**总体判断**：v2.0 的结构同构度从 v1.0 的约 60% 升至**约 75%**，因为假设、上下文、对比、心智模型这几块 11-24 已经落好，L3 只剩「多轮循环 + 沙盒执行 + 谱系记录」三个真缺口。

### 3.2 非显性约束（规划必须遵守）

- **LLM 调用必须显式传 `model`**：上游 OpenAI 兼容网关对空 model 直接 400；模型名走 `ECOS_QRUN_LLM_MODEL` → `LLM_DEFAULT_MODEL` → `Qwen3.8-27B` 三级回落。
- **读守卫 fail-closed**：`ScenarioReadGuard.assertReadable(entityCode)` 对未登记实体 403；L3 新读面只能复用已登记键（`scenario_analyses`/`scenario_analysis`/`scenario_analysis_compare`）或不挂守卫。
- **DAO 返回 snake_case**：Service 取多 key 字段需容错（`pipeline_id` vs `pipelineId`）。
- **workbook 宿主机执行不可用作 L3**：`PythonRuntime` 用 `prlimit`（Linux 工具）包 `python3`；本机 Git Bash 实测 `python3`/`prlimit` 均不存在；且无容器隔离、无包环境。

## 四、L3 研究循环的目标形态（规划）

### 4.1 用户视角

在场景运行页，当用户觉得「单轮心智模型/算法回答不够深」时，可选择**研究模式（L3）**：

1. 确认问题与假设（复用现有 prepare 交互）；
2. 系统基于 Context Pack + 算法结果，进入**多轮研究循环**：每轮提出新假设 → 生成实现（代码/配置/查询）→ 沙盒执行 → 评估 → 记录，直到达到停止条件（可接受/预算/轮数）；
3. 结束后给出**谱系视图**（每轮的假设/结果/反馈/是否 SOTA）与**候选产物**（改进建议、新蓝图草案、可复用模板）；
4. 用户审批后，候选才回写蓝图或沉淀为模板。

### 2.2 内部执行序列（对齐 RD-Agent 五步，落到 ECOS 语义）

```
prepare（已有） → plan → [ loop: hypothesize → implement → sandbox_run → evaluate → record ] → sota → propose
```

- `plan`：由意图 + 假设 + Context Pack 生成实验计划（`experiment_spec`：目标、数据切片、成功标准、预算）；
- `hypothesize`：复用/扩展现有假设生成（多轮时带历史谱系）；
- `implement`：**在沙盒内**生成实现（Python 代码 / 算法配置 / 查询脚本），不落 ECOS 主机；
- `sandbox_run`：隔离沙盒执行，返回指标与日志；
- `evaluate`：算法结果 + 业务真值为主，LLM 自评为辅（降级时才用）；
- `record`：写入谱系（`ecos_scenario_run` 每轮一行，`parent_run_id` 指向上轮）；
- `sota`：选出谱系中最近 `decision=true` 的运行；
- `propose`：产出候选产物（**不自动生效**）。

## 五、方案设计（v2.0 推荐）

### 5.1 数据模型增量（只增不改，落 V365+）

| 变更 | 说明 |
|---|---|
| `ecos_scenario_run` 增列 | `run_level VARCHAR(16)`（`MENTAL_MODEL/ALGORITHM/RD_AGENT`）、`parent_run_id VARCHAR(36)`、`sota_run_id VARCHAR(36)`、`branch_key VARCHAR(64)`、`loop_index INT`、`experiment_spec JSONB`、`budget JSONB`、`stop_reason VARCHAR(32)` |
| 新表 `ecos_scenario_run_artifact` | 沙盒产物引用：`run_id / artifact_type / storage_ref / digest / size_bytes`（产物实体落 MinIO，DB 只存引用与摘要） |
| 不新增 | 不新建 `scenario_experiment` 平行表——谱系就长在 `ecos_scenario_run` 上，保持「一次场景运行一行」的哲学 |

> 版本号：当前 `NEXT_FREE_VERSION=365`，本规划首批 DDL 从 **V365** 起；加脚本时 `MAX_BASELINE_VERSION`/`NEXT_FREE_VERSION`/`SCRIPT_COUNT_FLOOR` 三处同批改。

### 5.2 API 增量（只增不改）

| 端点 | 方法 | 说明 |
|---|---|---|
| `POST /api/v1/workspace/scenarios/{id}/research-runs/prepare` | 新增 | L3 备料：复用现有意图/假设 + 生成 `experiment_spec` 草案 + 预算默认值 |
| `POST /api/v1/workspace/scenarios/{id}/research-runs` | 新增 | 发起 L3 运行（异步，runtime-task），返回 `runId` |
| `GET /api/v1/workspace/scenarios/{id}/research-runs` | 新增 | 谱系列表（含 parent/sota/branch） |
| `GET /api/v1/workspace/scenarios/{id}/research-runs/{runId}` | 新增 | 单轮详情 + 该轮沙盒产物引用 |
| `GET /api/v1/workspace/scenarios/{id}/research-runs/{a}/compare/{b}` | 新增 | 谱系对比（升级现有两两对比为树对比） |
| `POST /api/v1/workspace/research-runs/{runId}/approve` | 新增 | 候选审批（走现有 WAgent Candidate 咽喉） |

### 5.3 前端增量

- 场景运行页新增「研究模式」开关/Tab（`runLevel=RD_AGENT`）；
- 谱系可视化：树/时间线展示每轮假设、结果、SOTA 标记；
- 候选审批入口：沿用现有审批交互；
- 不新增顶级路由，复用 `#/workbench/:scenarioId` 的运行页。

### 5.4 沙盒执行（红线设计）

| 约束 | 规格 |
|---|---|
| 隔离 | 独立容器，非 root，只读根文件系统，无 docker socket，无宿主凭据 |
| 网络 | 出口白名单（仅 ECOS 只读 API + 批准的镜像源），禁连生产库 |
| 资源 | CPU/内存/时长/磁盘/进程数配额；超时强杀 |
| 数据 | 只读快照（Context Pack 导出 + 算法结果），带租户/场景/口径标记与 sha256 |
| 凭据 | 研究专用短期令牌，作用域仅限提交任务/读自身快照/上传产物 |
| 产物 | 落 MinIO 指定 bucket，DB 只存 `storage_ref + digest` |
| 审计 | 任务号/场景号/快照摘要/模型/提示摘要/代码摘要/执行日志全留痕 |

### 5.5 反馈与候选治理

- **业务真值优先**：能用算法/确定性计算评估的指标，绝不让 LLM 自评定级；
- **P1-18 未解前**：`action-outcome` 实际值缺失 ⇒ L3 评估显式降级（`EVALUATION_DEGRADED`），结论只作建议；
- **候选唯一通道**：L3 产出的蓝图草案/模板/结论一律走 WAgent Candidate → 人工审批 → 发布；不自动写蓝图状态机、不自动改场景指标；
- **失败闭合**：沙盒不可用 / LLM 不可用 / 快照缺失 ⇒ 运行显式失败或降级，禁止 200 空结论。

## 六、分期规划（v2.0）

| 阶段 | 周期 | 范围 | 代码面 | 验收（真实跑通） | 退出条件 |
|---|---|---|---|---|---|
| **Phase 0 离线验证** | ~2 周 | 选 1 场景（建议 `sc_ent2_group_month`），用真实 Context Pack + 算法结果做只读快照；Linux 容器内跑 5 轮研究循环 | **零 ECOS 代码变更** | 5 轮可复现；≥2 轮有信息量；≥1 条建议被业务 owner 认可；快照无越界；成本有账单 | 循环无增量 → 止于借鉴 |
| **Phase 1 沙盒接入** | ~4 周 | 隔离沙盒服务 + `research-runs` 异步链 + `run_level` 增列；结论只落候选 | 新增 1 沙盒容器（需授权）+ workspace 增量；前端运行页开关 | 提交→循环→谱系→候选全链；失败显式；审计可查；不碰生产库 | 安全评审不过 → 回退 P0 |
| **Phase 2 谱系与审批产品化** | ~6 周 | 谱系对比视图、SOTA 选优、候选→蓝图草案接线、预算/熔断 | ai-engine/workspace 增量；DDL V365+；API 只增不改 | 研究→候选→审批→蓝图 v+1→FORMAL 运行全链；SOTA 可回溯 | P1-18 仍缺 → 限定建议型 |

### Phase 0 清单（关键条目）

- [ ] 数据快照：Context Pack 导出 + 列白名单 + 脱敏 + sha256，落只读卷/MinIO
- [ ] 环境：Linux 容器 + Python 3.10/3.11 + rdagent 锁版本
- [ ] LLM：DeepSeek chat + embedding，密钥环境注入
- [ ] 基线：现有 L1/L2 运行结果作对照（非 LLM 自评）
- [ ] 5 轮循环：固定 `loop_n=5`、并发 1、每轮 ≤2h、总预算小额
- [ ] 失败注入：代码错/超时/LLM 超时/缺列，确认 `decision=false` 不中断
- [ ] 产出：谱系 + SOTA 报告 + 蓝图草案（DRAFT）
- [ ] 三方评审：业务 owner + 架构 + 安全

### 立即停止条件

数据越界 / 凭据泄露 / 成本失控 / 连续 3 轮无信息量 → 停，回退到「只借鉴方法」。

## 八、红线与不做清单（v2.0）

1. L3 的代码实现与执行**不得落在 ECOS JVM 或宿主机**；不得复用 `workbook` 的 `python3`/`prlimit` 通道。
2. 不直连生产库；沙盒只读快照。
3. 研究结论**不自动写蓝图状态机、不自动改场景指标**；一律走候选审批。
4. 数字/金额/概率/贡献度只来自确定性计算；LLM 只写解释与建议。
5. 不新增未授权容器/模块（compose 基线 9、Maven 模块基线 49）。
6. 失败显式闭合：沙盒/LLM/快照不可用即失败或降级，禁止 200 空结论。
7. 不引入第二套运行存储：谱系长在 `ecos_scenario_run` 上。
8. 心智模型/算法（L1/L2）既有行为零变化；`run_level` 缺省不指 L3。
