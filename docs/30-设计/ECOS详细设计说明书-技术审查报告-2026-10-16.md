## 一、严重阻断项（P0，修复前不得进入开发）

### A-1 `ecos_ontology_version` 生命周期自相矛盾
- **章节**: §2.9.6（L1033 附近） vs §6.4（L3998 / L4037 / L4054 / L4116）
- **问题描述**: §2.9.6 依据 R12 裁决将 `ecos_ontology_version` 列入「4 张废弃版本表：停写 → 15 处读写切 git → 备份后 DROP」；但 §6.4 全篇仍将其设计为**在用版本表**（`snapshot_json + git_ref`、`uniq(domain_code, version_no)`），且 `executeAndPublish` 主发布流程**继续写入该表**（L4116），V170.1 迁移脚本也仍维护该表（L4101）。同一张表同时被定义为「待 DROP」和「发布主链路目标」，开发无法执行。
- **修改建议**: 二选一并全文统一——
  1. 按后端开发规范 §十一语义：DB 只保留**无版本号的在用行**（`ecos_ontology` 本表），`ecos_ontology_version` 从发布链路移除，历史/回滚/差异只走 git（`repositoryId="ontology"`）；
  2. 若需保留索引，改为 `{asset}_version` 只存索引字段（asset_id / version_no / git_commit_id / git_tag / 发布人 / 时间 / 状态），删除 `snapshot_json` 全量内容列。
  同步修订 L1175 追溯表、L9943、L10268 的表述。
- **优先级**: P0（发布链路与 DDL 都会写错方向）

### A-2 知识工作台「规则」Tab 未落到 §7.6 详细前端设计
- **章节**: §6.2.6⑨ 裁定二（L3904）、§7.1.2 F-KB-16（L4326） vs §7.6.1（L4738）
- **问题描述**: R12 裁决与 F-KB-16 已改为**七 Tab**（含「规则」），但 §7.6.1 的路由树只有 `overview/assets/extract/graph/wiki/govern` 六个节点，API 拆分 `api/{overview,assets,extract,graph,wiki,govern}.ts` 无 `rules.ts`，状态管理、i18n 命名空间（`knowledge.nav.*` 只列到 tabGovern）均无「规则」Tab 对应设计。前端开发按 §7.6 实施将直接遗漏 Rule Center 产品面入口。
- **修改建议**: §7.6.1 路由树补 `└─ rules 规则（Rule Center 前端口：规则列表/五层模型/载体路由/启用停用生命周期）`；API 拆分补 `api/rules.ts`；i18n 补 `knowledge.nav.tabRules` 等键（zh/en 成对）；状态与 OpenAPI 枚举对齐 `rule_carrier` / `rule_layer`；§7.6.7 可达性与 §7.7 Playwright 门禁补「规则」Tab 用例。
- **优先级**: P0（R12 裁决未贯通到实施层）

## 二、一般风险项（P1）

### B-1 Rule Center 14 项能力缺少接口级生命周期契约
- **章节**: §6.2.6
- **问题描述**: 规则五层模型、双路由维度（`rule_carrier` / `rule_layer`）、`RuleRegistry` 收口均为概念层设计；规则的创建 / 启用 / 停用 / 版本发布（git 归档）/ 删除（逻辑删除）等生命周期端点、错误码、幂等键未逐项落契约，测试用例设计无法据此展开。
- **修改建议**: 在 §6.2.6 或补充设计册补一张「规则生命周期 × 端点 × 错误码 × 幂等键」矩阵表；未落地能力显式返回 `not_available`，禁伪成功（对齐后端规范 §十一.7）。
- **优先级**: P1

### B-2 Redis 目标态遗留 Q2 / Q7 / Q10 未收敛为可验收条款
- **章节**: §2.9.8
- **问题描述**: R12 已裁定 Redis 归属 runtime 底座、Runtime 统一管理配置，但三个遗留问题（多级缓存一致性策略、键隔离与 `X-Org-Id`、降级行为）仍以「待议 Q」形式存在，未转为带验收标准的设计条款。
- **修改建议**: 将 Q2/Q7/Q10 改写为「目标态条款 + 现状缺口登记 + DoD」三段式，并明确过渡期语义（现状 Caffeine/本地缓存继续可用，切换以 runtime 提供的客户端为准）。
- **优先级**: P1

## 三、轻微建议项（P2）

### C-1 历史表述残留「六 Tab」
- **章节**: L5332（认知资产中心描述）、L4868 等处
- **问题描述**: 认知资产中心「六 Tab」属另一模块的合法表述，但与知识工作台七 Tab 并存易造成读者混淆；部分「六 Tab→七 Tab」对比仅出现在 R12 说明行，检索时需人工区分。
- **修改建议**: 在 §7.6 开头加一行「本工作台为七 Tab（含规则），注意与认知资产中心六 Tab 区分」即可，无需大改。
- **优先级**: P2
