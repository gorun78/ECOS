# ECOS 系统配置现状与差距分析（2026-11-19）

> 范围：系统配置功能（`sys_config`）与数据字典（`sys_dict`）双线；对照「全局配置 = 安全中心 + runtime；引擎独有配置 = 各引擎工作台」的目标口径，盘点工程实现差距。
> 证据基线：2026-11-19 工作树实扫；所有结论附文件路径，行号随代码漂移以当前工作树为准。
> 性质：现状盘点 + 差距登记 + 整改方向建议；**不含任务拆解、不构成已批准方案**。
>
> **整改执行记录见 §10（2026-11-19 同日落地批）**：G-3（reset 404 / 前端组驱动 / D-2）、E-2、D-3 已落地；G-2 / E-X / D-1 转入后续批次。

## 1. 结论先行

1. **存储单源已立**：配置/字典落在 `sys_config` / `sys_dict` 单表，按 `config_group` / `subsystem` 分组，sysman 提供唯一 REST 门面 `/api/v1/system/config*`，前端消费走 `src/api/dictConfigClient.ts` 单通道。
2. **「全局配置」范围远小于目标**：实际只有 `global` + `security` 两组约 11 个键（密码策略、登录锁定、会话、审计保留天数）。**runtime 配置（llm/kafka/minio/neo4j/调度/事件）0 项入门面**，全部散在 yml 与 `@Value`/`@ConfigurationProperties`；安全中心主力（JWT、OPA、审计哈希链、KMS）同样硬绑定在 security-engine。
3. **引擎配置全部绕过 sysman HTTP 门面**：data/ontology/cognitive/kb 四引擎直注 `SysConfigService` 同 JVM bean、自建引擎前缀 Controller 暴露——后端规范 §十.8 已登记为 CD-1~CD-3 存量偏差，未整改。
4. **前端工作台缺口参差**：data 有设置 Tab；ontology 后端就绪但前端零消费；cognitive/kb 经 workspace 聚合且 cognitive 双组并存；ai 实质 yml-only（模型注册接口显式 501）；workspace 无引擎参数。
5. **口径差需裁决**：规范铁律 §3.6 的「全局」= `config_group='general'` 一组；「全局 = 安全中心 + runtime」是按功能域重切的新口径，与现行规范不一致。按功能域落地须 PMO 立项同改铁律 §3.6 + 后端规范 §十 + 前端规范 §九三处。

## 2. 口径声明

- **本文主线口径**（用户提供）：全局配置 = 安全中心相关功能 + runtime 相关功能的配置项，在全局（系统管理/安全中心）域维护；引擎独有配置在各引擎工作台实现。
- **规范现行口径**（对照）：铁律 §3.6 规定 `config_group='general'` = 平台全局（仅 sysman/gateway 可写），`config_group='{engine}'` = 引擎/工作台独立配置；`sys_dict.subsystem` 与所属引擎 `config_group` 同名对齐，空值 = 全局字典。
- **差异点**：① 安全策略数据（RLS/CLS/脱敏/OPA 策略）在设计上走独立表（`ecos_security_policy` 等），不进 `sys_config`；② runtime 相关（如缓存）在规范里也是独立分组（`cache`）而非 `general`；③ 因此「全局 = 安全中心 + runtime」在规范框架下没有现成落点，属待裁决的新切分轴。

## 4. 全局配置差距（安全中心 + runtime）

### G-1 安全中心配置仅约 10 键入门面，主力仍硬绑定

- 已入 `sys_config` 的安全键：`global` 组 7 键（`session_timeout_minutes`、`password_min_length`、`password_expire_days`、`password_history_count`、`max_login_attempts`、`lockout_duration_minutes`、`max_concurrent_sessions`，消费方见 `SysConfigController.java:56-65` `KNOWN_CONSUMED`）+ `security` 组 4 键（V102：`password_require_upper/digit/special`、`audit_retention_days`）。
- **未做成配置项**（仍 `@Value`/yml 硬绑定）：
  - OPA：`OpaPolicyService.java:74-75` `@Value("${opa.url}")` / `${opa.policy-dir}`；
  - JWT 密钥：pem 文件注入（`%USERPROFILE%\.config\ecos\jwt-private-key.pem`），不可在线调整；
  - 审计哈希链（`AuditHashChainService`）、ABAC 决策缓存（`DecisionCacheService`）、KMS（`crypto/kms/*`）均无 sys_config 键。
- **边界说明**：安全策略本体（RLS/CLS/脱敏/ABAC 规则）走独立表 `ecos_security_policy`（V148），由 `SecurityPolicyController`/`SecurityProfileController` 管理——这是设计如此，不算差距；差距在于「策略之外的引擎运行参数」没有进入全局配置面。

### G-2 runtime 配置 0 项入门面

唯一例外是 `cache` 组 4 键（V306：`ecos.cache.enabled / default_ttl_seconds / max_stale_seconds / redis_enabled`，消费方 `SysConfigCacheSettingsSource`；V321 清退旧行）。其余 runtime 底座全部散在 yml + 注解：

| 模块 | 形态 | 代表键（证据） |
|---|---|---|
| llm-gateway | `@ConfigurationProperties(prefix="llm")` | `runtime/llm-gateway/.../config/LLMGatewayProperties.java`：`llm.engine.*`、`llm.gateway.*`、`llm.sessions.*`、`llm.models.*` |
| runtime-event | `@Value` | `KafkaBusProducerConfig.java:40`、`KafkaBusConsumerConfig.java:49`：`spring.kafka.bootstrap-servers`、`ecos.event.kafka.*` |
| runtime-access | `@Value` | `MinioStorageService.java:50`、`MinerUHttpParser.java:47`、`Neo4jConfig.java:37`：`minio.*`、`ecos.mineru.base-url`、`neo4j.*` |
| runtime-core | `@Value` | `CacheInvalidationRelay.java:56`：`ecos.cache.outbox.retention-minutes` |
| runtime-task / runtime-monitor | — | 未发现可配项（参数编码在代码内） |

历史口径冲突：V264 头注明确写「模型目录属部署期形态，留在 Spring yml 而非 sys_config 字典」——与「runtime 配置纳入全局配置」的目标直接冲突，需裁决推翻或维持。

### G-3 前端全局面薄弱 + 两个活缺陷

- `SystemConfigManager.tsx` 只对白名单 11 键可写，安全中心/runtime 语义的新键即使入库也不会出现在编辑面。
- `/api/v1/system/config/params` 实测 503（`ISystemParamService` 未装配）——`docs/50-测试/ECOS逐功能验证矩阵-07-安全与系统管理-2026-11-13.md` 已登记。
- `/api/v1/sysconfig/{key}/reset` 因 `sys_config` 缺 `default_value` 列在活体恒 404。

## 6. 字典（sys_dict）差距

- **D-1 同名对齐未双列化**：规范要求 `sys_dict.subsystem` 与引擎 `config_group` 同名对齐；但 `sys_config` 表无 `subsystem` 列，「对齐」只在契约别名层成立（§3.1），两侧真实值域靠人工维护，无门禁校验一致性。
- **D-2 消费面不完整**：`SystemConfigManager.tsx` 未消费 `sys_config.config_options`（V40 已加列），可枚举配置仍以前端硬编码选项渲染；字典通道 `useDict`/`fetchDictItems` 与 `fetchDictSubsystems`（G1-G5 分组）在 `dictConfigClient.ts` 已就绪。

## 8. 整改建议方向

> 方向级建议，不展开任务拆解；落地前需按 PMO 流程立项裁决。

1. **runtime 配置建组入 sys_config**：参照 V306 `cache` 组先例，为 llm-gateway / runtime-event / runtime-access 建 `llm`、`event`、`storage` 等分组 seed，消费侧做 `SysConfigXxxSettingsSource` 桥接，逐步收编 yml `@Value`（涉铁律 §2.5 第 9 项缓存归口同款路线）。V264「模型目录留 yml」旧口径需一并裁决。
2. **引擎配置收敛 sysman HTTP 门面**：落实后端规范 §十.8 CD-1~CD-3——引擎改调 `/api/v1/system/config/group` 契约端点（已支持分组+keys 批量+edition），废除直注 bean 与引擎前缀配置 Controller；DEFAULTS 落 `default_value` 列以修复 reset 404。
3. **补齐前端工作台设置 Tab**：ontology（后端已就绪，接 `ontologyEngineApi.ts`）、ai（先解决模型注册 501 的写通道与授权载体）、workspace；kb/cognitive 去掉 workspace 聚合层直连门面。
4. **前端全局面改按组驱动**：`SystemConfigManager` 从白名单驱动改为 `config_group` 驱动（参照 `governance/EngineConfigTab`），新增安全/runtime 键自动可见；消费 `config_options` 渲染枚举项。
5. **修复活缺陷**：`ISystemParamService` 未装配 503；N9 匿名 PUT 移出 permitAll；`/engine/data/settings` 路径漂移（待裁决清单 D156）。
6. **字典侧**：裁决 `subsystem` 双列化或维持别名层终态并加一致性门禁；补 `ecos_mask_strategy` 字典表（F04-03）。
7. **口径裁决**：若确认「全局 = 安全中心 + runtime」功能域切分，须 PMO 立项同改铁律 §3.6、后端规范 §十、前端规范 §九（三处要求同名对齐），并定义与 `general` 组的迁移关系。
