## 三、红色清单（✗ 失败，不掩盖）

### 3.1 【P0-1】本体工作台路由拦截：`/api/api/v1/ecos/*` 双前缀 404

- **现象**：切 `#/ontology_workbench` 后所有 10 Sidebar 类目无法拿到数据；整面板 `业务分级域维护中心` 卡片内容为空。
- **console 直接证据**（browser-use `list_console_messages`）：
  ```
  Failed to load resource: 404 (Not Found)  http://localhost:3000/api/api/v1/ecos/ontologies
  Failed to load resource: 404 (Not Found)  http://localhost:3000/api/api/v1/ecos/actions
  Failed to load resource: 404 (Not Found)  http://localhost:3000/api/api/v1/ecos/domains
  Failed to load resource: 404 (Not Found)  http://localhost:3000/api/api/v1/ecos/relationships
  （同一 4 条重复 2 轮 = 首次加载 + 类目切换重试）
  ```
- **旁证 500**：`/api/v1/ontology/data` 独立端点 4 次 500 Internal Server Error（同页面既有 Ontology ER Diagram + Relationship 双端点）。
- **推断（不代决）**：前端 client 前缀包含 `/api/v1/` 而 BFF 转发路径中已含 `/api` 前缀（Express BFF `forwardProxy`），造成双前缀。同一前缀其它工作台全绿，说明**该 bug 限定 ontology-workbench 专属 client**（`ecos_frontend/src/pages/ontology/**/api.ts` 或 `OntologyWorkbenchLayout` 消费库）。
- **同源影响**：`ProjectItem` 页面已改用 `workspace/scenarios/{id}/…`，不受影响；独立 `knowledge_graph`/`AIPKnowledgeView` tab 属上一域 Test Round C 覆盖，本批未重复。

### 3.2 【P1-1】AI 工作台 / Agent Studio tab 全滚

- **现象**：点击"Agent Studio 智能体"，进入页面后主区域 `main.innerLen=609` 且显示："服务暂不可用 `{"status":404,"error":"Not Found"}` ..."。
- **console**：
  ```
  404  http://localhost:3000/api/v1/agent-mesh/agents   × 2
  ```
- **影响**：Agent 全生命周期（构建/市场/上线/回滚）不可用，与 F06 认知 4 卡、Agent Mesh UI 同邻居 —— 需单独 fix `agent-mesh` 路由是否缺失或路径不明。

### 3.3 【P1-2】认知 tab 的 beliefs 端点 500/400

- **console**（在"认知工作台"tab 停留数秒）：
  ```
  400  /api/v1/cognitive/beliefs   × 4
  ```
- **推断**：`cognitive-engine` 的 beliefs 列表 GET 未处理空 body / 未注册 param → 返回 400；不影响认知 4 卡 UI（认知总览屏幕正常）。

### 3.4 【P2-1】Playground / Agent-Loop 探活 405
- **console**：`405 /api/v1/agent-loop/sessions?agentId=…` × 3。推断为前端先探活 GET、后端仅注册 POST —— 单次 405 属正常 guard，但 3 次连续属超频；不影响 playground 交互面板渲染。
