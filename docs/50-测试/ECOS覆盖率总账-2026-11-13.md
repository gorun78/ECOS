## 五、判定为「确定性拒绝」而非缺陷的形态(避免误判)

本批刻意区分了三类**不是缺陷**的 4xx/5xx:

| 形态 | 实例 | 为何不是缺陷 |
|---|---|---|
| 方法语义 405 | `GET /api/v1/workspace/.../pre-validate` → 405 | 端点是 POST 语义;GET 405 是正确的方法拒绝 |
| 显式降级 5xx | `GET /api/v1/agent-call/stats` → 502 `ECOS-AI-502` | LLM 依赖不可用的**显式**降级,带机读码,非静默 |
| fail-closed 503 | 本体候选面 → 503 `ECOS-SEC-501` | security 不可用时默认 DENY(§4.5.4 分态),是设计要求 |

反向纪律:**任何 200 + `code≠0`** 都判缺陷(状态行不保真),本批由 D37/D41 两次实证。

## 八、本批最重要的两条方法论结论

1. **「测试绿」必须自证真的跑过**:本批遇到过三次假绿——
   ① `execFile` 退出码取错字段(把非 0 读成 0);
   ② spec 文件被写坏含 NUL 字节,Node 当二进制;
   ③ `cmd | head` 的 `$?` 是 head 的退出码。
   三者都会让「有问题的 CLI」显示为「通过」。修法统一为:**断言前先证明输入/执行真的发生了**。

2. **门禁自身的错误锚定会造出假红**:66 路由 spec 的 `KNOWN_BACKEND_GAPS` 用 `^` 锚定了不存在的
   前缀形态,导致已归因缺口被判 UNATTRIBUTED。修法是**用实测 detail 反推正则**,而非凭想象写锚点。

### 2026-11-14 追加：五条同族缺陷（D31 / D59 / D60 / D61 / D62）

| 缺陷 | 类型 | 一句话根因 |
|---|---|---|

| **D62** | **前端代理前缀争用** | vite 表把 `/api/v1/ecos` 整根给 ontology :18083，抢走 workspace 的 objects/state-machine 子族 ⇒ 浏览器里仍 403 |

> **追加观察**：这五条是**一条链上的五层**——修好网关路由才暴露 500，修好 500 才暴露分页，
> 修好分页才暴露查询方言，网关全通后浏览器里又冒出前端代理层的同型错误（D62）。**只修一层就宣布"已修复"会得到假绿**：因为上一层在挡路，
> 下一层的缺陷根本走不到。本批坚持「修一层、走一步」，五层全部穿过后才判 PASS。

> **共性观察**：十四处里有 **7 处是「静默错配」**（漏扫、漏注册、漏映射、漏配探针、漏带认证），
> 而不是业务逻辑写错。这类缺陷不会被单元测试发现（单测直接 new 对象、mock 网关），
> **只有活体链路能照出来** —— 这正是本方案坚持「活体 + 证据三元组 + 反向探针」的价值所在。
