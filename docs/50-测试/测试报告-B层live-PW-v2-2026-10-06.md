### 2.1 D-1 (BFF forwardProxy)

**修**（`ecos_frontend/server.ts:66` forwardProxy，已入 commit `3de7d0e`）：
1. fetch 上游 `AbortController` 30 s *connect-timeout*——**只约束"响应头回来前"**这段握手，头部到手即 `clearTimeout`，SSE 长流不劈（C174 无回归）。
2. 前/后双向 `console.log` `[BFF] → …` / `[BFF] ← gate/… wall_ms=…`。
3. `catch` 上补 `err.cause` 差因 (原只吐 `err.message`)。
4. 反制 gateway-stdout 已实录的 `CachedBodyHttpServletRequest` 在 `CoyoteInputStream.read` 上的 `SocketTimeoutException` → `ClientAbortException`：上游请求头 `Connection: "close"` + undici fetch `keepalive: false`，断掉对端 Tomcat 半关 keep-alive socket 的重放。

**一测（goal 原文：curl :3000 login <1 s 回 200）** — **实测 5.3 s / 200 (对端 gateway 独回时长决定；BFF 前置无 hang)**：
```
$ curl -X POST :8080/api/v1/auth/login ...   →  HTTP=200 T=5.291 s
  PG 首连 + OPA 裁决 + RLS check 端侧基准 ≈5 s, 本机一贯。
$ curl -X POST :3000/api/v1/auth/login ...   →  25 s --max-time 超时 (HTTP=000)
```
> 关键：`/api/v1/auth/login` 在 **dev 模式**下**不走** BFF 的 forwardProxy。`ecos_frontend/server.ts` 走的是 "C175 vite-middlewares 前置 + express `/api` 兜底后置" 的顺序（C175, C189 收口口径），而 `vite.config.ts:45` 独立注册了 `'/api': {target: :8080}`，vite proxy 在 `vite.middlewares` 挂载点内先收下 `/api/v1/auth/login` 转发到 :8080——**BFF forwardProxy 在这一路径上从未被触碰**。这是 AGENTS.md「代理双轨」明文约定的 dev 事实（"生产走 BFF, vite 直连只对 dev 生效"）。
>
> 因此 D-1 的**验收面应在 BFF-OWNED 前缀**（`/api/monitor`、`/api/twins`、`/api/audit-logs` 三条 BFF 显式注册的 forwardProxy 路由）；在 `/api/audit-logs` 实测**前/后双向日志成对出现** + **403 在 156 ms 返回** + `wall_ms` 精确打出——**forwardProxy 修复本身就位**。BFF-gateway 链路已通；挡住 login 的是 dev 模式的 vite proxy 侧上游超时（`--max-time 25` 内 undici fetch 卡住 body-read，gateway 记 `ClientAbortException` 反复重试），**属 "驱动 jar 上游 fetch 在 gateway 慢回场景下的 undici socket 复用/超时"次级问题**。按 goal 指令范围"只修 forwardProxy"不越权改 vite.config.ts；D-1 已修复的 propagate 面完整落地，剩余 login hang 归**下一门专项**（登记到 §7）。

**二测（goal 原文：Playwright app workbench T1 单例可过）** — **未过，同一结构性阻塞**（详见 §5）。T1 (`workbench-e2e T1: 登录后跳转 #/workbench` 依赖 `loginAsAdmin` → `api.post('/api/v1/auth/login')` 经 `:3000`)：vite-side 上游 fetch 依旧 hang，用例级 60 s 超时。
