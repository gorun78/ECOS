## 一、检视口径与方法

1. **页面基准**：`main.tsx` 实测 52 个内容路由根 + `navConfig.ts` 45 导航项（12 Sidebar）+ `DELIBERATELY_UNLINKED` 15 根白名单；pages 目录 `.tsx` 共 425 个文件。
2. **检视框架**（每页统一 checklist）：A1 信息架构与命名 / A2 任务流断链死链 / A3 六态完备（空/加载/错误/降级/403/成功）/ A4 反馈可预期（确认门、toast、traceId 归因）/ A5 认知负荷 / A6 跨页一致性 / A7 无障碍；B 技术红线（i18n 硬编码、裸 Tailwind 色板、运行时拼类、mock 假数据、console 泄漏、孤儿文件）。
3. **执行方式**：8 个只读检视代理分组逐页（壳层/总览/平台、数据域、本体/配置、知识域、智能域、场景层、安全/系统、共享件底座），全部论断要求 `file:line` 实读锚定；随后对关键 P0/P1 做二次 grep/读源复核（附录 A），并做 live 浏览器抽检（§五）。
4. **严重度定义**：P0 = 流程断裂或假真理（假数据冒充真实、成功假象、必崩/必 404）；P1 = 明显体验缺陷；P2 = 打磨项。
5. **局限**：以静态实读为主 + live 抽样（:3000 dev、gateway 全栈、slate-light 与 deep-space 两主题）；cyber-terminal / royal-purple 两主题与生产 build 未跑检；截图按 R5 不入库，仅文字留证。

## 三、系统性问题聚类（跨组模式，按修复杠杆排序）

**S1 「假真理」是全域最大病灶（P0 主贡献者，约 30 条）** — 后端不可达/能力缺失时，各域不约而同选择"演出去"而非"降级示警"：COS 假审计脚本播放并拉满 coverage（A）、数据域假调试 session/Git 恢复 stub/Copilot 罐头话术（B）、本体/业务工作台 demo 常量与 688 行 seedData 冒充真实资产且 CRUD 内存即成功（C）、知识域假待办/假正文/恒 dryRun 谎报提交（D）、ChatbotStudio 假 LLM 回复/假发布/假指标（E）、沙盘假占位节点与"保存成功但内容丢失"（F）、审计 FAILURE 显示"pending"、健康徽章恒绿（G）。**同一产品内并存两套真值标准**：CandidateReviewPanel / GatewayDiagnosticsPage / AlertsPage / EvalsView 已示范"诚实降级+traceId"的正确写法，说明缺的是机制（门禁+共享降级件），不是规范。

**S2 API 层 fail-open 使六态成为死代码（G 组根因，跨 B/C/D/E 复现）** — securityClient/iamClient/dictConfigClient/useOntologyData 等普遍 `catch → 返空数组 + console.warn`，页面精心写的 error/denied/offline 分支永不可达，故障一律渲染为"空策略/零审计/暂无数据"。live 佐证：本体工作台后端 500 时主区空白无提示、COS 控制台自供 "using hardcoded data"。修复应下沉到 transport 层统一错误对象，页面只消费。

**S3 「写了但没接上」：死控件、孤儿页、断深链** — 筛选器不入请求（SecurityAudit 日期/IP、UserManagement 状态/角色）、抽屉无打开入口（ExternalInterfacesDrawer）、Tab 不入 URL（安全中心/世界模型/治理子页）、命令面板不传对象 id、`#/ontology-workbench/entity` 必 404、干预四面板与 AiGuardrails 孤岛群零 importer、SecurityPolicyPage/AuditQueryPage 控制面页未挂载。交互件"存在但不产生效果"比缺失更伤信任。

**S4 主题与 i18n 红线呈"文件级贫富分化"** — 运行时拼类（`hover:${token}`、`${bg}/50`、`+"0d"`）、非法类（indigo-650、`-650/50`、animate-in）、`bg-[var(--card,#020617)]` 暗色兜底、`text-white` 压 accent、内联双语对象（labelZh/locale 三元）绕过 t()、i18n 键名嵌中文（ragtab.检索来源）——按文件成片出现，palette-baseline 已挂账但无 CI 拦截。新页（workbench 层）几乎零违规，旧页成片违例，证实"新代码自律、旧页无人收口"。

**S5 反馈与确认链未单源** — Toast 至少 4 套 fork（common/user-management/tenant-manager/pipeline-editor）+ 页内自绘（CognitiveEngineView/GuardrailsView/GraphExplorerTab）；确认门三分（原生 window.confirm 18 文件 / 自建 Modal / 无确认），危险操作（删告警规则、冻结账户、审批、重置配置、安全参数回车即存）大量缺确认；auth 生命周期三套 key 读写（Login 写 `token`、Topbar 清 `ecos_token`、NoAccess 又一套）。

**S6 壳层与底座的单点流程断裂（live 全复现）** — 登录成功落 `/app`→404；登出键名错配→点了没退出；RequireAuth 对 5xx `else setState("ok")` 放行，与文件头 fail-closed 铁律矛盾；Topbar 身份恒 "AD"。这四条构成用户第一次进系统的完整坏路径，优先级最高。

**S7 呈现层认知负荷** — 裸 JSON `<pre>` 直排（EngineMonitor/CognitiveEngineView/DecisionDesk/WikiDetail/ABAC details）、原始枚举直显（COMPLETED/RUNNING/block/positive）、10px 以下正文（本体工作台全页）、traceId 全域稀缺且 `select-none` 禁止复制。
