## 五、缺陷登记（本批新发现 4 项，全部附证据）

### D1 — gateway PATCH 转发 fail-closed（P0）

| 字段 | 值 |
|---|---|
| 现象 | `PATCH /api/v1/workspace/scenarios/{id}/status` 经 gateway :8080 → **503 `ECOS-WS-503-UPSTREAM`**；直连 workspace :18090 → **409 `ILLEGAL_TRANSITION`**（正常） |
| 根因 | `RestTemplateConfig.restTemplate()` 用默认 `SimpleClientHttpRequestFactory`（JDK `HttpURLConnection`），**不支持 PATCH 方法** |
| 证据 | `verify-evidence-2026-11-13/缺陷与降级证据.txt` D1 段；`gateway/.../WorkspaceForwardController.java:115` exchange；`gateway/.../config/RestTemplateConfig.java:12` `new RestTemplate()` |
| 影响 | 场景状态机经网关完全不可用（前端若走 gateway 则状态操作全部失败） |
| 级别 | **P0**（阻断核心写链路） |
| 建议 | RestTemplate 换 Apache HttpClient 5（`HttpComponentsClientHttpRequestFactory`）或 OkHttp |

### D2 — 场景创建无幂等（P1）

| 字段 | 值 |
|---|---|
| 现象 | 同名场景重复创建，追加不同 id 多行（实测 3 组各 2 行） |
| 证据 | `verify-evidence-2026-11-13/l4-对账.txt`；库中 `VERIFY-scenario-*` 同名重复 |
| 影响 | 重复数据、列表膨胀、下游引用歧义 |
| 级别 | P1 |
| 建议 | 加唯一约束或幂等键（idempotency-key） |

### D3 — 金额列类型违反 MC01 红线（P0）

| 字段 | 值 |
|---|---|
| 现象 | `ecos_control.ecos_business_scenario.budget` 为 `character varying`（存「850万」字符串），违反数据库访问规范 MC01「金额列唯一形态 NUMERIC(p,s)」；对照 `safety_index_target` 为 `numeric` |
| 证据 | `verify-evidence-2026-11-13/缺陷与降级证据.txt` D3 段 |
| 级别 | **P0**（红线） |
| 建议 | 迁移列类型为 NUMERIC；注意「850万」是文本需先清洗 |

### D4 — 沙箱画布页 2 个 `<main>` 元素（P3）

| 字段 | 值 |
|---|---|
| 现象 | `#/scenario-sandbox/:id` 渲染 2 个 `<main>` 元素，Playwright strict mode violation |
| 证据 | `test-results/.../V-WS-006/error-context.md` |
| 影响 | HTML 语义错误，影响可访问性（屏幕阅读器）与测试稳定性 |
| 级别 | P3 |
| 建议 | 次容器改为 `<aside>` 或 `<section>` |

**订正 D —— V-WS-082 根因不是「无 RLS 策略」（BLOCKED，根因重定位）**

矩阵原假设是"无 RLS 策略 ⇒ `RLS_NO_POLICY_MATCHED`"。实测：策略行**存在且与能通过的 `scenario_graph` 完全相同**（`role_admin` / priority 10 / enabled）。真实报错是 `ECOS-AUTH-010 缺少信任头`。定位过程：
1. 对照 `scenario_graph`（200）与 `calibers`（403），二者走同一客户端、同一 `assertReadable`；
2. 直接 `POST /api/v1/security/rls/apply` 带齐 `X-ECOS-USER/ROLE/TENANT` + userId → **200 `(1=1)`**；两个实体名在 security 侧表现**完全等价**（`noPolicyMatched=false`）；
