## 三、不到位清单（复盘核心，按严重度排序）

### S1（高）「蓝图构建向导」整体未向导化，十幕仅 4 幕有面
- §3.4 十幕中：幕1 W Agent 目标理解 ⬜（端点未核验显式留口，符合"禁 mock"但闭环缺一）；幕3 Gap 看板 🟡（仅 `BlueprintDetail` gaps 只读投影，无 §6.5 suggestedActions/requiresApproval 交互）；幕5 补齐依赖候选评审 🔁（评审面落在知识台而非向导流内，流程断裂）；幕7 回放/测试 🟡（tests 只读呈现，"固定数据集只读预览"未接）；幕10 运行反馈 ⬜（见 S2）。**其余幕为独立面板堆叠，无步骤编排/进度续作 UI**；L1"新建场景→启动向导"未实现（复盘 grep：`workbench/index.tsx` 零蓝图引用）。
- 后果：用户拿到的是"蓝图对象控制台"，不是设计承诺的"目标→发布→回流工作流"。

### S2（高）L3 运行与推演面未纳入本轮重构
- `forecast.tsx` grep **零命中** `blueprintVersion/contextDigest/traceId` 关联呈现（§3.2 L3 受控运行要求）；全 src **零命中** `exploratory`（§3.2/§2.3 反事实显式标注要求——推演结果与核算结果区分的防混淆护栏缺失）。
- Outcome 回流：`outcomesApi.ts`+`OutcomeQuadView`（详设-07 时代读面，挂 `decisions.tsx`）存在，但 §3.4 幕10「偏差诊断→更新候选进认知域候选状态机」的**回流环未接入** proposals 通道（proposals 仅知识台手工发起）。

### S3（高）§3.9 专项守护三件未齐（门禁强度低于设计口径）
1. 文档点名的 `FrontendStateMatrix.test.tsx` **不存在**；实际替代 = `sixStates.matrix.guard.tsx` **仅冻结 4 个面**（BlueprintPanel/CapabilityPanel/ContextBuildPanel/CognitiveAssetPage），CandidateReviewPanel/BlueprintDetail/StatusTrack/ValidatePanel/AdvancedDebug/L1/L3 均未入守卫。
2. 守卫是**结构断言**（状态判别联合+渲染分支存在+i18n 键+zh↔en 平权+禁假字面量），非"每态 × 4 主题"的**行为渲染断言**；权限态（403 不泄露存在性）与离态**无任何行为用例**（live E2E 走金路+降级白名单，未测 403/离线）。
3. §3.9 line369 要求的 **L1 首屏静态 grep 门禁**（Mind/Goal Tree/Causal/后端原始字段）**未建**——`__tests__` 零命中。§3.11 称"门禁口径不变"，复盘认定：**该门禁从未存在，属承诺未兑现而非口径不变**。

### S4（中高）主题 token 面存在"隐性失效"与既有债
- `ThemeContext.tsx` 预设值含 Tailwind **不存在的色阶类**：`indigo-650`/`emerald-650`/`purple-650`/`blue-450`/`purple-450`/`purple-350`（index.css 仅登记 royal-purple 的 `text-slate-450` 一例）→ 消费这些 token 的位点**无样式产出**（等同静默假实现）。同类散写还存在于 `GraphCanvas/AgentStudio/OntologyExplorer/cos/*`（非本批改造面，同缺陷族）。
- 遗留项 1 `fourThemesSixTabsNoRawColor` live 红 @ slate-light：token 值本身是色板字面类，属 #126/#122 既有债，本批显式不触碰全局主题系统——留痕合规，但**四主题观感与无障碍对比度未经行为验证**。

### S5（中）L2 operationEval 卡片原始 JSON 直排
- `workbench/[scenarioId]/index.tsx:192` `JSON.stringify(operationEval.data, null, 2)` 进 `<pre>`——正是 §3.1 批判技术视图"暴露后端原始字段"的形态，被原样带进了新 IA 的 L2。降级横幅/空态处理正确，但**未结构化呈现**，属过渡简实现，与重构目标自相矛盾。

### S6（中）议题1 承诺类型面不全 + 跨面跳转断链
- B 层可见类仅 BELIEF/HYPOTHESIS/MODEL 三治理类（`LIST_DISPATCH` 实证）；§1.2/§1.4.2 承诺的 **Decision Basis、经治理 Pattern·Case** 无实例面（受后端真实列表端点约束，§1.7 已如实登记，但 UI 亦无"该类暂缺列表端点"引导文案，用户无从得知边界）。
- §1.4.3 流程 3「卡片跳转来源场景/蓝图」**未实现**（Card/Drawer 无 router/href 跳转命中）——"引用不复制、跨面跳转"联动（§4.1 图）只剩单向。

### S7（中）候选评审卡必带字段不全（§3.5）
- 实证在面：未校准角标、conflict 态、traceId、分离动作；**未见** evidenceRefs 列表、assumptions、impact（affectedAssets/breakingChange）、回滚方案展示（对照补充设计 §7.2 候选协议）——护栏语义做了，字段完备性欠账。

### S8（中）"全绿"口径的边界（诚实登记，非虚报）
- 本机 Node 20：全量 `vitest run` 3 个 jsdom 文件无法起进程（含议题1 的 `KnowledgeView.i18n.test.tsx` **从未本机执行**）；Playwright 全量 22 skipped（合法空态/未就绪分支）**行为从未执行**、2 failed=登记基线。结论"三题相关用例全绿"成立，但**整库前端测试在本机不构成完整全绿**。

### S9（高·环境风险）交付滞留与基线分叉扩大
- 四批次 commit 未 push、未走 MR/PR 合入基线（Git规范 §一：合入基线必须走 MR）。
- 复盘实测分叉：merge-base 2026-09-30 后 `release/v2.1-alpha` 领先 366 commits（前端 210 个，+25k/−20k 行），`git merge-tree` 预演**前端冲突 59 文件**，其中 `aiworkbench/cognition/` 7 文件为「master 已删 / release 在改」的删改冲突，locale/BFF 测试/project-workbench tabs 为双写热点；release 侧波次4 与本批在 i18n/主题/收敛面上**并行同题异构**。越晚收口冲突代价越高。

### S10（低·债）迁移单源漂移
- V275/V276 属"迁移孤儿列"补列 replay（V200 ALTER SET SCHEMA 致 V192 对 live 表 no-op），根因是迁移脚本目录与开发库实态长期漂移；单源计数（231）与 V 号基线在合入 release 时需对账。

### S11（低·过程偏离，如实登记）红线⑦「仅前端、不改 Java/DDL」被实况突破
- §〇红线⑦约定本设计轮"不改 pom.xml/Java/网关/DDL，仅前端静态检查+单测"；实施期因 live 核验暴露真实后端缺陷（`ScenarioBlueprint` 实体 no-op、`ContextBuildErrorAdvice` 排序、`ScenarioDao` schema 前缀）与迁移孤儿列，经用户授权实跑后**实际动了后端与 DDL**（V275/V276 + 后端测试）。该突破有正当根因（不修则无法验证前端契约）且全程留痕于 §3.12/§3.13，但**批次边界口径已被改写**——复盘认定：后续同类"纯前端批次"应在开工前显式重划边界，而非事后追认。

## 四、根因分析

1. **契约核验前置未竟**：W Agent、蓝图批量端点、Decision Basis 列表端点未核验/不存在 → 按"禁假实现"铁律留口（正确的取舍），但**留口未升级为排期项**，导致向导/徽标/L3 三个关联面集体停摆。
2. **门禁以结构代行为**：选择 fs 静态断言路线（可复现、免浏览器），成本低但天然测不到渲染观感、403/离线行为、主题矩阵——S3/S4 的共同根因。
3. **历史债授权边界清晰但未外溢修复**：本批声明不动全局主题系统（合规），而新面消费的老 token 本身失效（S4），说明"不动债"策略需要显式的**债-面交叉登记**。
4. **验证环境受限**：Node 20 限制把"全绿"切成"口径绿"，S8 属环境而非代码，但汇报口径必须永远带限定语。
5. **分支治理空转**：基线应是 `release/*`（架构铁律/AGENTS 口径），本批产出却滞留孤悬 master 本地且与基线分叉扩大（S9）——流程执行（push+MR）缺位。

## 六、结论

三项改造的**核心承诺（真实契约直连、无假真理、治理/运行/能力三分、Blueprint 立为 L2 权威、双结构收敛）已达成且有 live 双证据**，缺陷五连闭环质量高、文档回写诚实（含 §3.7 勘误自纠）。主要不到位集中在**外围闭环**：向导整体流程化（S1）、L3 面（S2）、守护强度低于设计口径（S3）、token 静默失效（S4）、原始 JSON 直排（S5），以及**交付流程滞留**（S9）。按"彻底全面、不接受假实现"的用户标准衡量：已核验部分做实（成立），未核验部分显式留口（合规），但留口面之广使**需求侧验收尚不能宣布完整成立**——建议以 S9 合流为第一行动，再按 §五 排期收口。
