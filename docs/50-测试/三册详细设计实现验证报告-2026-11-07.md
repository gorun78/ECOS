## 六、缺陷与缺口清单

### P0-1 网关不承流 workspace 面（产品入口断裂）

- **证据**：#2/#3/#4。根因双点：`GatewayApplication` 以正则排除 `workspace.controller.*` 与 `workspace.twin.*`（同名 Bean 冲突，注释自述「workspace 端独立 :18090 已扫」）；`VersionPrefixRewriteFilter` 内 `workspace` 关键字 **0 命中**（今日 git grep HEAD）。
- **影响**：BFF 默认 gateway-first（`ECOS_LOCAL_DIRECT_SERVICE_PROXY=false`）⇒ **前端场景工作台全量 404**，除非本地解锁直连。这是「代码在、产品不通」的第一根因。
- **建议修法**：网关为 `/api/v1/workspace/**` 增加指向 :18090 的转发路由（与 5 服务同机制，**不要**扫 workspace controller——会复活 Bean 冲突）；新增门 `WorkspaceRouteCarrierGateTest`（路由/重写表必须含 workspace 前缀）+ 活体 200 探针用例。

### P0-2 心智读写分裂（注册成功、列表恒空）

- **证据**：#7/#8/#9/#15。写面走认知（预校验读到 count=1）；读面 `listMinds()`/mind-model 仍读 legacy `ecos_scenario_mind`（0 行）；v2 绑定表 3 行（1 active）。
- **影响**：UI 心智页空白、mind-model 404；「注册成功但列表为空」是最伤演示与信任的形态。工作树在途改动（`ScenarioMindService` +67 行）只改了写面与 unbind/activate，**读面未动**——即提交在途面也修不好 P0-2。
- **建议修法**：读面切认知查询 API（`/cognitive/minds` + 资产表），legacy 只作显式 not_available 兜底；补读写面一致性对账门；V319 mind 种子（未跟踪）评审后应用。

### P0-3 v1 种子蓝图 `gaps` 非 JSON（校验 fail-closed）

- **证据**：#6/#14。v2 RELEASED 校验通过、v1 `passed=false`（`Unrecognized token '缺口'`）。`docs/50-db_script/03-seed/entmgmt_demo_seed_v2_w6_ai_scenario.sql` 在工作树已改（未提交、未重放），live 仍旧数据。
- **修法**：v1 四行 `gaps` 规范为 JSON 数组（或空数组）重放；加种子形状 lint 门（全表 `gaps` 可被 JSON 解析）。**fail-closed 行为保持不动**——它是对的。
