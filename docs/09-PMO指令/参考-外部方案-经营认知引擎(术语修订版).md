## 一、整体定位与核心目标

**定位**：区别于 BI（看过去）、LLM（聊文本），认知引擎 = **企业经营心智系统**

- 持久保存企业对市场、竞品、供应链、经营变量的「假设 + **不确定性判断**概率」
- 持续接收新证据自动更新认知
- 结构化反事实推演经营方案收益与风险
- 全链路可审计、可复盘、可人工干预

**四大工程目标**：
1. 认知可持久化：不确定性判断、假设、推理路径落库
2. 认知可迭代：新数据自动修正旧判断
3. 决策可推演：支持"如果这么做会怎样"的经营模拟
4. 结论可解释：每一个经营结论有证据、假设、概率来源

## 二、整体五层软件架构（工程落地版）

### 层1：感知接入层（证据采集层）
把所有内外部信息统一转化为「可被引擎消费的结构化证据」。

| 组件 | 说明 |
|---|---|
| 多源数据连接器 | ERP/CRM/OA/库存/财务直连；爬虫/舆情/研报 PDF 解析；人工专家录入端 |
| 文档解析与实体抽取服务 | LLM 抽取：事件、主体、时间、观点、变化 |
| 证据可信度打分器 | 系统数据 95–100% / 权威新闻官宣 80% / 小道消息 30–50% |
| 证据冲突检测器 | 同一事实多条证据不一致 → 标记冲突待修正 |

**输出物**：标准化证据结构体（入库）

### 层2：业务本体与事实知识库（确定性知识）
存储永远不变或极慢变的企业业务公理与事实。

- 业务本体管理后台（产品/客户/渠道/竞品/供应链/指标体系）
- 经营指标公式引擎（毛利、净利、库存周转、销量弹性、渠道成本，可配置）
- 事实库（只读确认数据：历史财报、历史销量、已发生事件）
- 业务规则引擎（销量 ≥ 0、成本逻辑、价格区间约束）

**存储**：Neo4j（本体关系）+ 指标规则库 + 经营事实大表

### 层3：**不确定性判断与假设管理层（认知核心——心智层）** ⭐
整个系统最独特、区别于所有 BI/AI 产品的核心。

**3.1 假设管理模块（H 库）**：每条假设结构化存储
- 核心能力：自动监测证据是否触发「假设失效」
- 假设失效 → 自动下游推演作废 + 告警

**3.2 不确定性判断概率管理模块（P 库）**：
对不可观测经营变量维护概率分布（竞品降价概率、原材料涨跌概率、需求弹性区间概率等）。
工程实现（轻量化，不搞复杂贝叶斯网络）：
- 关键变量**有限离散概率分布**
- 新证据到来 → **加权贝叶斯更新**
- 支持**人工覆写**（专家干预）

**3.3 认知盲区检测**：自动识别无证据、无假设、无不确定性判断覆盖的经营变量，
输出「本次决策信息缺失清单」

### 层4：推理推演层（思考层）
基于「事实 + 当前不确定性判断 + 有效假设」做经营仿真推理。

| 组件 | 说明 |
|---|---|
| 正向情景推演引擎 | 自动生成 N 种未来经营情景（高/中/低景气、竞品动作情景） |
| **反事实推理引擎（杀手锏）** | do(A) 干预式模拟：如果涨价 5% / 如果扩产 / 如果竞品降价 → 销量/毛利变化 + 风险概率 |
| 风险量化引擎 | 每方案输出：期望收益、最大回撤、亏损概率、波动区间 |
| 敏感性分析引擎 | 自动找出影响结论 Top3 核心变量 |

工程实现：情景蒙特卡洛采样（轻量 1000 次模拟）+ 业务公式建模 + 概率扰动；LLM 负责因果链条解释

### 层5：决策交互与审计层
- 决策推演工作台（方案对比视图 / 不确定性判断可视化 / 假设依赖图谱 / 敏感性分析图表）
- 人机干预模块（人工改概率、改假设、增删情景）
- 全链路审计系统（每次推演：证据 ID、假设 ID、不确定性判断版本、参数、结果全部存版）
- 智能告警（假设失效 / 不确定性判断大幅变动 / 决策结论失效）

## 三、核心数据流（完整闭环）

```
感知层采集新证据
  → 证据更新不确定性判断 / 检验假设是否失效
  → 刷新全局经营认知状态
  → 推理层自动重算情景与方案
  → 输出更新后的决策建议、风险、敏感点
  → 人机确认 + 全链路审计落库
```

## 四、与传统系统的核心差异（工程视角）

| 系统 | 差距 |
|---|---|
| BI | 只有历史事实数据，无概率、无假设、无仿真 |
| 普通 LLM | 无持久化认知库、无假设监测、无结构化推演、无审计 |

认知引擎独有工程能力：
1. **假设生命周期管理**（业界几乎没有产品化）
2. 经营不确定性判断持续迭代更新
3. 可审计的反事实经营仿真
4. 决策依赖溯源图谱

## 五、技术栈落地选型（原稿口径，ECOS 适配见下）

- Java/Go 微服务；自研轻量表达式引擎（规则）
- Python 数值计算服务（原稿口径——**ECOS 不采纳，蒙特卡洛并入 Java 主链路**）
- MySQL 业务配置 + 假设 + 不确定性判断主数据；ClickHouse 证据/行为/时序（**ECOS 映射 Doris ultimate 档，standard 档 PG 承载 MVP**）；Neo4j 本体；Redis 实时认知状态缓存（**ECOS 暂不引入**）
- 通用 LLM API 做证据抽取/因果解释/报告生成；**不依赖大模型做核心计算**（与 ECOS ADR-8 同向）

## 六、最小 MVP 落地范围（原稿"30 天"口径，ECOS 按 Sprint 重排）

1. 接入：竞品新闻、价格数据、销售数据
2. 实现：假设管理、**不确定性判断**概率更新
3. 实现：三方案定价推演（高/中/低）
4. 输出：收益对比、风险概率、敏感因素、依赖假设
5. 实现：假设失效告警

## 七、三张核心表（最关键）

1. **证据表**（层1）
2. **经营假设表**（层3核心）
3. **经营不确定性判断概率表**（层3核心）

> 原稿断言："有这三张表，就是认知引擎；没有就是普通数据分析系统。" —— ECOS 采纳，作为 PMO-54 验收口径。

## 八、一句话总结

**数据变成证据，证据更新不确定性判断，不确定性判断驱动推演，推演支撑决策，
全程可审计、可迭代、可干预。**
