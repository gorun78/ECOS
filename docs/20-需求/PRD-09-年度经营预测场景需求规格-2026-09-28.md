## 一、REQ-FC-01 财务口径治理（P0）

### 1.1 数据模型（DDL 草案，遵循 DR01~08 + PRD-01 DDL 模板）

```sql
CREATE TABLE IF NOT EXISTS ecos_fc_caliber (
    id                VARCHAR(36) PRIMARY KEY DEFAULT gen_random_uuid(),
    caliber_code      VARCHAR(50)  NOT NULL,             -- 如 MANAGEMENT_FORECAST
    caliber_name      VARCHAR(200) NOT NULL,             -- 业务名「管理口径-年度经营预测」
    version           INT          NOT NULL,             -- 单调递增,同 code 内唯一
    status            VARCHAR(20)  NOT NULL DEFAULT 'DRAFT',  -- DRAFT/PENDING_APPROVAL/APPROVED/SUPERSEDED
    formula_json      JSONB        NOT NULL,             -- 公式 DSL(见 1.2),_json 后缀 DR04
    effective_from    VARCHAR(7)   NOT NULL,             -- 'YYYY-MM'
    effective_to      VARCHAR(7),                        -- NULL=长期有效
    accounting_map_json JSONB,                           -- 管理口径→会计科目映射(可空,首期登记文本级)
    approved_by       VARCHAR(100),
    approved_at       TIMESTAMP,
    change_reason     VARCHAR(500),                      -- 新版本必填
    create_time TIMESTAMP NOT NULL DEFAULT NOW(), update_time TIMESTAMP NOT NULL DEFAULT NOW(),
    create_by VARCHAR(100), update_by VARCHAR(100),
    version_no VARCHAR(20) NOT NULL DEFAULT '1', is_deleted SMALLINT NOT NULL DEFAULT 0,
    domain VARCHAR(50) NOT NULL DEFAULT 'default',
    CONSTRAINT uniq_fc_caliber_code_ver UNIQUE (caliber_code, version)
);
CREATE INDEX IF NOT EXISTS idx_fc_caliber_status ON ecos_fc_caliber(status, effective_from);
```

### 1.2 公式 DSL（受限表达式,非图灵完备）

```
Grammar（EBNF 摘要）:
  formula   := IDENT '=' expr
  expr      := term (('+'|'-') term)*
  term      := factor (('*'|'/') factor)*
  factor    := NUMBER | IDENT | IDENT '[' IDENT ']' | '(' expr ')' | FUNC '(' args ')'
  FUNC      := SUM | ROUND | MIN | MAX | IF        -- 白名单函数,禁任意代码
  IDENT     := 指标码(M_*) | 事实字段(stage.contract_base 等) | 维度(project/department/period/stage)

示例（环节额公式,与附件 §3 一致）:
  M_STAGE_AMT[stage] = stage.contract_base * attribution.ratio * stage.realization_rate
  M_FC_REVENUE       = SUM(M_STAGE_AMT[ACCEPTANCE])
  M_FC_PROFIT        = M_FC_REVENUE - SUM(M_COST_SALARY) - SUM(M_COST_MGMT) - SUM(M_COST_MKT)
```

**校验规则（保存前静态校验,违一即 400）**：
- V1 语法：DSL parser 通过（自研递归下降,禁引入脚本引擎执行任意表达式）。
- V2 引用闭合：所有 IDENT 可解析到 ONTO-02 指标注册表或 PRD-02 事实表字段。
- V3 量纲一致：金额×比率=金额；禁金额+比率直加（复用 PRD-03 ONTO-01 发布门禁 V2 的单位元数据）。
- V4 无循环依赖：公式图拓扑排序通过。

### 1.3 版本与审批铁律

1. **APPROVED 版本不可变**：修订=创建 `version+1` 新行（`change_reason` 必填），旧版置 `SUPERSEDED`（禁 UPDATE formula_json，禁物理删）。
2. 审批流：`DRAFT → PENDING_APPROVAL →（财务角色批准）→ APPROVED`；批准动作发 Kafka 审计（PRD-07）。
3. **公式不得硬编码为系统"营收"**：全系统"收入/利润"语义一律经 `caliber_id@version` 解引用；任何代码出现写死的营收公式 = 验收失败。
4. 旧预测可复现：forecast run 冻结 `caliber_snapshot_json`（PRD-03 ONTO-02），口径升版不影响历史 run。
5. 生效期裁决：run 创建时按 `asOfTime` 落入 `[effective_from, effective_to)` 的 APPROVED 版本自动选缺省，允许人工指定历史版本（复现用途）。

| GET | `/api/v1/workspace/calibers?code=&status=` | 目录（含版本链） |

### 1.5 验收标准（附件步骤 1）

1. 任一参与者可从口径页面/接口看到 `MANAGEMENT_FORECAST` 的版本列表 + 生效期 + 批准人。
2. 修改已 APPROVED 口径 → 只能产生新版本；对旧 run 重放结果不变（幂等复现用例）。
3. DSL 校验 4 类违规夹具全部 400 且错误信息定位到符号位置。

## 二、REQ-FC-02 确定性预测运行服务（P0）

### 2.1 运行生命周期（状态机）

```
CREATED → DATA_CHECK → SNAPSHOT_FROZEN → RUNNING → SUCCEEDED
              │               │              │
              ▼               ▼              ▼
           FAILED(DQ_BLOCK) FAILED(快照失败) FAILED(计算/六要素缺失)
```

| 态 | 动作 | 失败处置 |
|:--|:--|:--|
| CREATED | `POST forecast-runs`（wizard 第 4 步提交），生成 runId，参数：scenarioId/caliberId@version/asOfTime/periodRange/projectSet/departmentSet/overrides(可空) | 参数校验 400 |
| DATA_CHECK | 调 PRD-02 DQ 门禁：范围内事实行齐备性 + PUBLISHED 态检查 | BLOCK 级 → FAILED，错误清单写 run.error_json，前端跳 FE-03 待办 |
| SNAPSHOT_FROZEN | 写 `ecos_forecast_input_snapshot`（PRD-02 DATA-01 表五）：fact_refs + 指标/画像/假设版本 + caliber 快照 + checksum；**冻结后源数据变更不影响本 run** | 快照写失败 → FAILED，禁半冻结 |
| RUNNING | 提交 `ITaskManagementService.submitTask + executeTask`（铁律 §1.6，同步等待派发；>50 项目或 >10 万行走异步,见 FC-07），执行 2.2 计算规格 | 计算异常 → FAILED + 堆栈入日志（禁吞异常） |
| SUCCEEDED | 结果明细落 `ecos_fc_result_detail`（见 2.3），六要素完备性自检（FC-03）通过后才置 SUCCEEDED | 自检失败 → FAILED（宁可失败不可缺要素成功） |

**幂等重跑**：相同 `(caliberVersion, asOfTime, scopeHash, scenarioSet, overridesHash)` 且既有 SUCCEEDED run → 默认返回既有 runId（响应 `reused: true`）；`force=true` 才新建 run，新 run 明细与旧 run **diff=0**（金额逐行相等,验收基准）。

### 2.2 计算规格（BigDecimal,HALF_UP,scale 见 PRD-01 DB-04）

**实现率取值优先级（每个 项目×部门×期间×环节 独立裁决,来源必记录）**：

| 优先 | 来源 | source_type | 附加要求 |
|:--:|:--|:--|:--|
| 1 | 已发布 ACTUAL 事实行 | `ACTUAL` | — |
| 2 | 已发布 PLAN 事实行（项目计划） | `PROJECT_PLAN` | — |
| 3 | 画像补齐（PRD-04 KB-02 resolve API） | `PROFILE_IMPUTED` | 记录 profile_version + 置信档（HIGH/MEDIUM/DEGRADED），run 明细标注 |
| 4 | 人工覆盖（wizard 第 3 步） | `MANUAL_OVERRIDE` | 必须已 APPROVED 假设（KB-03），记录 assumption_key + 审批人 |
| — | 四者皆无 | — | 该格 FAILED 前置检查拦截（DATA_CHECK 阶段判缺失,禁静默取 0 或均值） |

**环节额与聚合**：

```
环节额(项目p,部门d,月m,环节s) = contract_base(p,合同变更版本) × attribution_ratio(p,d,effective_from≤m) × realization_rate(p,d,m,s)
聚合顺序（严格自下而上,禁跨层重算）:
  环节 → 项目×部门×月 → 部门×月 → 项目 → 企业
每层聚合 = 下层 SUM（BigDecimal.add），三级平衡断言:
  |企业利润 − Σ部门利润| = 0 （精确相等,非容差——BigDecimal 无浮点误差）
```

**区间（P10–P90）**：来自画像统计（KB-02 p10/p90 字段）按环节额加权合成，合成算法确定性（同输入同输出）；**禁 LLM 生成或修饰区间数字**。区间合成公式登记于 caliber formula_json（`M_STAGE_AMT_P10/P90`），版本化。

**情景/反事实**：overrides 结构走 PRD-05 COG-03 裁定——**计算主体在本服务**（forecast-run 按 overrides 重算受影响格子），cognitive 只做归因解释；本服务提供 `POST /forecast-runs/{runId}/scenario-copy`（结构化复制 + overrides 注入）。

## 三、REQ-FC-03 结果六要素（P0）

### 3.1 六要素断言点（缺一即 FAIL/拒绝）

| 要素 | 载体 | 断言点 |
|:--|:--|:--|
| forecastRunId | run 主键 | 创建即生成；所有结果/证据/导出 API 强制路径参数 |
| caliberId(@version) | run.caliber_id + formula_version | DATA_CHECK 前校验口径 APPROVED 且生效期覆盖 asOfTime |
| asOfTime | run.as_of_time | 必填；快照冻结时刻 = asOfTime 语义（快照内容以该时刻可见数据为准） |
| 输入快照 | snapshot_id → `ecos_forecast_input_snapshot` | SNAPSHOT_FROZEN 态必须非空 + checksum 可验 |
| 公式 | formula_version + caliber_snapshot_json | 明细行 formula_version 非空；渲染文本可由快照重建 |
| 证据引用 | result.source_ref_json | SUCCEEDED 前逐行自检：COMPUTED 行有下层引用，叶子行有事实行 ID/画像/假设引用 |

### 3.2 不可篡改铁律

1. SUCCEEDED run 的明细/快照/口径快照**只读**——源数据后续变更、口径升版、假设过期均不回写历史 run（DB 层：run SUCCEEDED 后 UPDATE 明细 → 应用层拒绝 + Mapper 审查）。
2. **禁以 AI 文本替代要素**：AI 回答中的数字必须引用 run 结果（PRD-06 AI-04 引用块），无 runId 引用的金额类回答被拒答规则拦截。
3. 展示层"已关账实际替换预测展示"（FC-05）是**视图层并排**，非覆盖 run 数据。

### 3.3 验收

1. 人为构造缺要素夹具（快照空/公式版本空/证据空）→ run 状态 = FAILED，error_json 指明缺失要素。
2. SUCCEEDED 后修改源事实行 → 重查 run 结果不变；新 run（新 asOfTime）反映新数据。
3. 六要素完备标记在 FE-02 证据抽屉显示 ✓×6（PRD-08 §6.3）。

## 五、REQ-FC-05 回测与滚动预测（P1）

### 5.1 期间锁定与回灌

1. 期间状态表/字段：`period_status(YYYY-MM) = OPEN | CLOSED`（关账由财务角色操作,发审计事件）。
2. **CLOSED 期间**：ACTUAL 事实导入仍允许（关账后补录走审批），但**预测 run 的 asOfTime 落入 CLOSED 期间 → 该期展示切换为实际值**（视图层并排,§3.2-3）；历史快照永不覆盖。
3. 回灌 = PRD-02 事实导入管道（ACTUAL 行 + DQ 门禁），无独立回灌通道。

### 5.2 回测指标（对每个 已关账期间 × 粒度{项目|部门|环节}）

| 指标 | 公式 | 守卫 |
|:--|:--|:--|
| MAE | Σ\|预测−实际\| / n | — |
| MAPE | Σ(\|预测−实际\| / \|实际\|) / n | 实际=0 的格子剔除并计入 `zero_actual_count` 披露,禁除零、禁以 1 兜底 |
| 偏差方向 | Σ(预测−实际) 符号 → OVER_FORECAST/UNDER_FORECAST/BALANCED | — |
| 区间覆盖率 | 实际 ∈ [P10,P90] 的格子数 / n | n<5 → 标 `LOW_SAMPLE` 不参与告警 |
| 数据覆盖率 | 该期 ACTUAL source 格子数 / 应预测格子数 | — |

回测结果落 `ecos_fc_backtest`（run 对比期粒度一行,含上述 5 指标 + 审计字段 + domain/version_no,同模板）。

### 5.3 复审任务生成（阈值驱动）

```
触发条件（任一）: MAPE > 15%  或  区间覆盖率 < 80%  （阈值可配 ecos.fc.backtest.review_threshold.*）
产出: 「需复审」任务 → 按对象归属路由:
  画像偏差(PROFILE_IMPUTED 格子集中超标) → 复审画像 → KB-02 生成新版本(PUBLISHED 旧版 SUPERSEDED)
  假设偏差(MANUAL_OVERRIDE 格子超标)     → 复审假设 → KB-03 走 EXPIRED/SUPERSEDED + 新假设审批
任务分派: 画像 → 知识管理员角色; 假设 → 财务+经营负责人角色(原审批人回避)
```

- 滚动预测 = 关账后以新 asOfTime 重开向导（新 run），旧 run 保留——**禁"自动改历史 run 为滚动值"**。

### 5.4 验收（附件演练 5 后半段）

1. 回灌 8 月实际 → 该期展示"预测 vs 实际"并排；历史 run 快照 checksum 不变。
2. 注入偏差夹具（预测 100 实际 80）→ MAPE=25% → 自动生成复审任务且路由正确角色。
3. CLOSED 期间再建 run → asOfTime 该期显示实际值；系统拒绝任何覆盖历史 run 的写路径（负向用例）。

## 七、REQ-FC-07 规模与运维（P1）

1. **委托 runtime-task（铁律 §1.6）**：预测运行 >50 项目 或 快照事实行 >10 万 → RUNNING 态转异步：`submitTask` 返回真实 taskId，前端 AsyncTaskCenter + run 进度页消费 `td_runtime_task_status`（progress/log/重试）；**禁自建任务表/自造 jobId**（响应回 taskId + status=SUBMITTED）。
2. 重试：FAILED run 可 `POST /forecast-runs/{runId}/retry`（从 DATA_CHECK 重入,复用原参数；SNAPSHOT_FROZEN 之后失败则从快照重算,不重冻快照）。
3. **runtime-monitor 监控指标**（登记监控项,禁自建监控）：run 耗时 P95 / DATA_CHECK 失败率 / DQ BLOCK 数趋势 / 回测 MAPE 均值 / 事实数据时效（最新 ACTUAL 期间 vs 当前期间差）。
4. 页面不阻塞：异步 run 期间向导/总览可导航，进度经任务中心轮询（FE-08 优化后增量）。

验收：注入 >50 项目夹具 → run 走异步 + 任务中心可见进度；kill 计算进程 → FAILED + retry 从快照恢复成功；监控面板 5 指标可查。
