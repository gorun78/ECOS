## 四、冲突与不合理项清单（供用户裁决，WC-01~WC-19 → R-31~R-49）

> 格式：**主张（附件出处）** / **实测事实（证据）** / **规则条文** / **影响** / **备选与推荐**

### WC-01 W 的语义定义与铁律直接冲突
- 主张：全体系称"W Agent"；一册 A-01 把五大 Engine 解为 D/I/K/C/**W=Decision**；二册 §1.3"Agent 归属 AI Engine 域之上"。
- 事实：铁律 v2.0 :63/:221 明文"**禁止 AI=W / LLM=W / Agent=W**"，W 核心为 `Decision / Strategy / Policy / Action / Execution`，AI 只是实现 W 的技术手段；:253 已把 ai-engine 定义为"火（W 智慧/决策与行动）"。
- 影响：若照附件命名与分层写进 PRD/ARCH，等于在需求层确立"Agent=W"，Reviewer 依铁律判 FAIL。
- 推荐：**保留"W Agent"为产品代号**，在 PRD-00 术语表与 ARCH_SPEC 术语节加显式辨析（W Agent = 面向 W 域的 Agent 族群之编排主体，W ≠ Agent），并把附件的"W=Decision Engine"改写为"W 域由 ai-engine 承载"。→ **R-31**

### WC-02 "五大 Engine"与 ECOS 六引擎+横切+场景层不同构；Decision 归属两处
- 主张：二册 §10 边界总表列 Data/Ontology/Knowledge/Cognition/**Decision(W)** 五 Engine。
- 事实：ECOS = 六引擎（security-护 :18081 + data-土D :18082 + ontology-金I :18083 + kb-水K :18086 + cognitive-木C :18089 + ai-火W :18084）+ 四转化（格致诚明）+ runtime-器 + workspace 场景层；决策数据当前**分裂两处**——cognitive 侧 `/api/v1/cognitive/decision` + `ecos_decision*`（V103/V151），ai 侧按铁律 :235 持有"Decision Action Orchestration"。
- 影响：Engine 映射不对齐则 §10 边界、Tool 归属、权限点全部错位。
- 推荐：映射表落 ARCH_SPEC——附件 Cognition Engine→cognitive-engine；Decision Engine(W 域)→**ai-engine 为 Owner**；cognitive 现有 `ecos_decision*` 定性为附件 §16.2 的 **Decision Basis（属 C）**，不改表不改 API（API 只增不改），由 ai-engine 侧新增 Decision/Option/Action 对象承接附件 §8/§9。→ **R-32**

### WC-03 表前缀与 Schema 落位违反 ST07
- 主张：三册 §1.1"Agent 控制面库，`agt_` 前缀表"、§1.2 `agt_*`、附录 A `aim_*`（AI 工作台）/`cog_*`（Cognition）。
- 规则：ST07"引擎 schema **仅五枚举** `ecos_data/ecos_ontology/ecos_knowledge/ecos_ai/ecos_cognitive`；`CREATE SCHEMA` / 新表落新引擎 schema = FAIL"，且五枚举内容**已明写** ecos_ai = "Agent/Loop 定义"、ecos_cognitive = "认知模型"；DR01+§四"表名必须带 schema 限定，裸表名 = FAIL"。
- 影响：附件三册全部 DDL（约 20 张表）落位方式不合规，lint 与 Reviewer 双 FAIL。
- 推荐：Agent 控制面 → `ecos_ai`（附件 `agt_` 段改名对齐 ECOS 命名规范，具体表名前缀以 DR 系列定稿）；模型与能力（附件 `aim_`）→ `ecos_ai`；认知模型（附件 `cog_`）→ `ecos_cognitive`；不新建 schema、不新建"Agent 控制面库"。存量 `ecos_agent` 相关表定性为 knownLegacy（只停写）**或** 另立 PMO 迁移批次，两者须用户裁定。→ **R-33**（存量另立 **R-34**）
