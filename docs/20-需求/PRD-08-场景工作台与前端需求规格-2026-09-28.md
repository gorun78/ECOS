## 一、REQ-WS-01 业务场景语言入口（P0）

### 1.1 需求陈述

场景工作台首页以业务语言呈现（如"2027 年度利润预测"），经营用户从首页 **3 步内**进入预测向导；不要求用户先理解 Goal/Causal/Scenario/Mind 技术对象；底层组件复用，信息架构不绕路。

### 1.2 信息架构（IA）细化

**首页（`#/workbench` 场景列表态）三层结构**：

```
① 我的场景卡片区（业务语言）
   卡片字段: 场景名(业务命名) / 状态徽章(DRAFT草稿|ACTIVE运行中|SUSPENDED已挂起|COMPLETED已完成)
             / 最近运行时间 / 完整度环(见 WS-02) / 主操作按钮
   主操作按钮按状态变化:
     DRAFT    → 「继续搭建」(进沙盘编排)
     ACTIVE   → 「查看结果」(进利润总览 FE-02) + 「新建预测」(进向导 FE-01)
     SUSPENDED→ 「恢复」(需 scenario:write)
② 快捷入口区: 「新建业务场景」(四步向导起点) / 「数据质量待办」(FE-03 聚合卡)
③ 技术视图折叠区(默认收起): Goal Tree / Causal Graph / Scenarios Tab 原技术入口
   —— 保留可达(组件复用)，但不在首屏主张；折叠区标题「高级视图(技术)」
```

**3 步路径定义（验收基准）**：

| 步 | 用户动作 | 系统响应 |
|:--:|:--|:--|
| 1 | 登录进入 `#/workbench` | 场景卡片列表（业务语言命名，无 Goal/Mind 术语） |
| 2 | 点击 ACTIVE 场景卡「新建预测」 | 直接进入该场景的预测向导第 1 步（范围已预填场景绑定） |
| 3 | 向导第 1 步确认范围 → 「下一步」 | 进入数据检查步（第 2 步），路径成立 |

**术语映射表（前端 i18n 强制，禁硬编码中文 → 走 `useLanguage()`）**：

| 技术对象 | 业务语言（zh-CN） | 出现位置约束 |
|:--|:--|:--|
| scenario | 业务场景 | 首屏可见 |
| forecastRun | 预测运行 / 一次预测 | 首屏可见 |
| Mind / capability | 分析能力 | **仅高级视图**出现 |
| Goal Tree | 目标拆解（高级） | 仅折叠区 |
| Causal Graph | 因果分析（高级） | 仅折叠区 |
| binding | 场景资源 | 沙盘内 |
| caliber | 财务口径 | 向导第 3 步、口径页 |

### 1.3 边界与禁令

- 禁止为业务语言化而**复制**一套新组件——技术视图与业务视图共用 `ScenarioDetail` 数据层，仅呈现层分流（前端铁律：禁重复组件）。
- 禁止在首屏暴露 `scenarioId`/`bindingType` 等原始字段名；URL 可含 `?scenarioId=` 但页面文案用场景名。
- 名词排他（铁律 §0.6.3）：本工作台「场景」≠ AI 域「项目跟踪」（`pages/ProjectTracker.tsx`），i18n key 分属 `workspace.*` 与 `aiworkbench.*` namespace，禁混用。

### 1.4 验收标准

1. Playwright：登录后 ≤3 次点击到达向导第 2 步（数据检查），断言路由与页面标题。
2. 首屏 DOM 文本扫描：无 "Mind"/"Goal Tree"/"Causal" 字样（折叠区展开后允许）。
3. 4 主题（slate-light/deep-space/cyber-terminal/royal-purple）下卡片区无硬编码色（grep `bg-white|bg-slate-|text-gray-` 0 命中于新增文件）。
4. zh/en 切换后全部文案变化（i18n 覆盖率 100%，无硬编码中文）。

## 二、REQ-WS-02 场景组成模型完整度（P0）

### 2.1 需求陈述

子图+横切+出口六类绑定三层可视化；完整度=**连边覆盖率**（铁律 §0.6.2，禁按绑定数量算分）；孤岛绑定拒绝。

### 2.2 可视化规格

**三层布局（沙盘画布，@xyflow/react）**：

```
┌─ 链路层（横向主轴，有序）──────────────────────────┐
│  [DATASET] ──映射──► [OBJECT_TYPE] ──抽取──► [KNOWLEDGE_BASE] ──认知──► [AI_AGENT] │
│      数据集            业务对象              知识库                 智能体/动作    │
└──────────────────────────────────────────────┘
┌─ 横切层（覆盖带，画布顶部色条）─┐   ┌─ 出口层（主轴右端外挂）─┐
│ SECURITY_POLICY × n（点击看作用域）│   │ INTERFACE × n（暴露面清单）│
└─────────────────────────┘   └─────────────────────┘
```

- 边渲染：实线=已建立（有契约引用），虚线红=缺失必需边（见 2.3 E_req）。
- 每条链路边 hover 显示契约来源（如映射边 → `ecos_entity_table_mapping` 记录数 + 最近校验时间）。

### 2.3 完整度算法（与 PRD-01 PLT-13 同源，前端只消费不重算）

> **v1.2 定版（R-27 ①）**：分母**固定为 3**（映射／抽取／认知三类必需边），**不按已绑定节点动态推导**——动态分母会使"只绑 1 个节点"的场景自动 100%，与"完整度"语义相反；固定分母下取值自洽为 `1.0／0.67／0.33／0`（单测夹具断言）。必需边口径**抽为单一挂载位 `RequiredEdgePolicy`**（后端一处定义，workspace／向导闸门／前端环全部消费同一输出，禁第二处重算）。

```
coverage = |E_present ∩ E_req| / 3          -- R-27 ①：分母固定 3
E_req（固定三类）:
  映射边  DATASET → OBJECT_TYPE        （必需，ecos_entity_table_mapping 契约）
  抽取边  OBJECT_TYPE → KNOWLEDGE_BASE （必需，KB 抽取契约）
  认知边  KNOWLEDGE_BASE → AI_AGENT    （必需，认知模型契约）
E_present: ecos_scenario_binding_link 中 source/target 均已绑定且契约校验通过的边
```

- 后端 API：`GET /api/v1/workspace/scenarios/{id}/completeness` → `{ coverage: 0.67, requiredEdges: [...], presentEdges: [...], islands: [...] }`（前端禁止自行遍历 binding 表算分）。
- 展示：完整度环（0–100%）+ 缺失边清单（业务语言："数据集《合同台账》尚未关联业务对象《合同》"）。

### 2.4 孤岛绑定拒绝（交互 + 后端双闸）

> **v1.2 定版（R-26 ②）**：孤岛校验是**同一份实现的两个挂载位**，不是两条规则——`addBinding()` 挂载位**容忍中间态**（打标不拒写），`transition(ACTIVE)` 挂载位**拒绝**（409）；两处必须调用同一校验器（禁两套判定逻辑导致"DRAFT 能存、ACTIVE 永远激活不了"或反之）。

| 场景 | 前端行为 | 后端行为 |
|:--|:--|:--|
| 绑定新节点后形成孤岛（无任何边可达主链） | 保存时弹确认："该资源未与场景链路连接，保存后场景完整度不增加，且无法参与预测运行" — 允许保存为 DRAFT 但在节点上打灰色「孤岛」角标 | `POST bindings` 返回 `isIsland: true` 标记（不拒绝写入，DRAFT 态容忍） |
| 场景激活（DRAFT→ACTIVE） | 阻断按钮 + 列出孤岛清单 | **409 拒绝**：`{ code: "ISLAND_BINDING", islands: [...] }`（铁律 §0.6.2-1） |
| 预测向导选择场景 | 仅列 ACTIVE 场景 | 向导第 1 步 API 过滤 `status=ACTIVE AND coverage>0` |

### 2.5 验收标准

> 验收一律可执行标识（Q13 + R-58 ①：质量门禁不得以"跳过测试"换绿灯）；**下列测试类／spec 实测尚未创建 ⇒ 记"未执行"**，P-3 Playwright 工程（任务 #30）建成前不得宣称通过（铁律 :14）。

1. 单测：coverage 算法 5 组夹具（固定分母 3：全链 = **1.0**；缺 1 类 = **0.67**；仅 1 类 = **0.33**；纯孤岛 = **0**；重复边不加分）→ `mvn -Dtest=ScenarioCompletenessPolicyTest#coverageUsesFixedDenominator`；`RequiredEdgePolicy` 单挂载位一致性 → `mvn -Dtest=RequiredEdgePolicyTest#singleSourceForAllMounts`。
2. E2E：绑定孤岛节点→激活→断言 409 与前端阻断文案 → `pw scenario-island.spec.ts`「孤岛节点可存 DRAFT、激活被 409 阻断」；两挂载位同源 → `mvn -Dtest=IslandValidationMountsTest#sameValidatorAtAddAndTransition`。
3. 画布截图基线：4 主题 × 有/无缺失边 共 8 张，边色/角标可辨。
4. `ecos_scenario_binding_link` 行数与 presentEdges 一致（SQL 对账脚本）。

## 四、REQ-WS-04 沙盘演练隔离（P1）

### 4.1 规格

1. 沙盘内触发的认知演练（诊断/预测/仿真/反事实）产生的一切运行记录带 **`run_mode=SANDBOX`**（v1.2 按 **R-25 ①** 定版：**新增正交列 `run_mode FORMAL／SANDBOX`**，**不扩既有 `ecos_scenario_run.run_type` 枚举**——原写"复用 run_type"与批准口径冲突已更正；`run_type` 承载"运行种类"、`run_mode` 承载"是否沙盘"，两维正交）。列落 DDL 单源目录的迁移脚本文件（不实跑库）。
2. **不污染生产事实**：演练禁止写 D 层事实表（PRD-02 五表）、禁止写 `ecos_biz_action_outcome`；违规写路径由 ArchUnit + Mapper 审查拦截（SANDBOX 上下文中的写 DAO 白名单仅 run/layout 表）。
3. 正式运行（`run_mode=FORMAL`）**不得引用** SANDBOX 产物：forecast-run 服务校验 `baselineRunId` 的 **`run_mode`**，SANDBOX→400 `{ code: "SANDBOX_REF_FORBIDDEN" }`。
4. 演练结果 UI 必须带持久水印角标「演练」（非 toast 瞬态），导出文件同名前缀 `[演练]`。
5. 真接引擎（铁律 §0.6.4-3）：演练经 services REST 真调 cognitive/forecast 引擎，禁 stub 哈希当结论；网络面板断言演练触发真实 `POST /api/v1/cognitive/*`。

### 4.2 验收标准

1. 演练后 SQL 对账：五事实表 + outcome 表行数不变。
2. FORMAL run 引用 SANDBOX baseline → 400 用例通过。
3. 演练导出 CSV 文件名含 `[演练]`；截图含水印角标。

## 五、REQ-FE-01 预测向导四步流（P0）

### 5.1 步骤规格

| 步 | 名称 | 字段与默认值 | 校验（当前步阻止） | 覆盖率/影响说明 |
|:--:|:--|:--|:--|:--|
| 1 | 范围 | 场景(默认当前)、预测期间 `period` YYYY-MM~YYYY-MM(默认未来 12 月)、项目集(默认场景绑定全量,可多选)、部门集(默认按归属比例表推导) | 期间起>止→阻止；项目集空→阻止 | 显示"覆盖 N 个项目 / M 个部门，占场景绑定 X%" |
| 2 | 数据检查 | 只读检查结果列表（调 PRD-02 DQ 门禁 API）：每项目×环节的事实行齐备性、已关账期间标记、DQ 状态 | 存在 `BLOCK` 级缺失（必需事实行缺）→「下一步」禁用 + 跳 FE-03 待办 | **数据覆盖率 = 必需事实行实有数 ÷ 应有数**（应有数=项目×部门×月×环节笛卡尔积中口径要求的子集），逐项目展开 |
| 3 | 假设 | 口径选择(默认场景默认 caliber 最新 APPROVED 版)、画像版本(默认 PUBLISHED 最新)、人工假设覆盖列表(默认空,新增需 reason 必填 + 走 PRD-04 审批态) | caliber 非 APPROVED→阻止；覆盖无 reason→阻止 | 影响说明："覆盖 3 项假设，影响 2 个项目回款环节"（后端 diff 计算） |
| 4 | 运行确认 | 摘要卡（范围/覆盖率/口径@版本/假设数）+ 幂等提示（同参已有 SUCCEEDED run → 显示"将复用运行 xxx 或强制重跑"） | 覆盖率 < 阈值(默认 80%,可配 `ecos.fc.wizard.min_coverage`)→ 警示但允许勾选"知情运行"（run 标记 `lowCoverage=true`） | 提交 → `POST /api/v1/workspace/forecast-runs`（PRD-09 FC-02），跳运行进度页 |

### 5.2 交互铁律

- 每步「上一步」保留已填状态（组件内 state + sessionStorage，刷新不丢当前向导会话）。
- 无效选择**在当前步阻止**（禁用下一步 + 行内错误），禁止到第 4 步汇总报错。
- 附件 §6.1-2 验收：每步含「默认值 + 数据覆盖率 + 影响说明」三件套，缺一验收不过。

### 5.3 验收标准

1. E2E：默认路径 4 步直通（全程只点「下一步」），断言每步覆盖率文案存在。
2. 阻断用例：步骤 2 注入 BLOCK 缺失 → 下一步禁用；步骤 3 空 reason → 行内错误。
3. 组件文件 ≤800 行，每步独立文件（`wizard/Step1Scope.tsx` 等），主 Layout <300 行。

### 6.2 下钻交互矩阵（每个可点击元素 → 目标视图）
