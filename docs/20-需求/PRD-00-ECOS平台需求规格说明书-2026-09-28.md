## 一、引言

### 1.1 目的

ECOS（Enterprise Cognitive Operating System）是"数据治理 → 知识图谱 → LLM Agent 部署"链路的企业认知操作系统平台。本文档：

1. 定义平台整体与分模块的功能/非功能/数据/接口需求，每条需求带编号（REQ-*）与验收标准；
2. 以首个业务落地场景「企业年度经营预测」为试金石，把场景步骤映射为平台能力需求，暴露"有底座 vs 可生产"的缺口；
3. 给出优先级与路线图（M0–M3 里程碑 + P0/P1/P2 批次），作为后续 PMO 指令的需求来源。

### 1.2 范围

**在范围内**：六引擎（security/data/ontology/kb/cognitive/ai）、runtime 横切底座、四工作台前端（数据/本体/知识/AI）+ 场景工作台（workspace）、gateway BFF、微服务 v2 七个部署单元、三档发布形态。

**不在范围内**：具体代码实现方案、单个 PMO 批次的任务拆解、UI 视觉稿。

### 1.3 术语与认知模型

| 术语 | 定义 |
|---|---|
| DIKCW | D 数据(事实)→I 信息(语义/本体)→K 知识→C 认知(推理)→W 智慧(决策/行动)，外加 W→D 现实反馈链，构成 Enterprise Cognitive Loop |
| 四转化 | ge 格物(D→I，寄居 data-engine-impl/transform)、zhi 致知(I→K，ontology→kb KgSyncService)、cheng 诚(K→C，cognitive-engine)、ming 明(C→W，ai-engine 行动编排) |
| 五行引擎 | 土D=data / 金I=ontology / 水K=kb / 木C=cognitive / 火W=ai；security 为横切"护"，不入五行 |
| 场景 | 场景工作台主实体，**场景≠项目**，禁止引入 `ecos_project`；组成模型 = 子图 + 横切 + 出口（铁律 §0.6） |
| Mind | 认知心智单元，注册于 `kb_mind_registry`，带 capabilityMask（DETECT/FORECAST/SIMULATE/PLAN/REVIEW）与 closedLoopBounds |
| 三档 | standard(PG only) / enterprise(+Neo4j) / ultimate(+Doris)，按部署档位叠加，不新增 Maven 模块与 Docker 容器 |
| 三滤波器 | 新增 Controller 必过：VersionPrefixRewriteFilter 前缀映射 + SecurityConfig permitAll 白名单 + ClearanceInterceptor 豁免 |
| forecastRunId / caliberId / asOfTime | 预测运行三要素：运行标识 / 口径版本标识 / 数据截至时点——所有金额结果必须携带，保证可复现可审计 |

### 1.4 需求优先级定义

- **P0**：阻断主链路或安全红线，未完成不得对外发布场景数字；
- **P1**：影响生产可用性/可解释性/可运维性；
- **P2**：体验、性能、可维护性改进。

## 四、场景落地需求 —— 企业年度经营预测（首个验收场景）

> 来源：附件 ECOS-IMP-COG-06。场景定位：**不是让 LLM 直接回答利润数字的聊天页**，而是经营人员可重复执行的闭环：
> `设定经营口径 → 导入/校验项目经营事实 → 维护预测假设 → 运行预测 → 查看利润瀑布和项目下钻 → 比较情景 → 生成经营动作 → 回灌实际 → 回测复审`
> 首期范围：1 个目标年度、月度期间、3 个项目、2 个部门、"基准/验收延期"两情景。

### 8.3 PMO 指令化约束

- 每条 PMO 指令开头必须引用架构铁律；原子任务 = 单文件 + curl 验收；单指令 ≤5 Task；
- 批次 A 内 REQ 存在依赖序：事实模型（DATA-01）→ DQ 门禁（DATA-02）→ 口径（FC-01/ONTO-02）→ 画像假设（KB-02/03）→ 预测运行（FC-02）→ 前端（FE-01/02）；
- 安全类 REQ（SEC-01/02、AI-01）为强制卡：涉敏 Task grep 命中 0 直接判 FAIL。

## 九、验收准则与门禁（平台级）

### 9.1 第一轮验收演练（附件 §8，M2 后执行）

固定演练包：2027 年 × 3 项目 × 2 部门 × 12 月。

1. 财务发布一版管理口径；数据管理员导入完整基准数据并修复三项故意制造的 DQ 错误；
2. 经营负责人创建基准预测运行，企业/部门/项目三级利润与已签核手工表一致；
3. 从企业利润下钻至某项目 8 月验收额，核对合同基数/归属比例/实现率/画像假设/证据/公式；
4. 复制"验收延期"情景仅降低该项目 7–9 月验收率，变化只出现在目标范围，因果解释带证据标识；
5. 从风险项创建"重点项目验收治理"动作，完成负责人/期限/审批；回灌 8 月实际，查看当时预测/实际/误差/待复审假设；
6. 受控 AI 提问"预测 2027 年利润并说明最大风险"，回答引用运行 ID/口径/截至时间/置信度/可点击证据。
