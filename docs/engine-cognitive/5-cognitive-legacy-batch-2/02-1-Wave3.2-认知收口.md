## 二、固定的硬边界（与 Wave-1B 设计同步）

1. **不新增 DB 表** — 所有推理结果纯内存（CausalChainResult.reasoningPath 生命周期 = 请求）
2. **不引入规则引擎** — SpEL 走 SpelConditionEvaluator（既有），未碰
3. **LLM 调用** — NewsFeedReader 不直调 LLM，预留 LLM 解留 05 文档 §四 由 kb-engine 走 MinerU/MCP
4. **跨引擎只调 API** — EntityLinker 走 REST（kb-engine 18086）
5. **不破坏既有端点契约** — DiagnosisController 仅在响应中加 `reasoningPath` 字段（G2），curl 契约不变
6. **三滤波器** — Wave3DemoController 前缀 `/api/v1/cognitive/demo/wave3`，需 PMO 推到 gateway 三滤波器（见 §五「演示场景」）
