## 二、ARCH 方案：目标架构

### 推荐方案：5引擎 → 4引擎（K层合并）

```
┌──────────────────────────────────────────────────────┐
│                   Gateway (:8080)                     │
├───────────┬───────────┬───────────┬──────────────────┤
│ data-engine│ontology-  │knowledge- │ ai-engine        │
│           │engine     │engine     │                  │
│ 数据源/管道 │ 本体/版本  │ KG+RAG+   │ Agent/Loop/      │
│ 目录/血缘  │ 实体/工作流 │ 推理/规则  │ Tool/Session/    │
│ 质量/调度  │ 领域/提案  │ 抽取/因果  │ Delegation/      │
│           │           │           │ AIP/Guardrails   │
│ D 数据     │ I 信息     │ K 知识     │ W 智能           │
│ :18082    │ :18083    │ :18086    │ :18084           │
└───────────┴───────────┴───────────┴──────────────────┘
```

**核心变化**：cognitive-engine 并入 kb-engine → **knowledge-engine**

### 合并理由

| 维度 | cognitive-engine(30文件) | kb-engine(50文件) | 合并后 |
|------|:--:|:--:|:--:|
| 职责 | 混合检索/KG推理/因果链/场景模拟 | KG/RAG/规则/SubGraph/抽取 | K层全栈 |
| Controller | 4个 | 12个 | 16个(去重后~14) |
| 依赖 | 依赖kb-engine-api | 无外部依赖 | 无外部依赖 |
| DIKW层 | K | K | K |

cognitive-engine 本就依赖 kb-engine-api，合并是自然收敛。

### ai-engine 拆分瘦身

ai-engine 98文件拆为两层：

| 保留在ai-engine | 迁出到knowledge-engine |
|------|------|
| AgentLoop/ToolExecutor/AgentSession/AgentDelegation | KnowledgeExtractor(知识抽取) |
| AIP系列(Agent/Guardrail/Model/Pipeline) | EcosKnowledgeGraphController(重复) |
| AgentMesh/AgentStudio/AgentProfile | GraphSyncController(重复) |
| Copilot/PromptCompiler/Skill | KnowledgeApiController(重复) |
| CronJob/DiagnosticAgent | KnowledgeGraphController(重复) |
| NLQ/Evolution/Classification | KnowledgeSettingsController(重复) |
| Oag/Glossary(术语→迁ontology?) | — |

**预期**：ai-engine 98→~60文件，knowledge-engine 50+30-5重复+15迁入=~90文件

## 三、PM 方案：产品视角

### 用户场景被拖累的典型case

| 场景 | 当前痛点 | 融合后 |
|------|------|------|
| 知识问答 | 前端调`/api/v1/kb/rag`(KB) + `/api/v1/knowledge/reason`(Cognitive) 两次请求 | 单端点`/api/v1/knowledge/qa` |
| 本体→KG同步 | ontology→kb graph/sync，跨引擎REST | 引擎内直接调用 |
| Agent推理 | ai-engine→cognitive→kb 三跳 | ai-engine→knowledge 两跳 |
| 知识图谱管理 | `/api/v1/ecos/knowledge-graph` 三个Controller竞争 | 单一Controller |

### 融合优先级

| 优先级 | 融合动作 | 收益 | 工期估算 |
|:--:|------|------|:--:|
| 🔴 P0 | cognitive并入kb → knowledge-engine | 消除K层分裂，5个重复Controller去重 | 3天 |
| 🔴 P0 | API路径统一：`/api/v1/knowledge/*` 全归knowledge-engine | 消除三方重叠 | 1天 |
| 🟡 P1 | ai-engine知识抽取类迁出到knowledge-engine | ai瘦身，职责清晰 | 2天 |
| 🟡 P1 | ai-engine Glossary迁出到ontology-engine | 术语属于本体范畴 | 1天 |
| 🟢 P2 | PipelineEvent升级为Spring ApplicationEvent | 跨引擎通信规范化 | 2天 |

### 前端影响

| 工作台 | 当前 | 融合后 | 改动量 |
|------|------|------|:--:|
| datanet(D) | data-engine | 不变 | 0 |
| buszhi(I) | ontology-engine | 不变 | 0 |
| dccheng(K) | cognitive+kb两后端 | knowledge-engine单一后端 | API路径合并 |
| aimod(W) | ai-engine | API路径微调 | 小 |

## 五、风险与回退

| 风险 | 概率 | 影响 | 缓解措施 |
|------|:--:|:--:|------|
| 源码迁移引入编译错误 | 中 | 中 | 每步git commit，可checkout回退 |
| API路径合并破坏前端 | 中 | 高 | 前端同步更新，curl验证每个端点 |
| Bean名称冲突(Controller同名) | 高 | 高 | 迁移时重命名，excludeFilters同步 |
| cognitive-engine boot端口废弃 | 低 | 低 | 生产环境仅用Gateway，boot端口仅开发用 |
| ArchUnit依赖方向违规 | 低 | 中 | 迁移后运行ArchitectureTest |

**回退策略**：每个Phase独立Git commit，任一Phase失败可 `git revert` 回退到上一Phase，不影响已交付的Sprint。
