## 二、目标架构：DIKCW 五引擎

```
┌────────────────────────────────────────────────────────────────┐
│                      Gateway (:8080)                            │
├──────────┬──────────┬──────────┬──────────┬───────────────────┤
│   D 数据  │   I 信息  │   K 知识  │   C 认知  │     W 智能        │
│data-engine│ontology- │ kb-engine│cognitive-│   ai-engine       │
│          │engine    │          │engine    │                   │
│数据源/管道 │本体/版本  │KG/RAG/   │混合推理/  │Agent/Loop/        │
│目录/血缘  │实体/工作流 │规则/抽取  │因果链/   │Tool/Session/      │
│质量/调度  │领域/提案  │知识库全   │影响分析/ │Delegation/        │
│          │术语表★   │生命周期  │场景模拟/ │AIP/Guardrails/    │
│          │          │          │预测      │Mesh/Studio/       │
│          │          │          │          │Copilot/Prompt     │
│ :18082   │ :18083   │ :18086   │ :18089   │ :18084            │
└──────────┴──────────┴──────────┴──────────┴───────────────────┘

★ = 本次迁入    没有引擎被删除，五引擎各司其职
```

### DIKCW 层级定义

| 层 | 名称 | 引擎 | 职责定义 | 前端工作台 |
|:--:|------|------|------|------|
| D | Data 数据 | data-engine | 数据源管理、管道采集、目录、血缘、质量 | datanet |
| I | Information 信息 | ontology-engine | 本体建模、实体/关系定义、版本、工作流、领域、**术语表** | buszhi |
| K | Knowledge 知识 | kb-engine | 知识库全生命周期：KG(Neo4j)、RAG、规则、**知识抽取**、SubGraph | dccheng |
| C | Cognitive 认知 | cognitive-engine | 知识理解、混合推理、因果链分析、影响分析、场景模拟、预测 | dccheng(共享) |
| W | Wisdom 智能 | ai-engine | Agent运行时、工具调用、会话、委托、AIP护栏、Mesh、Copilot | aimod |

## 三、具体变更清单

### 变更1：ai-engine → kb-engine 迁出（知识抽取）

| 迁出文件 | 类型 | 目标 |
|------|:--:|------|
| KnowledgeExtractorService | Service | kb-engine-impl |
| ExtractionController | Controller | kb-engine-impl |
| 知识抽取相关Model/DTO | Model | kb-engine-api |

**API路径变更**：
- `/api/v1/knowledge/extract` (原ai-engine) → `/api/v1/knowledge/extract` (kb-engine，路径不变，归属变更)

### 变更2：ai-engine → ontology-engine 迁出（术语表）

| 迁出文件 | 类型 | 目标 |
|------|:--:|------|
| GlossaryController | Controller | ontology-engine-impl |
| Glossary相关Service | Service | ontology-engine-impl |

**API路径变更**：
- `/api/v1/glossary` (原ai-engine) → `/api/v1/ontology/glossary` (ontology-engine)

### 变更3：ai-engine 删除5个重复Controller

| 删除文件(AI引擎副本) | 保留位置(KB引擎) | API路径 |
|------|------|------|
| EcosKnowledgeGraphController | kb-engine | `/api/v1/ecos/knowledge-graph` |
| GraphSyncController | kb-engine | 图同步 |
| KnowledgeApiController | kb-engine | `/api/v1/knowledge` |
| KnowledgeGraphController | kb-engine | KG查询 |
| KnowledgeSettingsController | kb-engine | `/api/v1/knowledge/settings` |

**原则**：AI层不应有KB层的Controller，知识库管理全归kb-engine。

### 变更4：API路径统一归kb-engine

| 当前路径 | 当前归属 | 统一后 | 归属 |
|------|:--:|------|:--:|
| `/api/v1/knowledge` | KB+AI+Cognitive三引擎 | `/api/v1/knowledge/*` | kb-engine |
| `/api/v1/ecos/knowledge-graph` | KB+AI两引擎 | `/api/v1/knowledge/graph` | kb-engine |
| `/api/v1/knowledge/settings` | KB+AI两引擎 | `/api/v1/knowledge/settings` | kb-engine |
| `/api/v1/kb/rag` | kb-engine | `/api/v1/knowledge/rag` | kb-engine |
| `/api/v1/kb/rules` | kb-engine | `/api/v1/knowledge/rules` | kb-engine |
| `/api/v1/kb/articles` | kb-engine | `/api/v1/knowledge/articles` | kb-engine |
| `/api/v1/kb/extraction` | kb-engine | `/api/v1/knowledge/extract` | kb-engine |

**cognitive-engine 路径保持独立**：
- `/api/v1/cognitive/reason` — 混合推理
- `/api/v1/cognitive/scenario` — 场景模拟
- `/api/v1/cognitive/impact` — 影响分析
- `/api/v1/world-model` — 世界模型

### 变更5：GatewayApplication excludeFilters 更新

- 删除5个AI引擎Controller副本的excludeFilters条目（因为文件已删除）
- 新增Glossary旧路径的excludeFilters（如果ontology-engine用新路径）
- 前端API路径同步更新

## 五、分阶段实施路径

### Phase 1：清理重复 + 路径统一（3天）

```
Day 1: ai-engine 删除5个重复Controller
       - EcosKnowledgeGraphController (AI副本)
       - GraphSyncController (AI副本)
       - KnowledgeApiController (AI副本)
       - KnowledgeGraphController (AI副本)
       - KnowledgeSettingsController (AI副本)
       - GatewayApplication excludeFilters清理
       - 编译验证 + curl验证

Day 2: API路径统一 /api/v1/knowledge/* → 全归kb-engine
       - kb-engine内部路径重命名: /api/v1/kb/* → /api/v1/knowledge/*
       - 前端 dccheng 工作台 API路径更新
       - curl全端点验证

Day 3: 全链路验证 + Git commit
```

### Phase 2：知识抽取迁入kb-engine（2天）

```
Day 1: KnowledgeExtractorService + ExtractionController 源码迁移
       - 从 ai-engine-impl 迁入 kb-engine-impl
       - 包名变更 + import修正
       - 编译验证

Day 2: 前端验证 + curl验证 + Git commit
```

### Phase 3：Glossary迁入ontology-engine（1天）

```
Day 1: GlossaryController + Service 迁入 ontology-engine-impl
       - API路径: /api/v1/glossary → /api/v1/ontology/glossary
       - 前端路径更新
       - 编译 + curl + Git commit
```

### Phase 4：ai-engine内部重构（2天，可选）

```
- 80文件内部包结构调整
- 去除知识/图谱相关残留代码
- 编译验证
```

**总工期**：8天（Phase 1-3 必做），+2天（Phase 4 可选）
