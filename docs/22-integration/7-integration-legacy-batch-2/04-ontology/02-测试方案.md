# Phase 4 ontology 测试方案

> 来源: 肖国荣 | 日期: 2026-08-25 | 对应需求: 01-需求文档.md
> 范围: 验证 PMO-28~31 交付（P0 六项 + P1 四项），修 L1 提案表缺失

## 一、测试策略

**核心原则**：PMO-28~31 于 8-08 提交，距今 17 天未经端到端验证。本轮测试不是"回归已有功能"，是"首次验收这四批交付是否真的可用"。

三条主线（对应需求 §三 F1/F2/F3）：

| 主线 | 后端验证 | 前端验证 | 落库验证 |
|------|---------|---------|---------|
| 提案链路 | curl POST/approve/publish | 提案面板 | ecos_ontology_proposals + ecos_ontology_version |
| Function 链路 | curl compile/execute/test | Function 详情测试 | ecos_function_audit_log |
| 自动发现链路 | curl auto-discover | 自动发现面板 | ecos_ontology_entity + property + entity_table_mapping |

**测试执行原则**（总规划 §四）：前端 dogfood 走完整用户流，后端 curl 覆盖 dogfood 没点到的端点，前后端 + DB 三者交叉验证，不一致 = bug。

## 四、测试方法

| 层 | 方法 |
|----|------|
| 后端 | curl + JWT，每端点验证 200 + 响应结构 + DB 落库 |
| 前端 | browser_exec dogfood，每交互查控制台错误 |
| 联调 | 前端操作 → 后端响应 → DB 实际，三者一致 |

## 五、风险与对策

| 风险 | 对策 |
|------|------|
| 提案表缺失（L1）导致 F1 全线 500 | T0 先修表，@PostConstruct 兜底 |
| Function 沙箱对真实表执行可能报错 | 用 SELECT 1 等安全表达式先验证编译，再上真实表 |
| 自动发现依赖 td_data_field 有数据 | 若无元数据，先手动造一批测试字段 |
| Neo4jGraphService（enterprise）在 standard 版不可用 | 记缺口，不阻塞（standard 用 PgGraphService） |

## 六、测试通过标准

1. F1/F2/F3 三条主线端到端全 PASS（curl + 落库证据）
2. L1 提案表修复，重启后提案仍在
3. 前端 9 步 dogfood 全 PASS，控制台 0 错误
4. 架构合规 grep 全 0（ConcurrentHashMap / 硬编码颜色 / 硬编码中文）
5. 后端 mvn install 全绿 + ArchUnit 全绿
