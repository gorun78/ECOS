## §背景

PMO-28~31（8-08 提交）已交付 ontology 核心代码（提案持久化、Function 沙箱引擎、自动发现 UI、DomainDesignerView 拆分），但有一个致命遗留 17 天未收尾：

**ecos_ontology_proposals 表缺失** —— V4.1__ontology_proposals.sql 建表 SQL 写了，但 Flyway disabled（spring.flyway.enabled: false），SQL 从未执行。OntologyProposalController 的 insertProposal 一调就 500 报 "relation ecos_ontology_proposals does not exist"。

本轮：先修表（T0），再端到端验收 PMO-28~31 的三条核心链路（提案/Function/自动发现）。

## §Task

### T0 — 修复 ecos_ontology_proposals 表缺失（P0 前置）

**根因**：Flyway 禁用，V4.1 建表 SQL 没执行。

**操作**：
1. 参照 data-engine `PipelineRepository.ensureDependsOnColumn()` 的 `@PostConstruct` 模式，在 `OntologyProposalService` 加 `@PostConstruct ensureProposalsTable()`，执行 `CREATE TABLE IF NOT EXISTS ecos_ontology_proposals`（完整复制 V4.1 SQL 的表结构：id BIGSERIAL PK / domain_code / proposal_type / target_entity / payload JSONB / snapshot JSONB / status / author / reviewer / reviewer_comment / version_id / created_at / updated_at + 2 个索引）
2. 同样检查 `ecos_entity_table_mapping` 表是否存在，不存在同样 @PostConstruct 兜底
3. 更新架构规则文档，加入铁律："新增表必须 @PostConstruct CREATE TABLE IF NOT EXISTS 兜底，Flyway 已禁用不能只写迁移文件"

**验收**：
- 启动 Gateway → `SELECT to_regclass('ecos_ontology_proposals')` 返回非空
- `SELECT count(*) FROM ecos_ontology_proposals` 返回 0（表存在且空）
- 不依赖手动执行 SQL

### T1 — 提案端到端验证（杀手锏）

**操作**：
1. 启动 Gateway，登录拿 token
2. `POST /api/v1/ontology/proposals` 创建提案（type=CREATE_ENTITY）
3. 查 `ecos_ontology_proposals` 表 → 提案落库（非内存）
4. `POST /api/v1/ontology/proposals/{id}/approve` → status=APPROVED
5. `POST /api/v1/ontology/proposals/{id}/publish`（或 approve-and-publish）→ 版本自动创建
6. 查 `ecos_ontology_version` 表 → 版本 +1
7. 重启 Gateway（模拟进程重启）→ 提案仍在（非内存丢失）
8. 清理测试数据

**验收**：
- 提案落库 ecos_ontology_proposals（重启不丢）
- approve → APPROVED → publish → 版本自动创建
- 全链路无 500

### T2 — Function 沙箱端到端验证

**操作**：
1. 确认 td_datasource 有可查的数据源 + 一张有数据的表
2. `POST /api/v1/ontology/functions/test`（或 compile/test 端点）传表达式，如 `SUM(amount) FROM fin_revenue WHERE period='2026-07'`
3. 查返回：单值 + 类型推断（LONG/DOUBLE/NUMERIC）
4. 查 `ecos_function_audit_log` 表 → 审计记录落库
5. 测白名单：传非法表达式（如 `DROP TABLE x` 或 `Runtime.exec`）→ 应拒绝
6. 测超时：传一个慢查询 → 5s 超时

**验收**：
- 合法表达式 → 返回单值 + 类型正确
- 审计记录落库 ecos_function_audit_log
- 非法表达式被 FunctionValidator 白名单拒绝（不执行）
- 超时控制生效（5s）

### T3 — 自动发现端到端验证

**操作**：
1. 确认有数据源 + 表（td_data_resource/td_data_field 有数据）
2. `POST /api/v1/ecos/domains/{domainCode}/auto-discover` 传 datasourceId + resourceNames
3. 查 `ecos_ontology_entity` + `ecos_ontology_property` → 实体+属性落库
4. 查 `ecos_entity_table_mapping` → 映射落库
5. 前端：本体工作台 → 自动发现面板 → 选数据源 → 预览候选 → 确认生成

**验收**：
- 自动发现生成实体+属性+映射，三表落库
- 前端预览→确认闭环可用
