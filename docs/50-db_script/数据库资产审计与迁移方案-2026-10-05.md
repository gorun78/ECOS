## 〇、一句话结论

现网 `sys_man` 单库实测 **12 个业务 schema · 682 个对象（675 表 + 7 视图，见 §二）**；仓内散置 **~248 个 .sql 资产**，其中 **DDL 有 3 套竞争性 "单源" 目录**（gateway 197 + sysman-boot 19 + ai/ontology-boot 2），外加多库（mysql/oracle）与脚本/种子。选项 B（全部 SQL 物理归集到 `docs/50-db_script/`）技术上可行但**破坏 架构铁律 §3.1 单源约定**，牵连 **~25 个离线 DDL 走查测试 + 2 条铁律文档 + `db-migration-lint.ps1`** 的路径重写；须用户逐项背书后分步执行。**本报告即为确认凭据，未获签前不移动任何文件。**

## 一、范围与方法

- **数据库侧**：`docker exec ecos-postgres psql -d sys_man` 直查 `pg_class`，取 schema 级表/视图/物化视图计数 + 全对象清单（682 行，已存 `.tmp-dbaudit/pg_objects.txt`）。
- **脚本侧**：全仓 `find -name "*.sql"`（排除 `target/`+`node_modules/`）= **248 个**；对 gateway 迁移目录 197 个 V 脚本抽取 `CREATE TABLE/VIEW` 目标名（278 表目标 + 13 视图目标），与现网做**双向交叉**。
- **交叉口径**：按"裸表名"去重比对（避免 `schema.table` 限定差异造成假阳性）。`CREATE` 解析为正则近似（`IF NOT EXISTS` 容错），极端边界（动态 SQL / 模板）可能漏计，已在 §四 标注置信度。

## 四、PG 现网 × 仓内脚本 双向交叉验证（本题重点）

抽取 gateway 197 个 V 脚本的 `CREATE TABLE/VIEW` 目标（278 表 + 13 视图），与现网 682 对象按裸名比对：

### 4.1 脚本声明、现网缺失（**93 个表目标 + 6 个视图目标**）
按业务聚类（依据表名关键词，置信度高）：

| 聚类 | 数量 | 判定 |
|:--|---:|:--|
| **wagent\_\***（`ecos_ai.ecos_wagent_candidate/goal/mission/question/readiness*/run*/skill/tool_contract/evidence*/claim*`） | 16 | **分册10 Agent 编排域 DDL，已写进 V227~V240 脚本但尚未在本 dev PG 实跑**（对齐 memory：分册10 交付"离线交付·不实跑库"） |
| **kb_/knowledge**（`ecos_knowledge.ecos_kb_document/term/profile/graph_*/extract_*/access_request/…`） | 20 | 分册04 知识域 DDL，脚本已立、dev 库未灌 |
| `outbox_event`（`ecos_{agent,audit,catalog,identity,mission,object,rule,workflow}.outbox_event`） | 11 | 横切事件 outbox，脚本声明但各 schema 未建（可能按需用） |

> **解读**：93 个"缺"绝大多数 **不是缺陷**，而是 **dev 库落后于脚本**（分册09/10 交付按项目纪律"离线交付·不实跑实库"，实跑属 §14.4 授权闸）。真正需要人工复核的少数项已单列：`ecos_interface_ref`（无 schema 限定，疑似裸名 bug）、`public.ecos_ontology_domain/_workbench_object`（public vs ontology 归属）。

### 4.2 现网存在、脚本无对应 CREATE（**441 个孤儿对象**）
按聚类（高置信）：

| 聚类 | 数量 | 判定 |
|:--|---:|:--|
| `ecos_demo.act_*`（Flowable 工作流引擎表） | 39 | 引擎自带，非项目脚本资产——`12_to_8_schema.sql` 归入 demo |
| `ecos_demo.*`（演示 / seed / `dw_*`/`common_*`/`demo_*`） | ~168 | 演示仓 + `ecos_demo_indexes.sql`/`rollback_ecos_demo.sql` 维护，**不在 gateway 单源内**（符合预期，demo 独立） |
| `ecos_ai.agent_cost_2025/2026_*` 月度分区 | 25 | 运行时按月建分区，非 static DDL 资产 |
| **其它 405 个 rest**（分布在各 schema 的 `ecos_*` 平台表） | ~209 | 见下方关键判定 |

> **关键判定（须人工复核）**：405 个孤儿里，很多是 `public`/`ecos_*` 下的 **213 张主控制平台表**——它们**是当前系统真正在跑的承载表**，但 `CREATE TABLE` 不在 gateway 的 `V*` 单源里（早期 `12_to_8` 大改 + `01~08` 全量快照 + 多轮 legacy 直接建表），**说明现有 DDL 单源并不覆盖现网真实 schema**。**这是本次审计最实质的发现：`gateway/db/migration` 并非现网 schema 的完整真源，`ecos-sql/postgresql/01~08` 全量快照 + `12_to_8` 大改才是更贴近现网的来源。** 若做的是"以 gateway 单源为准"的归集，会**漏掉约 400+ 现网对象**的 DDL 依据。
