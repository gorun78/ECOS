## 二、架构总览

### 2.1 逻辑分层（L1 上下文 → L2 容器）

```
┌─ 外部：浏览器 / 第三方客户端 / 外部业务系统（SOURCE）
│
├─ 接入层
│    ecos_frontend BFF (Express :3000) ── 默认全量 → gateway :8080（ADR-10）

│
├─ 场景编排层（W 侧收口，只编排不生产）
```

### 3.2 技术选型与理由（含替代方案）

| 领域 | 选择 | 理由 | 考虑过的替代及拒绝理由 |

| 控制域存储 | PostgreSQL 16，单库 5+1 schema | 与 665 表实测盘点一致，零存量迁移（ADR-3） | 每 service 独立 database：需存量迁移且与 ST07 冲突，降级为可选形态 |

## 七、接口架构

1. **基址与版本**：外部 `http://<host>/api/v1/...`；`VersionPrefixRewriteFilter` 把 `/api/v1/*` 重写为 `/api/*`，双路径各自过过滤器（三滤波器之一）。
2. **只增不改**（REQ-NF-06）：既有路径与参数签名不可变；旧端点保留只读兼容 ≥2 迭代。
3. **统一响应**：`ApiResponse{code,errorCode,message,data,timestamp}` —— **现状实测无 `traceId` 字段**（`runtime/common-api/.../ApiResponse.java:48-52`）；分册 00 D.5.1 以「只加字段 + 加 `withTraceId()` 工厂、不改既有静态方法签名」的增量方式引入 `traceId`（REQ-NF-04 前置）。分页 `{items,total,page,size}`；错误码语义按模块固定表（01 册总表 + 各册扩展）。
4. **场景语义不得下沉**（Q4）：引擎侧参数只准通用 `subjectType` + `subjectId`；`scope=scenario:{id}` 形态禁止（PRD-08 FE-03 需改）。
5. **契约文档**：各分册 D 章出 OpenAPI 片段（operationId 唯一，命名 `{动词}{资源}` 小驼峰）；E1~E4 与预测 API 族（REQ-API-06）纳入 ScenarioOpenApi 归档（REQ-API-05）。
