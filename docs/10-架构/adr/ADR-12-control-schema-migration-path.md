# ADR-12 — 主控制 Schema 迁移路径：`public` → `ecos_control`

> 来源: 《数据库访问规范》v1.2 工程清单 #9 + 需求检视报告 §四/§十 | 日期: 2026-09-28 | 责任人: AI Agent
> 版本: v1.0 | 裁决: **Accepted（方案层）；执行需另行用户批准**
> 上游: 铁律 v2.0 §3.1（5+1）+ 《数据库访问规范》v1.2 ST07/MC06 + ADR-3
> 状态: 生效（约束设计；不触存量）

---

## 1. 背景

`public` 现有 199 表，其中 57 张确属主控制数据（安全/审计 16、租户与域 8、场景工作台 22、流程底座 7、调度告警 4），78 张应归五引擎控制域，49 张 knownLegacy 无前缀历史表，3 张业务域混入，9 张演示/工具，3 张待裁决（中文表名，违 DR01）。主控制数据与 PG 默认 schema 混在一起，使"控制域/业务域"边界无法用授权与备份策略表达。

## 2. 决策

1. **目标态**：主控制 schema = `ecos_control`；`public` 保留为 PG 默认 schema，**不再新建业务/控制表**（ST07 白名单收紧为 5 引擎 + `ecos_control` + 业务域 `ecos_dw`）。
2. **迁移分三步、每步独立可回退**：
   - **S1 配置化前置（无 DDL 风险）**：所有 schema 名经 `ecos.db.control-schema` 等属性取数（MC06）。**这是唯一硬前置**——现网源码限定名硬编码 3973 处，未收口前任何改名都会全域爆炸。
   - **S2 双写 + 兼容视图**：新建 `ecos_control`，以**同名视图**（`public.<t>` → `ecos_control.<t>`）保证既有 Mapper/REST 零改动；新表直写 `ecos_control`。
   - **S3 读切换**：按域分批把 Mapper 的 `currentSchema` 指向 `ecos_control`，视图保留 ≥2 迭代（REQ-NF-06 只增不改）。
3. **不做什么**：不 RENAME 存量表（DR02 只约束新表）、不 DROP `public` 中任何对象（R9）、不迁移 78 张"应归引擎"的历史表（桶 B 按 ST07 附注只约束新增）。
4. **桶 D（业务域混入控制 schema 的 3 张：`dw_supplier_agg` / `kb_cognitive_pipeline` / `kb_lineage_event`）不随本迁移走**：合规动作是补 `td_data_resource` 的 `layer`/`zone` 登记，而非搬表。
5. **桶 F（中文命名 3 张：员工 / 数据目录 / 经营数据）**：本 ADR 不处理，仍需用户裁决（改名 = 违 R9；不改 = 长期违 DR01），已在盘点文档 §七列出。

## 3. 影响

| 维度 | 影响 |
|:--|:--|
| 顺序依赖 | S1（工程清单 #6，3973 处硬编码）是数周量级改造，本 ADR 明确其为**前置阻塞**，避免有人直接跳 S2 改 schema 名 |
| 隔离能力 | ✅ 迁移后可用 PG role + `GRANT` 做引擎级授权（ADR-3 §3 的隔离强度依赖此项） |
| 风险 | ⚠️ 视图对 `INSERT ... RETURNING`、触发器、`pg_dump` 恢复顺序有行为差异；S2 必须先跑 15 项 lint + 全量冒烟 |
| 决策门 | S2/S3 执行批次需用户明确批准（本报告默认只到方案定稿） |
