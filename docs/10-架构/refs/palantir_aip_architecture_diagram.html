核心洞察

AIP 的本质是 Ontology = 企业业务的可执行数字孪生。数据不搬、逻辑不重写——所有现有系统的数据在 Ontology 层被赋予"业务语义身份"，让 LLM 和 Agent 真正理解"这个数据代表什么业务含义、谁能操作它、怎么操作才是对的"，而不是在碎片化文本里靠 RAG 硬猜。

Ontology 本体核心
ObjectType + LinkType + ActionType 三大核心类型，构成 AIP 的语义基础设施。
ObjectType — 名词
行政许可 / 设备 / 人员
描述业务世界的"有什么"，每个对象自带业务语义注释，属性可枚举、可约束。
permit_type: Enum[
  "食品经营",
  "工程建设"
]
status: Enum[
  "受理","审核中",
  "通过","驳回"
]
LinkType — 关系
申请人 ↔ 审批件
关系本身是一等公民，有属性（role / mandatory / verified）。这是与图数据库的本质区别。
HAS_APPLICANT {
  source: Permit
  target: Person
  role: Enum[
    "主申请人",
    "共同申请人"
  ]
}
ActionType — 动词
approve_permit
平台级行动，含前置条件、后置动作和审计约束。人类和 Agent 共用同一套 ActionType。
preconditions: [
  role == "审批员",
  docs.verified
]
post: [
  status="通过",
  notify(applicant)
]
audit: required

OAG 业务场景落地
将本体增强生成（OAG）应用于两大核心业务领域：ERP 经营数据智能问数 + 政务服务事项咨询与办理，全链路覆盖权限控制与数据安全。
ERP 经营数据智能问数
数据库表 → 本体数据对象 → 权限控制 → 安全合规
数据库表映射 本体数据对象 数据权限 数据安全 审计追踪
OAG 问数流程
① 自然语言输入"本月华东区采购订单总额及各供应商排名"
② 本体对象匹配ObjectType: 采购订单/供应商/物料/组织架构 + LinkType 关联解析
③ 数据权限过滤部门级隔离（华东区）+ 角色级（采购经理/财务）+ 行级安全（供应商敏感标记）
④ 安全脱敏金额阈值控制 / 供应商评级字段脱敏 / 成本字段 ABAC 属性级访问控制
⑤ OAG Prompt 注入Ontology 语义（采购订单.总额、供应商.名称、组织.区域）→ 生成精确本体查询 / SQL
⑥ 结果审计输出自动生成表格+趋势图 + 数据来源追溯 + 操作全量审计日志

安全设计的核心原则

涉密数据永远留在内网。Ontology Proxy 只向外传递"结构化查询结果"（谁、有哪些、状态如何），不传递原始字段（身份证号、合同内容）。Agent 在外网的每次写操作（审批通过/工单派发）都必须经过内网 Permission Engine 校验，无法绕过。
